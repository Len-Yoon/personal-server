# N100 이중화 제어·복원·운영 패키징 준비

## 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-11-06, Asia/Seoul | 개발 환경은 Mac임 |
| 기준 자료 | PR #490 이후 실제 7개 앱·Windows bootstrap·PG 런타임 원본 | 운영 사실은 별도 확인함 |
| 목적 | Windows fencing·PG 승격·전체 복원·승인형 패키징 구현 | 운영 적용 직전 사용자 확인 필요 |
| 승인 범위 | 맥 구현·검증·독립 검토·저장소 반영 | N100 운영 변경은 아직 승인받지 않음 |

## 핵심 요약

기존 Windows 복구 경로와 새 제어기의 상호 배제, 구 primary 확인 후 승격, 새 standby 재가입 전 쓰기 폐쇄, 짧은 권한 갱신 및 전체 백업·복원 경계를 구현함. 운영 앱 이미지는 기존 7개 앱의 Python·CMD·USER를 보존하고 공유 런타임을 추가하는 별도 산출물로 준비함. 기존 운영 Compose·K3s·배포 workflow·scheduler·Secret·PVC·ingress는 수정하지 않음.

실제 Windows/VM 액추에이터의 현장 수용과 운영 데이터 이전은 완료로 처리하지 않음. Mac 격리 PG 시험, Windows 동작의 단위 대역, PowerShell 파서 확인, 실제 이미지 빌드, PR/main CI를 각각 별도 증거로 기록함.

## 상세 내용

| 경계 | 구현 내용 | 비고 |
|---|---|---|
| 단일 제어 | Windows 전역 mutex, 영구 journal·원자 교체·flush, 재시작 후에도 시도 상한3회 유지 | journal 손상·미저장은 차단함 |
| 기존 복구와 배제 | 승인된 `ha-controller-owner.json`이 있으면 기존 bootstrap의 시작·복구·재부팅·설치를 차단함 | marker가 없으면 기존 동작을 유지함. marker 설치 자체가 운영 승인 대상임 |
| Native 사전 조건 | 비공개 plan/approval·소유자/상위 ACL·hardlink/reparse 거절, 동일 Windows boot, legacy 작업 비활성·프로세스 부재, shutdown 이력 조회 성공 | 조회 실패나 불명확 상태를 정상으로 간주하지 않음 |
| 정확한 fencing | WSL 로컬 Docker socket·engine ID, 중복 없는 전체 ID/이미지/label 목록·restart=no 확인 후 기존 자원 정지 재관측 | 배포판 전체 종료·호스트 재부팅·새 권한 생성은 수행하지 않음 |
| 새 standby | 기존 writer ID와 승인된 새 PGDATA standby ID/이미지/generation을 분리함 | 기존 VM을 power-off한 경우 별도 새 VM 자원이 필요함. 기존 writer 재시작 금지 |
| 승격 | 영구 promoting 의도·대상/system ID/timeline 및 positive fence 확인 후 `pg_promote` 호출·재조회 | 최초부터 primary인 예상 밖 후보는 폐쇄 후 거절함 |
| 재가입 | 새 standby를 관측할 때까지 writes/history 폐쇄 유지 | destructive clone/rewind를 임의 실행하지 않음. 승인된 새 PGDATA 절차로 준비해야 함 |
| 보호 재개 | 정확한 동기 상대·내구성·역할 세대·두 nonce·postcommit WAL·양쪽 flush/replay를 신선한 관측으로 확인함 | 관측2초 상한 유지. native 지연 수용은 확인 필요 |
| 권한 유지 | `serve`가 native guard와 제어 잠금을 유지하며 5초 DB-clock lease를 갱신함 | 실패·중단 시 즉시 폐쇄 시도, 불가하면 lease 만료. 자동 장애 판정·승격 정책은 미설정임 |
| 임시 관측 보존 | 역할 잠금 안에서 지난 controller nonce를 정리하고 현재 시도의 두 행만 유지함 | 업무 요청 원장·앱 receipt 보존 정책을 변경하지 않음 |
| 승인 구분 | fence 전용 승인과 `ha-transition` 전체 전환 승인을 구분함 | fence 전용 승인으로 DB 변경·쓰기 재개를 허용하지 않음 |
| 실행 코드 결합 | controller bundle의 외부 manifest PIN·source commit·코드 hash·실행 경로를 첫 DB 작업 전에 검증함 | `python -B -m ha_control.cli`로 bytecode 생성 없이 실행함 |
| 앱 활성화 | `n100-approved`는 root 소유 읽기 전용 grant·release 식별자·노드/PG/TLS/만료를 정확 대조함 | 앱 소유 설정과 승인 발급자의 쓰기 권한을 분리함. 승인 파일은 자동 발급하지 않음 |
| 전체 복원 | 동일 snapshot dump·테이블/시퀀스/제약/인덱스/함수/ACL 및 참조 파일을 AES-GCM 묶음으로 보존함 | 빈 새 PG system에만 복원하고 예전 권한을 같은 transaction에서 폐쇄함 |
| 백업 승인 | root 소유 릴리스 결합 승인에서 `backup-whole`/`restore-whole` 목적·PG 신원·파일 경로·만료를 대조함 | 복원은 원본 암호문 hash와 새 target system ID까지 별도 승인에 결합함 |

### 패키징과 실행 경계

| 산출물 | 생성·검증 경로 | 비고 |
|---|---|---|
| 앱 패키지 | `infra/k8s/ha-package/build.py prepare --commit <정확 SHA> --output <새 경로>` → `build` → `verify` | 커밋 원본만 포함하며 환경·데이터·실제 인증값을 복사하지 않음 |
| 백업·복원 utility | 별도 비root 이미지, PG17 client·고정 암호화/driver 포함 | 일반 앱 이미지에 백업 관리자 권한을 추가하지 않음 |
| 제어 bundle | `python3 infra/k8s/ha_control/prepare.py prepare --commit <정확 SHA> --output <새 경로>` | verify 시 외부에 고정한 manifest SHA256을 요구함 |
| Windows CLI | `python -B -m ha_control.cli initialize / advance / serve --plan <비공개> --approval <비공개>` | actual bundle 위치에서 실행함. 각 명령은 하나씩 선택함 |

구성도·접속 주소·VM ID·container ID·계정·인증 경로를 추측하여 채우지 않음. 생성 계획과 승인 템플릿은 필수값이 미입력인 `ready=false` 상태이며 운영 명령이 아님.

주 담당은 Windows bridge·journal·bootstrap interlock·격리 통합·문서를 담당함. `gpt-6.1-sol` 높은 추론 구현자는 전체 복원·native PG 제어를, 중간 추론 구현자는 정확 커밋 패키지·승인 경계·제어 bundle을 담당함. 구현 미참여 `gpt-6.1-sol` 높은 추론 검토자가 실제 diff·원본·검사 결과·보호 경계를 독립 검토함. 같은 파일 동시 수정은 하지 않으며 파일 handoff 후에만 소유권을 변경함. 실제 작성 세션과 최종 검토 세션을 엄격 증거로 분리함.

## 확인 필요 사항

| 항목 | 현재 상태 | 비고 |
|---|---|---|
| N100 원격 경로 | 기존 SSH 설정·키 존재를 읽었으나 접속 이름 해석 실패함 | 사용자가 N100·원격 연결을 켜기로 함. 실제 대상 정보는 출력하지 않음 |
| Windows native 수용 | 미수행 | ACL/fsutil/mutex/legacy task/shutdown/Hyper-V/WSL 및 2초 보호 관측 성능 필요 |
| 기존 writer 전체 목록 | 확인 필요 | HA label 없는 기존 K3s/Compose SQLite/JSON writer까지 동결해야 함 |
| VM·자원·EA 영향 | 미수용 | VM2~3GiB는 후보일 뿐임. 정상/최대 동시 메모리·CPU·WSL/거래 지연 실측 필요 |
| 백업 자료 총량 | 실측 필요 | 현재 인증 암호화 묶음은 128MiB 상한이며 초과 시 차단함. 합성 결과를 실제 자료 수용으로 확대하지 않음 |
| 파일 제공 경로 | 운영 검증 필요 | 실제 Windows↔Linux 불변 객체 공개·fsync·반대 노드 가시성과 복원 시험 필요 |
| 외부 exactly-once | 미보장 | 이미 진행 중 효과는 별도 대사 필요. 모호한 provider 결과 자동 재전송 금지 |
| AA 및 자동 failover 정책 | 미수용 | 현재 명령은 승인형 수동 전환임. 임계값을 임의로 설정하지 않음 |

## 후속 조치 및 운영 승인 지점

1. 원격 경로가 회복되면 자원·VM·작업·전체 writer·보호 대상 및 기존 자격 증명 참조를 읽기 전용으로 확인함.
2. 정확 커밋·CI·이미지/config/archive digest·제어 manifest PIN·원본 백업/복원 결과와 대상 자원 ID를 결합함.
3. 기존 자료 동결, 이전 writer 중지, native guard 설치, 새 PGDATA/VM 준비, 전체 이전·복원, 앱/DB 역할 전환, 외부 health3회, 중단·복귀 순서를 한 적용 계획으로 확정함.
4. **첫 실제 N100 변경 직전에 사용자 확인을 받음.** 한 승인 범위 안의 단계는 다시 묻지 않으며 범위 밖 자원·새 중대한 위험만 보류함.
5. PG 신규 쓰기 후 SQLite 이미지 단독 rollback은 금지함. native preflight·자원 수용·파일 경계가 불명확하면 운영 활성화를 진행하지 않음.

기술 기준은 [PostgreSQL failover](https://www.postgresql.org/docs/17/warm-standby-failover.html), [새 timeline 재가입](https://www.postgresql.org/docs/17/app-pgrewind.html), [Windows 파일 공유 잠금](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare) 및 실제 소스임. host/power/disk 장애를 같은 N100의 두 실행 환경으로 해결했다고 표현하지 않음.
