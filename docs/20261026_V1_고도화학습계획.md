## 2. 핵심 요약

**전체 시작 순서는 V2 1주차 정상 상태·요청 추적 → V1 1주차 읽기 점검임.** V2를 먼저 직접 다루고 V1의 실제 운영 구조와 비교함. V1의 읽기 점검은 같은 주에 병행할 수 있음. V1 운영 변경이 V2 실습의 선행조건은 아님.

V1은 실제 N100 서비스의 신뢰성을 관측·설명하는 방향으로 고도화함. 이미 구현된 WSL·K3s·Portal·Tunnel 제한 자동복구, HomeOps, 원격 암호화 백업·격리 복원을 다시 만드는 학습은 제외함. 새 기능보다 정상 상태·실패 해석·배포 판단의 근거를 우선함.

관련 기준: [기존 개발·검증 상태](20260921_프로젝트보완_개발계획.md), [운영 참조](operations-reference.md), [자동복구 범위](n100-mt4-setup.md), [SLI·SLO 기준](slo-baseline.md), [V2 계획](https://github.com/Len-Yoon/personal-server-v2/blob/main/docs/20261026_V2_고도화학습계획.md).

## 4. 검증·운영 보호 기준

- SLO 정의가 정해진 범위에서 관측 수집을 초기에 병행할 수 있음. 기준 변경 전후를 섞지 않으며 일일 최솟값을 정확한 중단 시간으로 환산하거나 일별 p95를 평균하지 않음.
- 현재 저장소의 Prometheus 보존 설정은 7일임. 30일 원시 자료가 없는 상태에서 30일 가용성·에러 버짓을 산정했다고 주장하지 않음. 계획 정지·관측 누락을 성공으로 바꾸지 않음.
- N100·WSL·K3s 재시작, PVC·Secret·운영 데이터·배포·보존 기간·수집 일정 변경은 이 문서 저장에 포함되지 않음. 향후 운영 적용은 기존 유효 승인 범위를 대조하고 AGENTS.md에 따른 승인 지점을 적용함.
- 기능 변경 시 관련 테스트와 구현 미참여 독립 검토를 수행함. Git 병합·CI 성공·정책상 배포 제외를 실제 N100 배포 성공으로 표현하지 않음.

## 5. 검토 결과

- 기존 구현·에이전트 자동 검증과 사용자 직접 수행을 구분함. 기존 자동복구·백업을 처음부터 다시 만드는 과제를 추가하지 않음.
- 문서 저장은 실습 완료 또는 향후 기능·운영 변경의 포괄 승인을 뜻하지 않음. 실제 작업은 사용자 요청과 저장소 AGENTS.md의 설계·검증·독립 검토·운영 승인 기준을 적용함.
- 이번 변경은 주 담당 1명이 작성·자기 검수하는 문서 작업임. 실행 코드·CI·배포 설정을 변경하지 않아 하위 에이전트를 사용하지 않음. 독립 검토 완료로 표현하지 않으며 PR·CI 결과는 해당 PR에서 확인함.

## 6. 확인 필요 사항

- 사용자 직접 실습 결과와 최신 실행 상태는 확인 필요함. 과거 테스트·에이전트 실행·문서의 성공 수치를 현재 상태나 사용자 숙련으로 간주하지 않음.
- 회사 경력·연차·클라우드 담당 범위는 확인 필요함. 두 저장소에 구현이 없다는 이유로 전체 경력에서 미경험이라고 단정하지 않음.
- 주 5~7시간·6주 및 선택 2주는 권장 학습 분량임. 달력상 시간이 지났다고 다음 주차로 자동 진급하지 않음.
