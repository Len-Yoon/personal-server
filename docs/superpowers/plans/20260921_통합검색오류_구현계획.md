# 통합 검색 오류 수정 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development 또는 superpowers:executing-plans. 체크박스로 진행 상태를 기록함.

**Goal:** 실제 Portal 통합 검색에서 서비스별 상대 URL 결과가 HTTP 500 없이 올바른 공개·로컬 링크로 표시되도록 수정함.

**Architecture:** `service_base_urls(host)`를 검색의 `news/youtube/books` key 계약에 맞는 새 dict로 반환함. 원본 `PUBLIC_SERVICE_URLS`·`LOCAL_SERVICE_URLS`와 `service_url()`의 환경 이름 key 계약은 보존함. dashboard·정규화 함수를 mock하지 않는 route 통합 테스트로 실제 연결부를 검증함.

**Tech Stack:** Python 3.11, FastAPI, Jinja2, unittest, TestClient. 의존성 추가 없음.

**Spec:** [승인된 점검 F01](../../reviews/20260921_프로젝트_종합점검보고서.md), [상위 개발 계획](../../20260921_프로젝트보완_개발계획.md). 사용자의 순차 실행 요청을 1차 구현 승인으로 사용함.

- 계획·문서 저장은 주 에이전트, 위 코드·테스트는 구현 에이전트만 수정함. 검토 에이전트는 읽기 전용임.

## Review Focus

1. 공개 host에서 세 서비스의 상대 URL이 각각 올바른 공개 도메인으로 연결되는지 확인함.
2. localhost에서 상대 URL이 각각 기존 loopback 포트로 연결되는지 확인함.
3. 뉴스 endpoint 1곳 실패에도 책·영상 정상 결과가 유지되는지 확인함.
4. 정상 빈 결과를 장애로 표시하지 않는지 확인함.
5. 절대 HTTPS 결과와 기존 위험 URL 차단·서비스 진입 링크의 계약이 유지되는지 확인함.

## 입력·표시 경계

| 입력 | 실행 경로 | 기대 결과 | 비고 |
|---|---|---|---|
| 공개 host·상대 URL | dashboard → service_base_urls → search_all → normalize | 200·공개 링크 | 실제 연결부 검증 |
| 로컬 host·상대 URL | 동일 | 200·기존 loopback 링크 | 외부 접속 없음 |
| upstream 예외 1개 | 동일 | 해당 그룹 unavailable, 다른 그룹 유지 | 상세 endpoint·예외 노출 금지 |
| `results: []` | 동일 | 정상·빈 검색 결과 | 장애 표시 금지 |
| 절대 HTTPS·위험 URL | 기존 normalize | HTTPS 보존, javascript/data/protocol-relative 거절 | 기존 테스트 유지 |
