> 승인된 9차 F14. subagent-driven-development로 구현하며 실제 운영 DB·배포는 별도 경계임.

## 목표와 설계

같은 유효 Telegram update ID에 대해 로컬 업무 변경과 응답을 SQLite 단일 트랜잭션으로 확정함. send 실패나 프로세스 재시작 뒤 재수신하면 캐시 응답만 재사용함. 기존 main.py poll·offset·worker loop는 수정하지 않음. Telegram 응답 중복 수신은 가능하며 exactly-once 전달을 보장하지 않음.

신규 보조 테이블 telegram_command_results는 update_id INTEGER PRIMARY KEY, reply_text TEXT NOT NULL, processed_at TEXT NOT NULL(UTC aware ISO8601)을 저장함. 기존업무테이블·데이터변경없음. BEGIN IMMEDIATE로 처리전 중복확인·업무변경·결과기록을 직렬화함. 각 CRUD에 선택적 connection 또는 transaction-scoped store를 사용하며 공유 mutable active_connection은 금지함.

/현대연결 외부 OAuth는 중복 업무이력 대상이 아니므로 이번 캐시대상에서 제외함. 나머지 로컬 명령만 DB트랜잭션 안에서 수행. 네트워크호출을 트랜잭션에 넣지 않음. 허용chat 검사를 먼저 수행하며 자격증명·chat ID는 신규테이블에 저장하지 않음. 실제 poll의 ID는 bool 제외 0이상 int만 허용, 잘못된ID update는 무시함. 직접호출의 update_id=None 기존계약은 유지하되 멱등보장대상아님을 기록함.
