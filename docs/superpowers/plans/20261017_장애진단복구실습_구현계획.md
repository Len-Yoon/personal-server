# 로컬 장애 진단·복구 실습 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 세 가지 실제 로컬 장애를 관측·해제하고 데이터 보존·정리·시간선을 재검증할 CLI와 Runbook을 제공함.

**Architecture:** 부모가 spawn 프로세스·IPC·소유 fixture·출력 파일·deadline을 감독함. 검색 actor는 상태 전환 가능한 loopback HTTP 서버와 실제 검색 함수를, DB actor는 실제 Book 저장 함수와 제한된 연결을 사용함.

**Tech Stack:** 기존 Book Python 환경, httpx, 표준 asyncio·sqlite3·multiprocessing·unittest.

**Spec:** [설계서](../specs/20261017_장애진단복구실습_설계서.md)

## Global Constraints

- 임시 고정 fixture만 사용함. 운영·외부 URL·mount·sudo·임의 DB/PID 입력 제외.
- 전체 180초, IPC 12초, 정리 최대 10초. 반복 1~3회.
- SQLite page cap→SQLITE_FULL이며 OS ENOSPC를 주장하지 않음.
- 제품 소스 변경 없음. 자동 훈련 시간·논리 보존만 주장함.

## Review Focus

- 부모 환경과 기존 DB 경로 오염: 제품 import 전에 whitelist·소유 경로 확인.
- 가짜 성공·다른 오류: 실제 제품 호출·기본 SQLite 코드·snapshot·중복 원장 검증.
- 중단·무응답: deadline·소유 자식 회수·부분 증적·미실행 수 구분.
- 실행 중 디렉터리 삭제: 살아 있는 자식이 있으면 보존·실패.
- 시간 과장: ack 뒤 전이만 기록하며 정리·사람의 RCA/RTO/RPO와 구분.

## Task 1: 실제 SQLite actor

**Files:** `book-memo/tools/incident_sqlite.py`, `tests/test_incident_sqlite_actor.py` (DB 담당 전용).

**Interfaces:** `sqlite_actor(connection, root: str)`와 `lock_actor(connection, root: str)`는 spawn target임. 부모가 만든 신규 root의 `fixture.sqlite3`만 사용함. actor는 ready 뒤 dict 명령 수신, 성공 `{"ok":True,"data":...}`, 실패 `{"ok":False,"reason":고정값}`를 반환함. 지원 op는 `baseline`, `evidence`, `probe`(scenario=`sqlite_busy|sqlite_full`), `constrain`, `release`, `verify`, `stop`임. baseline data는 snapshot hash·page_count·page_size, probe data는 error_code, evidence data는 unchanged, verify data는 data_preserved·exactly_once·integrity_ok임. lock_actor는 `BEGIN IMMEDIATE` 성공 후 ready, `release`에서 rollback하고 정상 종료함. ready는 `{"ready":True}`임. 각 actor는 clean 환경에서 제품 모듈을 import하며 오류 원문을 보내지 않음.

- [ ] 실제 오류·원자성·재전송·소유 경로 테스트 RED 확인.
- [ ] 실제 Book 서비스와 제한 연결 구현 후 GREEN 확인.

## Task 2: 검색 actor와 감독 CLI

**Files:** `book-memo/tools/incident_search.py`, `book-memo/tools/incident_recovery_lab.py`, `tests/test_incident_recovery_lab.py` (주 담당 전용).

**Interfaces:** `search_actor(connection, sockets, nonce)`는 ready 뒤 op=`normal|fault|probe|stop` 수신. probe data는 statuses·valid, 세 고정 결과 검증. 감독기는 `--output`, `--scenario` 반복 선택, `--repeats` 1~3, `--deadline` 0초 초과~180초를 지원함.

## 실행 기록

주 담당은 감독·검색·통합, DB 담당은 helper·actor 테스트만 수정함. 공용 IPC 계약은 이 문서로 고정하고 차이는 주 담당에게 먼저 보고함. Task 2는 Task 1 응답 필드를 소비하며 제품 코드·1단계 실습 도구는 수정하지 않음. 새로 작성한 문서에 대한 반복 승인 대신 기존 단계 승인·일반 개발 연속 진행 기준을 적용함.
