## 2. 핵심 요약

- 현재 84개 `tests/**/test_*.py` 중 62개만 매트릭스 명령 또는 car-care discover 대상이며, F10 누락 22개가 확인됨.
- `tests/test_portal_http_metrics.py`는 기존부터 매트릭스에서 누락된 Portal 회귀이며, 5차 F06에서 수정 중인 파일이므로 6차에 반드시 포함해야 함.
- 9개 기존 프로세스 그룹을 유지하고, 서로 `app`이라는 최상위 패키지를 사용하는 Portal·Crawler·Book·YouTube를 한 Python 프로세스에 섞지 않음.

## 5. 매트릭스 포함성 guard 구현안

### 5.1 위치와 호출 시점

`tests/run_service_tests.py`에 아래 순서로 구현함.

1. 기존 `load_matrix()`가 JSON, 정확히 9개 group, 정확히 6개 field, 이름·Python 버전·문자열·`extra_packages` 형식을 검증함.
2. 새 `matrix_test_files(matrix)` 또는 동등한 private helper가 각 `test_command`를 `shlex.split`으로 다시 parse하여 실제 귀속 파일 집합을 생성함.
3. 새 `discover_test_files()`가 repository의 `tests/**/test_*.py`를 상대 경로 POSIX 형식으로 수집함.
4. 두 집합이 정확히 같은지, 각 파일이 한 group에만 배정됐는지 검증함. 누락·추가·중복은 경로를 정렬해 포함한 `ValueError`로 실패시킴.
5. `main()`은 `--github-matrix`, `--list`, `--dry-run`, 실제 suite 실행 이전에 이 검증을 수행함. 따라서 GitHub `matrix` job이 include JSON을 만들기 전에 실패하여 새 테스트 누락을 통과시킬 수 없음.

`load_matrix()` 자체에는 JSON schema 검사만 남기고, 포함성 guard는 `main()`에 배치하는 안을 권장함. 기존 단위 테스트가 작은 mock matrix로 `main()`의 실패 전파·계속 실행을 검증하므로, 해당 mock에 guard를 적용하려면 fixture 전체가 필요해져 테스트 목적이 흐려짐. 별도 `validate_matrix_coverage()` 직접 단위 테스트로 guard를 검증함.

### 5.2 명령 파서의 허용 문법

guard는 shell을 실행하지 않으며 아래 좁은 문법만 허용함.

| 명령 형태 | 파싱·귀속 방식 | 거절 조건 |
|---|---|---|
| `python3 -m unittest tests.foo tests.bar` | 각 module을 `tests/foo.py`로 변환하고 실제 file 존재 확인 | `tests.` 이외 module, option, `.py` 경로, 존재하지 않는 file, 같은 module 반복 |
| `python3 -m unittest discover -s tests/car_care_worker` | 현재 root의 직접 자식 `tests/car_care_worker/test_*.py`만 귀속으로 계산 | `-s` 누락·반복, 절대/상위 경로, 허용되지 않은 discover option·대상, 빈 결과, 하위 directory 존재 |

현재 matrix의 discover 문법은 정확히 후자 하나이며 대상 directory에는 하위 directory가 없음. Python `unittest discover`는 하위 directory의 package 여부(`__init__.py`)에 따라 재귀 여부가 달라지므로, 단순 `rglob` 결과를 실행 보장으로 간주하지 않음. 이 설계에서는 discover root를 **비재귀**로 고정하고 하위 directory가 생기면 guard가 즉시 실패하게 함. 새 nested test는 전체 `tests/**/test_*.py` 목록에는 나타나지만 현재 discover의 귀속 목록에는 없으므로, 구현자는 해당 test를 명시 module로 배정하거나 package-aware discover 문법·파서를 별도 설계해야 함.

필요한 경우 `-p` 또는 package-aware recursive discover를 지원할 수 있으나, 현재는 지원하지 않아 command 의미가 조용히 확장되는 것을 차단함. `discover` 대상은 `ROOT/tests` 하위인지 `Path.resolve().is_relative_to()`로 확인하고, symlink/상위 경로를 통한 범위 이탈도 거절함.

전체 기대 파일 목록은 `Path.rglob("test_*.py")` 결과에서 directory·file을 각각 `resolve()`하고 `ROOT/tests` 하위만 허용해 구성함. discover 명령의 귀속 파일 계산은 위 비재귀 제한을 적용하여 별도로 수행함. 이 비교 방식은 새 PR의 test 파일 또는 nested test가 matrix에 명시적으로 배정되지 않으면 CI matrix 생성이 실패하도록 함. Python의 import discovery 결과를 실행하여 검사하지 않으므로 guard 자체가 service `app` import, network, fixture 환경의 영향을 받지 않음.

### 5.3 guard 회귀 테스트

`tests/test_run_service_tests.py`에 다음을 추가 또는 기존 matrix 고정 기대값을 갱신함.

| 검증 | 기대 결과 |
|---|---|
| 현행 matrix의 module/discover 귀속 집합과 실제 `tests/**/test_*.py` 집합 일치 | 성공 |
| 임시/patch matrix에서 명시 module 하나 삭제 | 누락 경로가 포함된 `ValueError` |
| 같은 module을 두 group에 배정 | 중복 경로가 포함된 `ValueError` |
| 존재하지 않는 module, `tests` 밖 module, unsupported option | 입력 오류 |
| car-care discover가 현재 root의 직접 자식 `test_*.py`만 포함하고 하위 directory를 거절 | 성공 및 새 nested test 누락 방지 |
| 새 임시 test 파일은 실제 repository에 만들지 않고 `discover_test_files` 결과를 mock하여 matrix 밖 경로로 주입 | 누락 오류. 작업공간 오염 없음 |
| `--github-matrix` | 검증 성공 시 JSON만 출력, 검증 실패 시 non-zero 및 JSON 미출력 |

고정 `EXPECTED_GROUPS`는 9개 group 유지 전제에서 새 명령·두 httpx extras를 정확히 반영함. `test_matrix_defines_the_nine_ci_python_groups`는 의도치 않은 CI contract 변경을 계속 차단함.

## 6. F11 안전 fixture 환경 구현안

### 6.1 runner

`command_for()`의 `environment`를 다음 허용 목록으로 구성함.

```python
environment = {
    "PATH": os.environ.get("PATH", os.defpath),
    "PYTHONPATH": str(ROOT / str(entry["pythonpath"])),
    "USER": "audit_fixture",
}
```

`os.environ.copy()`를 사용하지 않음. 이 값은 `portal-pvc-backup-automation.sh`의 존재 여부 검증을 만족하는 고정 test fixture일 뿐 운영 사용자·자격 증명이 아님. 모든 group에 고정 값을 전달해 local runner와 CI job의 `USER` 존재 계약을 맞추며, `TOKEN`, `PASSWORD`, cloud credential, proxy 설정 등 호출자 환경은 전달하지 않음.

`tests/test_run_service_tests.py`에는 상속 `USER=real-user`, `TOKEN=must-not-be-inherited`를 넣은 subprocess dry-run/직접 `command_for` 검증을 추가함. 결과 env는 `PATH`, 정확한 서비스 `PYTHONPATH`, `USER=audit_fixture`만 가지며 실제·비밀 값이 없음을 검증함. 기존 `PYTHONPATH=must-not-be-inherited` 검증은 유지함.

### 6.2 venv 준비기

`scripts/setup-local-test-venvs.py`는 matrix의 `requirements` 및 `extra_packages`를 설치·검증하는 역할을 이미 수행함. 다음 보완만 적용함.

- 기존 `load_matrix()` schema 범위는 유지함. 이번 요구의 직접 결함은 pinned extra 의존성 검사이므로 schema 검증 확대는 하지 않음.
- command coverage/command grammar와 CI schema 검증은 runner가 담당함. setup에는 제품 동작과 관계없는 추가 schema 변경을 넣지 않음.
- `declared_packages()`는 `httpx==0.28.1`을 extra package pinned dependency로 인식하고 `--check`에서 version 불일치를 실패시킴.

`tests/test_setup_local_test_venvs.py`에는 Book 또는 YouTube 형태의 fixture로 `httpx==0.28.1` 설치 명령과 `--check`의 누락·wrong-version 실패를 추가함. `--go`만 외부 package 설치를 수행하며, 이번 설계 검토·CI guard는 설치를 수행하지 않음.

## 7. CI·하네스 분류 및 운영 경계 검토

| 항목 | 판정 | 근거·조치 |
|---|---|---|
| `.github/workflows/ci.yml` 수정 | 불필요 | matrix job이 runner의 `--github-matrix`를 이미 실행함. workflow를 건드리면 change scope가 deployment workflow가 아닌 경우에도 CI automation 영향 검토 범위를 넓힐 이유가 없음 |
| CI matrix failure 전달 | 충족 | guard `ValueError`는 matrix job non-zero가 되고 test·summary가 success가 될 수 없음 |
| `tests/ci_test_matrix.json`, `tests/run_service_tests.py`, runner tests | `verify_change_scope`상 `tests/` automation path로 maintenance check 필요 | PR CI 전체 9 groups가 통과해야 summary가 success가 됨. 로컬 하네스에는 최소 maintenance 성공을 전달함 |
| `scripts/setup-local-test-venvs.py` | `POLICY_MAINTENANCE_FILES`에 이미 포함됨 | maintenance check 필요. 차단 path가 아니며 script 이외 운영 동작 없음 |
| Book/YouTube requirements 변경 | 권장하지 않음 | test-only httpx는 matrix `extra_packages`로 명시함. production dependency·image·deploy scope를 넓히지 않음 |
| N100 배포 | 제외 | workflow, deploy script, runtime marker, K3s/Caddy/Tunnel/PVC/Secret를 수정하지 않음. CI 성공을 운영 적용으로 표현하지 않음 |

구체 검증 때 변경 경로 파일에는 matrix·runner·setup script·관련 tests·상세 계획만 넣고 `python3 scripts/run_change_harness.py --input <NUL 변경경로파일> --agent-context`를 실행함. 경로상 Book/YouTube production requirements를 변경하지 않는 안이므로 서비스 source 변경 요구는 없음. 다만 JSON matrix가 각 service test command를 변경하므로 실제로는 모든 9 suite를 실행하고, 성공 결과를 `--check-result`로 정확히 전달함. maintenance, portal, crawler-worker, book-memo, youtube-memo, k8s-contracts 결과는 특히 별도 기록 필요함.

| 6 | 독립 CI 전문 검토 | diff, command grammar 우회, matrix schema, import 분리, env leak, workflow/운영 제외 확인 | 차단 항목 없음 또는 보완 완료 |

필수 명령은 다음 순서임. 실제 전용 venv 준비는 package 설치가 필요한 실행 단계에서만 수행함.

```text
python3 -m unittest tests.test_run_service_tests tests.test_setup_local_test_venvs
python3 tests/run_service_tests.py --github-matrix
python3 scripts/setup-local-test-venvs.py --check
python3 tests/run_service_tests.py
git diff --check
```

`setup-local-test-venvs.py --check`가 아직 준비되지 않은 venv 때문에 실패하면 성공으로 표기하지 않음. `--go`로 새로운 venv와 공개 test dependency를 설치하는 것은 로컬 개발 환경 변경이므로 구현 단계의 승인 범위와 네트워크 가능 여부를 확인한 뒤 수행함.

## PR CI에서 확인한 Linux 호환성 보완
