# 통합 검색 성능 실습 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 운영 접속 없이 실제 통합 검색 함수의 정상·부분 실패·부하를 측정하고 재집계 가능한 증적을 생성함.

**Architecture:** 부모가 loopback socket을 확보한 뒤 소유 샘플 서버와 부하 프로세스를 셀마다 생성함. 실제 검색 모듈은 격리된 자식 환경에서 호출하고 부모는 시간 제한·중도 종료·증적 저장·프로세스 회수를 담당함.

**Tech Stack:** 기존 Portal Python 3.11+, httpx, Python 표준 라이브러리 asyncio·multiprocessing·resource·unittest.

**Spec:** [승인 설계](../specs/20261017_통합검색성능실습_설계서.md)

## Global Constraints

- 클라우드·새 VM·운영 서버·자격 증명·운영 앱 코드 변경 제외.
- 동시성 상한 10, 측정 30건, 반복 3회, 실행 600초와 정리 최대 10초.
- normal·delayed·timeout·http_failure, 기본 동시성 1·5·10, 준비 호출 5건.
- 고정 결과·loopback 전용·proxy와 demo 환경 제거·기존 결과 파일 덮어쓰기 금지.
- closed-loop 함수 측정이며 웹 응답·운영 최대 처리량·사용자 SLO로 표현하지 않음.

## Review Focus

- 부모 환경의 외부 SEARCH_URL·DEMO_MODE·proxy 설정이 실제 요청을 바꾸지 않는지 통합 검사함.
- 결과 파일 충돌·중단 시 기존 파일과 비소유 프로세스를 보존하는지 검사함.
- 부분 실행에서 시작·완료·취소·미시작 분모가 보존되는지 검사함.
- timeout과 HTTP 실패가 정상 대상 결과를 가리지 않는지 실제 socket으로 검사함.
- 자식 비정상 종료와 deadline 이후 제한 시간 안에 회수되고 부분 증적이 남는지 검사함.
