# 화면 품질·백업·휴지통·CI 개선 Implementation Plan

> **For agentic workers:** 저장소 AGENTS.md의 역할 분담과 사용자 `전부 진행해봐` 승인을 우선함. 주 담당·분리 구현 담당·독립 전문 검토로 진행하며 같은 파일을 동시에 수정하지 않음. 중복 기획·단계별 개발 승인 요청 없이 구현·검증·PR·병합까지 진행함.

**Goal:** 화면 오류 재발, 수동 차량 백업, 휴지통 누적, 긴 필수 검사 대기시간을 줄임.

**Architecture:** 격리 브라우저 시험을 CI에 연결하고 기존 모든 Python 검사를 유지한 채 느린 검사 묶음만 분할함. 차량 DB 백업은 기존 암호화 도구·등록 자격 증명을 사용해 변경 감지와 기간별 보관·자동 실행 준비를 추가함. Book·YouTube 휴지통은 제한 조회·용량 표시·인증된 선택 정리를 제공함.

**Tech Stack:** Python unittest/SQLite, Playwright Chromium, GitHub Actions, 기존 age/rclone·백업 실행 계약.

**Spec:** 개발 계획의 2026-10-14 품질·자동화 개선 및 사용자가 승인한 네 항목.

## Global Constraints

- 필수 Python 9개 묶음의 모든 검사 파일·검사 케이스를 보존함. 분할 시 누락·중복·실패 전파를 검사함.
- 브라우저 시험은 소유한 loopback 서버·임시 DB/파일만 사용하며 외부 요청을 차단함. 운영 업로드·삭제 시험을 실행하지 않음.
- 기존 이미지·인증·데이터 모델·백업 스케줄·Secret/PVC·운영 데이터를 임의 변경하지 않음.
- 차량 자동 실행 템플릿은 비활성 기본값으로 준비함. 실제 등록/활성화·원격 삭제는 최종 운영 범위를 확인한 뒤 수행함.
- 메모 휴지통 자동 만료·기존 데이터 일괄 삭제는 기본 비활성임. 선택한 항목만 인증·Origin·버전 충돌·재전송 방지를 검증해 정리함.
- 하나의 기능 브랜치/PR로 구현·관련 검증·전체 필수 CI·전문 검토·병합을 마무리함. 운영 적용은 저장소 성공과 구분함.

## Review Focus

- 브라우저 시험에서 숨김 버튼·모바일 넘침·파일 재선택 후 상태 복구가 실제 DOM/배치 검사로 검출되는가.
- CI 분할이 신규 검사 파일을 누락시키거나 실패한 shard를 성공 처리하지 않는가.
- 차량 데이터가 변하지 않아도 실제 복원 증명 없이 오래된 성공을 갱신하지 않는가.
- 백업 보관 정리가 다른 scope·미확인 객체·마지막 복원 가능 사본을 삭제하지 않는가.
- 휴지통 선택 정리가 다른 책/영상의 메모·버전이 바뀐 항목을 삭제하지 않는가.

## Task 1: 화면 자동 회귀 검사 — 주 담당

**Files:** `tests/browser/*`, `.github/workflows/ci.yml`, 필요한 테스트 runner 계약 검사.
**Interfaces:** 격리 runner가 `--service` 또는 별도 명확한 runner로 Portal·Book·YouTube의 성공/실패를 exit code로 보고함. 기존 Portal smoke 진입점 유지.

- [ ] 실제 서비스/템플릿을 격리 DB와 함께 실행하여 로그인·파일 선택·미리보기·숨김/재선택·1280/375px 넘침을 검사함.
- [ ] 검출력이 있는 회귀 케이스를 추가하고 실제 Chromium으로 확인함. 외부 통신·운영 URL 입력은 거부함.
- [ ] CI에 고정 의존성 설치·브라우저 캐시·실패 증거 업로드를 연결하고 브라우저 실패를 summary에 전파함.

## Task 2: 필수 검사 대기시간 개선 — 주 담당

**Files:** `tests/run_service_tests.py`, `tests/ci_test_matrix.json`, `.github/workflows/ci.yml`, `tests/test_run_service_tests.py`, 관련 CI 계약 검사.
**Interfaces:** 기존 9개 suite 의미·범위와 `selected_checks` 유지. Kubernetes suite만 독립 subprocess/shard로 나눠 검사를 정확히 한 번씩 실행하고 전체 결과로 합산함.

- [ ] 기존 Kubernetes 검사 시간 병목을 실행 단위별로 측정함. 실제 오래 걸린 fixture/묶음을 기준으로 분할함.
- [ ] 모든 모듈/케이스의 분할 전후 집합 동일·중복 없음·실패 전파·미분류 파일 실패를 검증함.
- [ ] 동일 환경에서 변경 전후 실행 시간을 기록하고 개선폭을 실제 측정값으로만 보고함.

## Task 3: 차량 DB 백업 자동화·보관 — 백업 구현 담당

**Files:** `car-care-worker/tools/backup.py`, 해당 디렉터리의 분리된 순수 정책/실행 helper, 비활성 자동 실행 템플릿, `tests/car_care_worker/test_backup.py` 등 소유 테스트.
**Interfaces:** 기존 `--check`/`--go`와 암호화·동일 객체 재다운로드 복원 검증 보존. 변경 없음을 별도 상태로 보고하며 이전 복원 시각을 새 성공으로 만들지 않음.

- [ ] 일관된 DB snapshot의 내용 fingerprint로 변경 감지, 동시 실행 잠금·원격 결과 불명확 시 중단·개별 시도 증적을 구현함.
- [ ] 기본 보관안을 일간 7개·주간 4개·월간 3개로 준비하되 계획 모드가 기본이며 원격 삭제는 별도 명시 실행만 허용함.
- [ ] 소유 범위·객체 이름·동일 초 동률·최신 복원 검증 사본·자격 증명 메모리 경계의 회귀 검사를 수행함.
- [ ] 기존 네 백업과 겹치지 않는 단일 차량 실행 템플릿을 비활성 상태로 준비하고 설치/활성화는 수행하지 않음.

## Task 4: 메모 휴지통 관리 — 메모 구현 담당

**Files:** Book·YouTube 각각 `app/services/*service.py`, `app/main.py`, 상세 템플릿·필요한 휴지통 JS/CSS, `tests/book_memo/*`, `tests/youtube_memo/*` 소유 테스트.
**Interfaces:** 기존 복원/수정 이력 API·최근 50회 보존 계약 유지. 휴지통 목록 기본 20개/페이지, 총 개수·저장 내용 바이트(실제 DB 파일 크기와 구분) 표시.

- [ ] 휴지통 제한 조회·페이지 경계·용량 집계·빈 상태를 구현하고 기존 복원 기능을 보존함.
- [ ] 사용자 선택 항목만 최대 20개/요청으로 영구 정리하며 대상 부모·expected version·인증·Origin·request ID를 검증함.
- [ ] 다른 부모 ID·중복/잘못된 ID·버전 충돌·재전송·부분 삭제 방지·원문 노출 방지를 검사함.
- [ ] UI 확인 문구에 영구 삭제임을 명시하고 자동 삭제 기본값은 추가하지 않음.
