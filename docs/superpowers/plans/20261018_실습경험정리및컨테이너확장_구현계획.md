# 실습 경험 정리 및 컨테이너 확장 구현 계획

> **For agentic workers:** Use superpowers:executing-plans for primary work; separately assigned runtime implementer, documentation implementer and independent expert follow their file boundaries.

**Goal:** DB 분석·사례·포트폴리오를 정리하고 실제 다른 Book 버전의 Docker 교체·데이터 호환·롤백을 증명함.
**Architecture:** 고정 Git context→LocalDocker→network-none Book 컨테이너→실제 서비스/HTTP probe→증거·소유 정리.
**Tech Stack:** 기존 Book Python·Git·Docker CLI·SQLite·unittest.
**Spec:** [설계](../specs/20261018_실습경험정리및컨테이너확장_설계서.md)

## Global Constraints

- 클라우드·새 VM·N100·운영·제품 소스 변경 없음.
- v1=d0a60639ccef6d8acdf821528baf88a1bb6af578 앱, v2=HEAD 앱, 두 환경은 현재 Dockerfile/requirements.
- 전체900~1800초·build300초·Docker15초·stop5초·cleanup90초, 반복1~3회.
- mocked CI·실제 Docker·사용자 수동 수행·운영 결과를 구분함.

## Review Focus

- Docker endpoint·owner·외부 자원 → 로컬 Unix·known ID/name·일치 label만 허용.
- 응답 소실·불명확 stop → actual inspect 확인, 다음 version start 금지.
- Git ref·경로·context 변조 → 조상·고정 source·전체 hash 검증.
- v2 data·schema drift → 논리 보존·schema hash·역방향 read/write, 자동 downgrade 금지.
- 개인 경험·자동 시간 → 사용자 직접 수행 증거 없으면 확정하지 않음.
