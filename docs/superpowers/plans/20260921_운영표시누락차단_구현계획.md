# 운영 표시 파일 누락 시 안전 배포 차단 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** 안전 배포에서 운영 표시 파일 부재·서비스 값 누락을 Compose 소유권으로 오인하지 않도록 함.

**Architecture:** reader에 opt-in `--require-explicit` 검증을 추가하고 안전 배포 호출만 사용함. 기존 1인수 reader/loader의 기본 호출 계약을 보존함. 파일 신뢰·fd 검증 안에서 누락을 차단하며 사전 exists 검사로 대체하지 않음.

**Tech Stack:** Python stdlib, Bash, unittest, fake Git/Docker.

**Spec:** AGENTS.md의 운영 표시 파일 누락 차단 보완 승인 및 상위 프로젝트 보완 계획. 사용자 2026-09-21 명시 승인.

## 설계 검토 경계

독립 운영 검토에서 구 revision의 helper/reader는 상태 확인 도구에서만 실행되며, Docker build/up/stop/start 및 소유권 변경은 현재 safe deploy의 runtime refresh를 통과함을 확인함. 이번 strict 계약은 배포·rollback의 변경 동작 진입 차단에 적용함. 상태 확인 도중 표시 파일이 사라지면 구버전 읽기 전용 health가 Compose로 해석할 수 있는 관측상 한계는 잔존함. 구 revision 코드를 변형하거나 health 호출 계약을 확대하지 않음. 표시 파일 검증과 Docker 호출 사이의 운영자 동시 변경을 원자적 소유권 이전으로 보장하지 않음.

## 저장소 반영과 운영 활성화 구분

- 현재 변경 경로의 실제 분류는 `action=blocked`, `reason=blocked_unknown_runtime`, 서비스 목록 없음임. 별도 안전 보완 PR 병합이 실제 deploy 작업을 실행하지 않는지 병합 후 다시 확인함.
- workflow는 해당 SHA의 safe deploy 스크립트만 임시 실행하며 helper/reader는 N100 checkout 것을 사용함. 구 loader는 추가 strict 인자를 거절하므로 Docker 변경 전에 중단됨.
- 저장소 병합으로 N100 helper/reader가 동기화되지는 않음. 승인된 운영 동기화 전에는 이후 자동 배포가 이 경계에서 중단될 수 있으며, 이를 새 fallback으로 우회하지 않음.
- N100 동기화·정책 활성화·실제 배포·외부 health 검증은 이번 작업에서 미수행함.
