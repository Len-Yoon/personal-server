# 뉴스 알림 영속 상태 구현 계획

> 승인된 10차 F15. 기존 단일 프로세스 archive·notification lock 계약 안에서 구현함.

## 목표와 설계

alert와 digest 모두 이벤트 ID·pending/sent 상태·전송 snapshot을 archive telegram_outbox에 영속화함. 수집결과와 alert intent는 같은 archive commit에서 저장하고, digest는 전송 전에 pending 이벤트를 저장함. 성공 ack 저장 뒤에만 sent로 변경함. 실패·재시작 시 pending을 같은 내용으로 재시도함. Telegram 성공 후 ack 저장 실패에는 중복 수신이 가능함을 명시하고 exactly-once를 보장하지 않음.

기존 schema version과 articles/pending/recent/topic 필드는 유지하고 새필드 누락은 []로 읽음. event_id는 kind와 URL집합의 안정적 해시. UTC aware ISO8601 created_at/sent_at. sent는 기존 DEDUPLICATION_WINDOW 보존 후 정리. pending은 전송 전에 지우지 않음. 잘못된 새필드는 정규화하며 기존 기사와 알림 상태를 폐기하지 않음.

기존 _NOTIFICATION_LOCK 아래 발행을 직렬화하고 _ARCHIVE_WRITE_LOCK은 로드·enqueue·ack만 보호함. 외부호출 중 archive lock을 잡지 않음. ack는 최신archive를 다시읽어 대상event만 변경함. 기존 초기baseline은 알림을 보내지 않음. pending digest재시도는 신규digest간격에 가로막히지 않으며 같은URL을 다른pendingdigest로 재선택하지 않음. 프로세스간 동시writer/전원손실 보장은 범위밖임.

## 검증·검토 기록

- 최초 archive의 outbox 필드 부재로 RED를 확인한 뒤 영속 저장을 구현함.
- 독립 검토의 P1 두 건(단일 이벤트만 처리, recent 보관 기간 누락)을 수정함. 시작 시점 대기 이벤트만 각 1회 처리하고 digest는 최대 1회 선택하여 동시 추가 이벤트를 다음 실행에 남김.
- 주 담당이 누락된 digest enqueue/ack 실패와 구 schema 보존 회귀를 추가함. 송신 중 추가된 일반 pending과 alert outbox가 모두 보존됨을 확인함.
- 최종 Crawler 104건, maintenance475건, AST·diff·하네스 통과함. 최종 독립 재검토 통과(P0~P2 없음). PR·전체 CI·병합 절차 진행함.
- 실제 N100 marker 읽기 검사에서 crawler-worker=k3s를 재확인함. 저장소 반영과 별개로 새 K3s 이미지 배포·실제 Telegram 발송은 수행하지 않음.
- 발송 응답 뒤 ack 저장 실패는 중복 수신 가능성이 남음. 현재 단일 프로세스의 archive·notification lock 범위이며 프로세스 간 writer 보장은 확장하지 않음.
