# 운영 개선 로드맵 설계서

## 목적

완료된 과거 계획을 현재 운영 문서에서 제거하고, 안전한 복구 훈련 절차와 실제 모델 토큰 측정 기록 방식을 운영 기준으로 고정함.

## 범위

| 구분 | 구현 내용 | 제외 범위 |
|---|---|---|
| 계획 정리 | 완료된 미추적 계획·설계서 제거, 현재 로드맵 추가 | 과거 구현 재수행 |
| 복구 훈련 | 기존 안전 도구만 호출하는 월간 점검 체크리스트 | scheduler, 자동 실행, 운영 데이터 변경 |
| 토큰 측정 | 비밀값 없이 JSONL 측정 기록을 생성·검증·집계하는 로컬 도구 | 토큰·비용 자동 수집, 원격 전송 |

## 설계 결정

- 공개 외부 감시는 기존 GitHub Actions `Public Portal Uptime Monitor`를 유지함. 새로운 외부 감시 서비스는 추가하지 않음.
- 복구 훈련은 실제 Portal 전환·공개 경로 변경·PVC 쓰기를 수행하지 않으며, `--check` 및 격리된 Pod 자동복구 실습만 사용함.
- 측정 기록은 저장소에 수치 자체를 커밋하지 않음. 로컬 JSONL 파일을 입력으로 받아 동일 조건의 기록만 생성·집계함.
- 비밀번호, 토큰, chat ID, Secret 값, 운영 데이터 경로는 문서·측정 기록·출력에 포함하지 않음.

## 성공 기준

1. 완료된 과거 계획·설계서가 저장소 작업공간에 남지 않고, 현재 로드맵이 운영 문서 색인에서 접근 가능함.
2. 복구 훈련 문서가 안전 명령·성공 기준·중단 시 복구 조치를 명시함.
3. 토큰 측정 도구가 표준 입력의 JSON 한 줄을 안전한 JSONL 기록으로 추가하고 기존 집계 도구가 결과를 읽음.
4. 문서·토큰 도구 관련 테스트와 정적 검사가 통과함.
