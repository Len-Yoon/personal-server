# DevOps 실습 증거 고도화 설계

## 목적·승인 범위

사용자의 네 항목 전체 진행 요청에 따라 기존 실습을 확장함. 목표는 새 스택 추가가 아니라 실패 감지·복구·관측 누락을 재현 가능한 결과로 증명하는 것임. 일반 개발·검증·PR·병합은 승인됨. 새 N100 변경은 실행 대상·순서를 준비한 뒤 별도 최종 승인 범위를 확인함.

## 구성과 성공 기준

| 영역 | 입력·출력 | 성공 기준 | 제외 범위 |
|---|---|---|---|
| Loki | 기존 고정 context·namespace → 검증 상태 | 최대 3회·총 제한 시간 내 readiness/샘플 조회. 최종 실패를 숨기지 않음. Grafana/API·보존·rollback 절차와 증거 구분 | 기존 monitoring release·Secret·PVC 데이터 삭제 |
| 실패 배포 훈련 | 전용 실습 자원 → 실패 감지·원상 복구 결과 | 정상 기준선 확인 후 의도적 probe 실패, 제한 시간 내 감지, 고정 정상 버전 복구와 health 확인. interrupt에도 복구 시도하고 복구 실패는 실패 보고 | 운영 앱·writer·기존 배포 정책 변경 |
| Ansible drift | 소유 확인된 localhost 실습 파일 → 차이·복구·멱등성 결과 | 응답 파일에만 의도적 drift 주입, check/diff 감지, site로 원복, 다음 실행 changed=0 | Compose 소유 계약 완화·임의 경로·운영 설정 변경 |
| SLO | 기존 records.json와 KST 기간 → 읽기 전용 집계 JSON | 성공·실패·unobservable·미수집 날짜 분리. 관측 가능 비율/coverage 명시. 일일 최솟값을 가용성 시간·30일 에러 버짓으로 환산하지 않음 | 수집 CronJob·보존 기간·SLO 경보·목표 자동 변경 |

## 경계

2026-10-05 읽기 전용 진단에서 최신 수집 Job의 공개 health HTTP 403을 확인함. 같은 N100에서 urllib 기본 식별자 403, 고정 모니터 식별자 200이 재현됨. SLO 실측 보강의 최소 보완으로 수집기의 공개 GET에 정직한 고정 User-Agent만 추가함. 기존 실패 증거·운영 이미지·CronJob·일정은 변경하지 않음. 실제 403은 계속 failed로 보존함.

- 실습 도구는 기본 dry/check를 제공하고 실제 변경은 명시 실행 모드로 구분함.
- Secret·운영 데이터·원시 로그·내부 주소를 출력하거나 기록하지 않음.
- SLO 입력이 손상·중복·미래 날짜이면 집계를 실패 처리함. 30일 자료 부족은 명시하고 성공으로 채우지 않음.
- 실제 N100 증거가 없는 검증은 로컬 테스트 통과와 분리해 미수행으로 기록함.
- Grafana 화면 및 24시간 삭제 검증은 경과·접속 증거가 확보된 뒤에만 완료 표시함.
