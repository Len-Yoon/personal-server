# A4 메모 목록 페이지네이션 설계

## 범위와 근거

Book·YouTube 홈의 저장 목록을 페이지당 24건으로 제한함. Book 외부 도서 검색과 `/api/search`, 영상·책 상세, Crawler JSON 보관함은 변경하지 않음. 로컬 자료는 Book 3권·목차 19건·메모 0건, YouTube 영상 2건·메모 1건으로 작음. N100 실제 규모와 성능 효과는 확인 필요임.

## 동작

| 경계 | 기준 |
|---|---|
| 입력 | 홈 `page`는 1부터 시작함. 0·음수는 422, 총 페이지 초과는 마지막 페이지로 이동함. 빈 목록의 현재 페이지는 1임. |
| 정렬 | Book의 기존 상태 우선순위·`updated_at DESC, id DESC`와 YouTube의 `updated_at DESC, id DESC`를 유지함. |
| 조회 | 총건수를 별도로 표시하고, 목록과 Book 목차는 현재 페이지에 해당하는 항목만 조회함. |
| 화면 | 이전·다음 링크, 현재/총 페이지와 총건수를 표시함. Book 검색어 `q`와 책장 수정·삭제 및 영상 삭제의 `page` 문맥을 보존함. |
| 저장 | 기존 SQLite 테이블과 데이터는 유지함. 인덱스는 쿼리 계획 근거가 있는 경우에만 추가함. |

## 검증·위험

25건 이상 자료의 페이지 경계, 동률 정렬, 상태 우선순위, 삭제 후 범위 보정, 검색어 링크와 목차 조회 범위를 회귀 테스트함. 합성 자료의 `EXPLAIN QUERY PLAN`으로 Book·YouTube 정렬 인덱스와 관계 조회 인덱스 사용을 확인함. 외부 정렬 단계의 임시 B-tree는 선택된 24건에 한정됨. 운영 DB 인덱스 생성은 배포 시 스키마 쓰기를 수반하므로 운영 배포 승인 전 실행하지 않음. 목록 변경 사이 페이지 이동 시 OFFSET 방식으로 항목 위치가 달라질 수 있음.
