# Design: HomeOps 전체 상태 요약 및 일괄 재시작

## Problem Statement

현재 HomeOps는 서비스별 진단 이력과 승인·실행 흐름을 노출함. 운영 화면에서 필요한 정보보다 이력이 먼저 보이고, `homeops-executor`가 자기 자신을 재시작할 때 HTTP 연결이 끊겨 포털에 Internal Server Error가 표시될 수 있음.

## Goal

관리자가 한 번의 진단으로 모든 HomeOps 관리 대상 서비스의 정상·비정상 상태와 비정상 이유만 간결하게 확인하고, 한 번의 전체 재시작 요청으로 관리 대상 컨테이너를 재시작한 뒤 최종 결과를 확인할 수 있게 함.

## Constraints

- HomeOps 관리 대상은 기존 allowlist 서비스로 한정함.
- 관리자 HomeOps 세션 인증과 same-origin 검증을 유지함.
- 서버 기동 스크립트와 Windows 정기 스케줄러는 수정하지 않음.
- Docker 소켓 접근은 `homeops-executor`에만 유지함.
- `homeops-executor`는 마지막에 재시작함. 자기 재시작으로 인한 연결 종료는 포털에서 예상 가능한 상태로 처리하고, 재기동 health 확인으로 최종 성공·실패를 판정함.

## Design

### 1. 단일 진단 결과

포털의 HomeOps 진단 요청은 서비스 선택값 없이 기존 allowlist 전체를 조회함. 서비스별 원시 로그와 개별 incident 목록 대신 단일 요약 결과를 생성함.

- 정상: health가 `healthy`이거나 health check가 없는 실행 중 서비스
- 비정상: 실행 중이 아님, health가 `unhealthy`, 또는 실행기 응답 실패
- 비정상 이유: `중지됨`, `healthcheck 비정상`, `실행기 응답 없음` 중 하나로 제한함

화면은 `정상: ... / 비정상: ...` 한 줄과 비정상 서비스별 이유만 표시함. 비정상이 없으면 `비정상: 없음`으로 표시함.

### 2. 전체 재시작

진단 결과와 관계없이 인증된 관리자는 `전체 재시작`을 한 번 실행할 수 있음. 실행기는 allowlist 서비스 전체를 정해진 순서로 재시작하고, `homeops-executor`를 마지막에 둠.

포털은 각 서비스가 재시작 후 health 상태로 회복하는지 확인함. 실행기의 자기 재시작으로 응답 연결이 끊긴 경우에는 이를 즉시 실패로 기록하지 않고, 실행기 health endpoint가 다시 응답할 때까지 제한된 횟수로 확인함.

결과는 `정상`, `복구됨`, `복구 확인 실패` 서비스 목록으로 단일 결과로 표시함.

### 3. 화면 및 기존 이력

서비스 선택, 개별 승인, 개별 실행 버튼, 개별 incident 이력 테이블은 HomeOps 화면에서 제거함. 기존 SQLite 테이블은 호환성을 위해 삭제하지 않되, 새 화면은 단일 진단·일괄 실행 결과만 사용함.

## Error Handling

- 진단 중 실행기 연결 실패는 서비스 상태 `실행기 응답 없음`으로 표시하고 500 오류를 반환하지 않음.
- 전체 재시작 중 일반 서비스 재시작 실패는 해당 서비스만 `복구 확인 실패`로 집계하고 나머지 대상 처리를 계속함.
- 실행기 자기 재시작에 따른 연결 종료는 재기동 health 재확인 결과로 성공·실패를 결정함.
- 인증·same-origin 검증 실패는 기존 403 동작을 유지함.

## Success Criteria

- 관리자는 한 번의 버튼으로 전체 상태 요약을 확인할 수 있음.
- 화면에는 정상 서비스, 비정상 서비스, 비정상 이유만 간결하게 표시됨.
- 관리자는 한 번의 `전체 재시작` 버튼으로 allowlist 대상 전체를 요청할 수 있음.
- `homeops-executor` 포함 전체 재시작에서 포털이 Internal Server Error를 표시하지 않음.
- 기존 HomeOps 인증·allowlist 보안 테스트와 새 단일 요약·일괄 재시작 테스트가 통과함.

## Out of Scope

- Windows, WSL, Docker 엔진, Compose 전체 스택의 재시작
- 서버 기동 스크립트와 정기 스케줄러 변경
- 자동 재시작 정책의 확장 또는 재시도 정책 변경
