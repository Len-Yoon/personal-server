# 사용자 표시 시간 KST 통일 설계

## 목적

개인 서버의 사용자 화면에 표시되는 모든 시각을 한국 표준시(`Asia/Seoul`) 기준의 `YYYY-MM-DD HH:MM` 형식으로 통일한다. 화면 문구에는 `KST`를 별도로 붙이지 않는다.

## 범위

| 서비스 | 대상 | 변경 내용 |
|---|---|---|
| 포털 관리자 | HomeOps 운영 이력, 상태 수집 시각, 보안 이벤트 | KST 변환 후 `YYYY-MM-DD HH:MM` 표시 |
| 뉴스 | 기사 수집·발행 시각 | 기존 KST 변환은 유지하고 형식만 통일 |
| 책 메모 | 메모 생성 시각 | SQLite UTC 값을 KST로 변환해 표시 |
| YouTube 메모 | 메모 생성 시각 | SQLite UTC 값을 KST로 변환해 표시 |

## 제외 범위

- 데이터베이스 저장값, 정렬, 만료·쿨다운·스케줄 판단 로직
- 서버 기동 코드와 스케줄러 코드
- 차량관리 Telegram 알림의 시간 표기 추가
- 과거 설계 문서의 예시 시각

## 설계

모든 서비스는 내부 저장과 비교에 기존 UTC 값을 유지한다. 템플릿 직전의 표시 전용 포매터만 `Asia/Seoul`로 변환한다. 시간대가 없는 기존 SQLite `CURRENT_TIMESTAMP` 값은 UTC로 간주한다. 비어 있거나 해석할 수 없는 값은 기존처럼 빈값 또는 `unknown`으로 안전하게 처리한다.

표시 포맷은 모든 대상에서 `YYYY-MM-DD HH:MM`으로 동일하다. 따라서 `KST`, 요일, 초 단위는 사용자 화면에서 제거된다.

## 검증

- UTC ISO 시간과 시간대 없는 SQLite UTC 시간이 모두 KST 기준 시각으로 표시되는지 확인
- 화면 출력에 `KST`, UTC 오프셋, ISO `T` 표기가 남지 않는지 확인
- 뉴스·포털·책 메모·YouTube 메모의 관련 테스트를 실행
- 전체 서비스 테스트와 변경 범위 검토를 실행

## 성공 기준

- 대상 화면의 시간은 KST 기준 `YYYY-MM-DD HH:MM` 형식으로 표시됨
- 내부 UTC 저장·비교·스케줄러 동작은 변경되지 않음
- 서버 기동 및 스케줄러 파일은 변경되지 않음
