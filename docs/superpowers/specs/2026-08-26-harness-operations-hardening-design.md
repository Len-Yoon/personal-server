# 변경 하네스 운영 보강 설계

## 1. 목적

변경 하네스의 입력 증적 바이트 절감과 실제 모델 토큰 절감을 구분하여 기록하고, CI와 로컬 하네스의 증적 경계를 명확히 함. NUL 기반 Git 변경 목록과 보고서 보관 기준을 회귀 검증 가능하게 유지함.

## 2. 범위 및 제외 범위

| 구분 | 내용 |
|---|---|
| 포함 | 토큰 측정 기록 검증·집계, 하네스 요약 artifact, NUL 입력 계약 테스트, 실행 예시, 문서·보고서 보관 기준 |
| 제외 | 서버 기동, 스케줄러, 배포 workflow 및 배포 스크립트 변경 |
| 시간 기준 | 측정 시각은 KST 표기와 UTC 시간대 인식 ISO 8601 원문을 함께 보존함 |

## 3. 설계

### 3.1 토큰 측정 기록

작업자는 JSONL 파일에 작업 식별자, 측정 그룹, 모델명, 프롬프트 지문, UTC 시각, 원본/압축 입력 토큰, 원본/압축 출력 토큰을 기록함. 측정 도구는 음수·누락값·시간대 없는 시각과 서로 다른 조건이 섞인 기록을 거부하고, 총 토큰 절감량 및 절감률을 JSON으로 출력함. 바이트 기반 79.5% 결과와 실제 토큰 결과를 혼용하지 않음.

### 3.2 CI 증적 경계

CI는 변경 목록과 서비스 테스트 결과로 정책 증적을 생성함. 동일 변경 목록으로 변경 하네스를 실행해 `--agent-context`와 구조화 JSON을 artifact에 추가함. 하네스의 `ready_for_review`는 사람 검토 가능 상태일 뿐 CI 성공 또는 배포 승인이 아님.

### 3.3 입력 계약

하네스 CLI는 `git-name-status-z` 입력에서 rename의 이전·이후 경로, 공백·한글 경로를 보존함. 해당 입력은 정책 검증기와 동일한 경로 분류 결과를 내야 함.

### 3.4 보관 및 사용성

실행 문서는 `git diff --name-status -z --find-renames`로 입력 파일을 만들고, 검증 뒤 실제 결과를 전달하는 두 단계 예시를 제공함. `.superpowers/sdd/` 보고서는 이미 추적된 완료 보고서만 보관 대상으로 인정하며, 새 임시 메모는 Git 제외 상태를 유지함.

## 4. 오류 처리 및 성공 기준

| 항목 | 기준 |
|---|---|
| 기록 오류 | 누락·음수 토큰·UTC 미포함 시 입력 오류로 종료함 |
| CI 오류 | 하네스 증적 생성 실패 또는 서비스 테스트 실패 시 summary job을 실패 처리함 |
| 테스트 | 단위·CLI·CI 계약 테스트가 통과해야 함 |
| 금지 영역 | `scripts/deploy-n100.sh`, `deploy-n100.yml`, 서버 기동·스케줄러 파일을 수정하지 않음 |

## 5. 확인 필요 사항

- 모델 제공자별 사용량 API 연동은 인증 정보와 비용·권한 범위가 필요하므로 이번 범위에 포함하지 않음.
- 실제 절감률은 동일 작업·모델·프롬프트 조건에서 기록값을 수집한 뒤 확정 필요함.
