# 개인서버 Codex 작업 완료 루프 설계

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 문서명 | 개인서버 Codex 작업 완료 루프 설계 |
| 작성일 | 2026-08-21 |
| 작성자 | Codex |
| 기준 자료 | `AGENTS.md`, 기존 테스트 구성, 기존 CI/CD 배포 게이트 설계 |
| 목적 | Codex 코드 작업의 계획·검증·재시도·중단·보고 절차를 프로젝트 규칙으로 표준화함 |
| 비고 | 개인서버 저장소에만 적용함 |

## 2. 핵심 요약

- `AGENTS.md`에는 모든 코드 변경에 적용할 필수 규칙과 상세 문서 참조를 추가함.
- 상세 절차는 `docs/codex-work-loop.md`에 분리하여 유지함.
- 완료 여부는 Codex의 자체 판단이 아니라 관련 검증 명령의 결과로 판단함.
- 실패 원인을 확인한 최소 수정만 허용하며, 최대 3회까지 재검증함.
- 변경 범위가 불명확하거나 보안·운영 영향 판단이 필요한 경우 즉시 중단하고 사용자 확인을 요청함.

## 3. 적용 범위

| 구분 | 내용 | 비고 |
|---|---|---|
| 적용 대상 | 개인서버 저장소에서 수행하는 코드·설정·문서 변경 작업 | Codex 작업에 적용 |
| 제외 대상 | 서버 기동 영역 및 스케줄러 영역의 변경 | 기존 `AGENTS.md` 제한 유지 |
| 전역 적용 | 적용하지 않음 | 다른 프로젝트에 영향 없음 |
| 자동 실행 | 적용하지 않음 | Codex가 작업 시 절차를 따르는 문서형 루프임 |

## 4. 작업 완료 루프

```text
작업 요청 확인
→ 변경 범위·제외 범위·성공 기준 확인
→ 구현 계획 수립 및 승인 확인
→ 최소 범위 변경
→ 관련 테스트·정적 검사 실행
→ 성공 시 변경사항 검토 및 결과 보고
→ 실패 시 원인 분석
→ 최소 수정 후 재검증(최대 3회)
→ 반복 실패·위험 판단 시 중단 및 사용자 확인 요청
```

## 5. 검증 및 중단 기준

| 구분 | 기준 | 처리 |
|---|---|---|
| 검증 성공 | 관련 테스트와 적용 가능한 정적 검사가 성공함 | 변경사항 검토 후 완료 보고 |
| 검증 실패 | 테스트 또는 정적 검사 실패 | 원인 확인 후 최소 수정 및 재검증 |
| 재시도 한도 | 동일 작업에서 최대 3회 재검증함 | 한도 초과 시 중단 및 원인 보고 |
| 검증 불가 | 테스트가 없거나 환경상 실행 불가함 | 성공으로 간주하지 않고 `확인 필요`로 보고 |
| 범위 불명확 | 요구사항 또는 변경 대상이 확정되지 않음 | 구현 전 사용자 확인 요청 |
| 위험 변경 | 보안·운영·배포 영향 또는 금지 영역 접근이 필요함 | 변경 전 사용자 확인 요청 |

## 6. 완료 보고 기준

완료 보고에는 아래 항목을 포함함.

| 항목 | 내용 |
|---|---|
| 변경 내용 | 변경 목적과 주요 변경사항 |
| 변경 파일 | 생성·수정한 파일 목록 |
| 검증 결과 | 실행 명령과 성공·실패 결과 |
| 미검증 항목 | 실행하지 못한 검증과 사유 |
| 확인 필요 사항 | 사용자 판단 또는 후속 작업이 필요한 사항 |

## 7. 제외 범위

- Codex 전역 설정, 전역 스킬, 자동화 일정은 변경하지 않음.
- CI/CD workflow, 서버 기동 스크립트, 스케줄러 코드는 본 문서 작업으로 변경하지 않음.
- 자동 재시도 스크립트 또는 외부 서비스 연동은 포함하지 않음.

## 8. 후속 조치

1. 설계 승인 후 `AGENTS.md`에 필수 규칙과 상세 문서 참조를 추가함.
2. `docs/codex-work-loop.md`에 실제 작업 절차와 보고 양식을 작성함.
3. 실제 Codex 작업에 적용하여 재시도·중단 기준의 적합성을 확인함.
4. 반복 적용 후 공통성이 검증되면 전역 개인 스킬 승격 여부를 검토함.
