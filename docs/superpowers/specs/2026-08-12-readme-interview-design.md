# README 면접 관점 개선 설계

## 목적

프로젝트 README를 기술 나열 중심 설명에서 문제 해결과 의사결정 중심의 포트폴리오 문서로 보완함. OpenAI Codex 활용 사실은 유지하되, 요구사항·보안 정책·운영 구조의 최종 판단 주체가 프로젝트 작성자임을 명확히 함.

## 변경 범위

- `README.md`의 도입 문구를 프로젝트 목적과 작성자 주도로 변경함.
- 뉴스, 파일함, 호스트 상태, 공개 쓰기 보안의 사례를 문제·결정·검증 결과 표로 추가함.
- Cloudflare Tunnel, localhost 바인딩, 역할별 인증, 검증 게이트를 작성자 의사결정으로 설명함.
- Codex 기반 역할 분리 개발 방식을 과장 없이 기술함.
- GitHub Actions CI와 N100 self-hosted 배포의 역할을 구분함.

## 제약 사항

- 실제 코드와 운영 문서에서 확인되는 사실만 작성함.
- 공개 도메인·구조는 기록하되, 비밀값·개인 데이터·관리자 인증 정보는 작성하지 않음.
- 서버 기동과 스케줄러 구성은 수정하지 않음.

## 검증 기준

- README의 링크와 이미지 경로를 유지함.
- `git diff --check`가 통과해야 함.
- AI 활용 설명이 작성자의 책임과 최종 판단을 흐리지 않아야 함.
