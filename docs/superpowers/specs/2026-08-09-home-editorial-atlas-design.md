| 항목 | 내용 |
|---|---|

| 기준 자료 | `portal-web/app/routers/dashboard.py`, `portal-web/app/templates/dashboard.html`, 현재 서비스 구성 |
| 목적 | 실제 서비스 진입과 통합 검색 기능을 유지하면서 개인 서버 메인 화면의 UI/UX를 고급화함 |

## 핵심 요약

메인 화면은 로그인 기반 운영 대시보드가 아닌 개인 서비스 허브로 유지함. 기존 서비스 목록과 통합 검색 기능을 보존하고, 밝은 종이 질감과 짙은 잉크 색상을 사용하는 `Editorial Atlas` 디자인 언어를 적용함.

현재 존재하지 않는 실시간 메인 상태 수치, 사용자 인사, 로그인 상태는 화면에 추가하지 않음. 관리자 상태는 인증이 필요한 별도 서비스 카드로만 노출함.

## 현재 기능 기준

| 구분 | 현재 기능 | 메인 화면 반영 방식 | 비고 |
|---|---|---|---|
| 뉴스 허브 | 일반 뉴스, 주식 뉴스, 보관 뉴스 확인 | 서비스 카드 `뉴스 허브` | `/news` 진입 유지 |
| 유튜브 메모장 | 영상별 학습 메모, 타임스탬프 기록 | 서비스 카드 `유튜브 메모장` | `/memo` 진입 유지 |
| 책 메모장 | 독서 진행률, 목차, 독서 메모 | 서비스 카드 `책 메모장` | `/books` 진입 유지 |
| 파일함 | 파일 업로드, 다운로드, 폴더 관리 | 서비스 카드 `파일함` | `/files` 진입 유지 |
| 관리자 상태 | 인증 후 서버, 보안, 백업 상태 확인 | 서비스 카드 `관리자 상태` | 인증 절차 유지 |
| 자동매매 결과지 | 아직 구현되지 않음 | 비활성 예정 카드 | 링크 동작 없음 |
| 통합 검색 | 저장 뉴스, 유튜브 메모, 책 메모 검색 | 하단 검색 영역 | 기존 검색 범위 유지 |

## 디자인 방향

### 1. 시각 언어

| 항목 | 적용 기준 |
|---|---|
| 기본 배경 | 따뜻한 밝은 회백색(`#edece7`) 계열 사용 |
| 기본 텍스트 | 짙은 잉크색(`#161918`) 사용 |
| 강조색 | 연두색 포인트(`#d4ff53`)를 검색 및 제한된 행동 요소에 사용 |
| 카드 | 얇은 경계선, 낮은 대비 배경, 최소 그림자 사용 |
| 타이포그래피 | 큰 제목과 짧은 설명으로 정보 계층을 분명히 함 |
| 장식 | 서비스별 은은한 원형 배경을 사용하되 기능 식별을 방해하지 않음 |

### 2. 화면 구조

1. 상단에는 `LEN / PERSONAL SERVER` 브랜드와 서비스 허브 상태를 표시함.
2. 히어로 영역에는 개인 서버의 목적을 짧은 문장으로 표시함.
3. 서비스 영역에는 현재 서비스 5개와 예정 서비스 1개를 동일한 카드 격자로 표시함.
4. 카드에는 번호, 용도 분류, 서비스명, 짧은 설명, 진입 동작을 표시함.
5. 통합 검색은 화면 하단에 단일 진입점으로 배치함.
6. 푸터에는 로컬·개인용·집중형 서비스라는 성격만 간결히 표시함.

### 3. 반응형 기준

| 화면 너비 | 적용 방식 |
|---|---|
| 데스크톱 | 서비스 카드 3열 격자 사용 |
| 태블릿 | 서비스 카드 2열 격자 사용 |
| 모바일 | 서비스 카드 1열, 검색 버튼 전체 너비 사용 |

## 공통 확장 원칙

이 메인 화면의 색상, 경계선, 타이포그래피, 버튼 및 상태 표현 규칙은 이후 각 서비스 화면에 적용함. 단, 모든 화면의 레이아웃을 동일하게 만들지 않음.

| 화면 | 디자인 시스템 적용 방향 |
|---|---|
| 뉴스 허브 | 기사 관련성, 출처, 시간, 필터를 읽기 쉬운 리서치 화면으로 구성함 |
| 파일함 | 탐색기형 목록/아이콘 보기와 파일 작업 흐름을 우선함 |
| 유튜브·책 메모 | 콘텐츠 제목, 진행률, 메모 탐색을 우선함 |
| 관리자 상태 | 실제 수집 시각, 경고, 상태 등급을 운영 리포트 형태로 명확히 표시함 |
| 포트폴리오 | 공개 사이트의 목적이 다르므로 별도 밝은 포트폴리오 톤을 유지함 |

## 제약 조건

- 서버 기동 영역 및 스케줄러 영역은 수정하지 않음.
- 기존 서비스 URL, 통합 검색 범위, 관리자 인증 정책을 변경하지 않음.
- 공개 메인 화면에 실제 서버 상태, 파일 경로, 보안 이벤트를 노출하지 않음.
- 자동매매 결과지는 구현 전까지 비활성 상태를 명확히 표시함.
- `Private workspace · 2026`과 같은 연도 표기가 필요할 경우 하드코딩하지 않고 서버 기준 현재 연도를 사용함.

## 검증 기준

| 검증 항목 | 완료 기준 |
|---|---|
| 서비스 진입 | 운영 중인 서비스 카드가 기존 URL로 이동함 |
| 예정 서비스 | 자동매매 결과지 카드가 활성 서비스처럼 동작하지 않음 |
| 통합 검색 | 기존 검색 폼과 결과 그룹이 유지됨 |
| 반응형 | 데스크톱, 태블릿, 모바일에서 카드가 겹치지 않음 |
| 접근성 | 링크와 버튼의 키보드 포커스, 충분한 색 대비, 의미 있는 라벨을 제공함 |
| 보안 | 메인 화면에 인증 전 관리자 상세 정보가 표시되지 않음 |

## 확인 필요 사항

- 메인 화면 문구 `모으고, 기록하고, 다시 꺼내는 곳.`의 확정 여부 확인 필요.
- 자동매매 결과지의 향후 실제 기능 범위 확인 필요.
- 메인 페이지에서 서비스별 최근 항목을 미리보기로 표시할지 여부 확인 필요. 현재 설계에서는 기존 기능만 유지하기 위해 제외함.

## 후속 조치

1. 사용자 검토 후 메인 화면 구현 계획을 작성함.
2. 메인 화면 구현 후 뉴스 허브, 파일함, 관리자 상태 순으로 화면별 디자인 설계를 분리함.
3. 각 화면 변경 전 기존 기능 및 테스트 범위를 다시 확인함.
