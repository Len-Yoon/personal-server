# 개인 서버 보안 보강 설계

## 목적

공개 개인 서버에서 책 메모·유튜브 메모의 무단 변경을 차단하고, 기존 파일함·포트폴리오 인증의 세션 및 브라우저 방어를 강화함.

## 범위

- 책 메모와 유튜브 메모의 모든 상태 변경 요청을 관리자 인증으로 보호함.
- 파일함과 포트폴리오 인증을 임의 토큰 기반 세션으로 전환하고, 운영 HTTPS에서는 Secure 쿠키를 사용함.
- 포털·뉴스·책·유튜브 서비스에 동일한 보안 응답 헤더와 Origin 기반 CSRF 방어를 적용함.
- 인증 실패 제한을 서비스별 JSON 상태 파일에 저장하여 재시작 후에도 유지함.
- `APP_ENV`, `FILE_MANAGER_AUTH_REQUIRED` 설정을 실제 파일함 인증 정책에 반영함.

## 제외 범위

- 외부 API 키·토큰·비밀번호 교체는 운영자가 수행하는 별도 작업으로 제외함.
- 서버 기동 파일과 Windows 스케줄러 파일은 변경하지 않음.
- 사용자 계정·다중 사용자 권한 체계는 추가하지 않음.

## 설계 결정

### 1. 쓰기 인증

기존 `DELETE_PASSWORD`를 책·유튜브의 쓰기 비밀번호로 재사용함. 로그인 성공 시 서비스별 HTTP-only 세션 쿠키를 발급하고, 이후 쓰기 요청은 세션을 요구함. 기존 삭제 폼의 비밀번호 입력 흐름은 유지하되, 세션이 없는 직접 요청은 차단함.

### 2. 세션과 쿠키

세션 값은 `secrets.token_urlsafe()`로 발급하고 서버 메모리에서 만료 시간을 관리함. 파일함·포트폴리오도 비밀번호에서 파생한 고정 쿠키 대신 이 방식을 사용함. 쿠키는 `HttpOnly`, `SameSite=Lax`를 사용하고 `APP_ENV=production`일 때 `Secure`를 적용함. 서버 재시작 시 기존 로그인 세션이 만료되는 것은 허용함.

### 3. CSRF 및 보안 헤더

상태 변경 메서드에서 브라우저가 보내는 `Origin`이 현재 요청의 HTTPS 호스트와 일치하는지 검증함. Origin이 없는 비브라우저 요청은 기존 내부/테스트 호환을 위해 허용하지 않고 명시적으로 차단함. 각 FastAPI 앱은 동일한 CSP, 클릭재킹 방지, MIME 스니핑 방지, Referrer, Permissions 헤더를 반환함.

### 4. 인증 실패 제한 저장

각 서비스는 `AUTH_RATE_LIMIT_STATE_PATH`가 설정되면 해당 경로에, 아니면 자신의 데이터 경로 아래에 상태 JSON을 원자적으로 저장함. 5회/300초 기본 정책은 유지하며, 오래된 기록은 매 접근 시 제거함.

### 5. 환경변수 정합성

파일함은 `FILE_MANAGER_AUTH_REQUIRED=true` 또는 `APP_ENV=production`이면 접근 비밀번호 누락 시 차단함. 두 값이 모두 비활성인 로컬 개발에서만 비밀번호 없이 접근할 수 있음.

## 검증 기준

- 인증 없이 책·유튜브의 생성·수정·삭제 POST 요청이 401 또는 403으로 거부됨.
- 정상 로그인 세션과 동일 Origin 요청은 성공함.
- 교차 Origin POST 요청은 403으로 거부됨.
- 파일함 및 포트폴리오 쿠키가 운영 모드에서 Secure, HttpOnly, SameSite 속성을 가짐.
- 서비스별 보안 헤더가 모든 앱 응답에 존재함.
- 인증 제한 상태가 새 서비스 인스턴스에서도 다시 읽힘.
- 기존 포털, 파일함, 뉴스, 책, 유튜브 테스트가 회귀 없이 통과함.
