# A5 Portal 파일 경계 설계

| 항목 | 내용 |
|---|---|
| 기준 | `docs/20260921_프로젝트보완_개발계획.md` A5, Portal 코드와 Caddy 설정 |
| 목적 | 저장소 밖 symlink 읽기·삭제 및 업로드 임시 저장 고갈 경로 차단 |
| 제외 | Caddy·Tunnel·K3s·PVC·운영 데이터·배포 정책 변경, N100 운영 적용 |

## 핵심 경계

| 경로 | 원본 | 동작 | 오류 |
|---|---|---|---|
| 목록 | 저장소 디렉터리 | symlink 항목 표시·추적 금지 | 정상 항목은 표시 |
| 직접 경로 | 조회·업로드·다운로드·삭제 | 루트 아래 구성요소의 symlink 접근 거부 | 기존 400/404 매핑 |
| 폴더 ZIP | 재귀 하위 항목 | 검사 뒤에도 실제 파일을 디렉터리 FD·`O_NOFOLLOW`로 열어 저장소 밖 바이트 차단; 실제 작성 바이트·항목 수 재검사 | 400, 임시 ZIP 없음 |
| 폴더 삭제 | 재귀 하위 항목 | 디렉터리 FD·`O_NOFOLLOW`로 다시 검사한 뒤 같은 FD 기준 삭제; 정적 symlink와 검사 직후 교체 거부 | 400 |
| 단일·다중 업로드 | 두 업로드 POST의 ASGI receive | Content-Length 사전 검사 및 파서로 전달하는 스트림 바이트 제한 | 초과 시 413 |

수신 상한은 저장 파일 상한에 multipart 여유 1 MiB를 더한 값으로 함. 기본 단일 26 MiB, 다중 31 MiB임. 외부 다중 요청에는 Caddy의 기존 30 MB 제한이 별도 적용되므로 실제 상한은 더 작은 값임. Caddy를 거치지 않는 요청과 기존 단일 업로드 경로는 애플리케이션 한도가 보호함. 저장 함수의 파일별·합계 한도는 유지함.

구성된 저장소 루트 자체가 symlink이면 그 실제 경로를 경계로 사용함. 그 아래 symlink는 내부 대상이라도 거부함. ZIP과 삭제의 실제 읽기·재귀 처리는 디렉터리 FD에서 `O_NOFOLLOW`로 항목을 열어 symlink 교체 후 외부 대상을 따라가지 않음. 다만 권한 있는 로컬 프로세스가 이미 열린 디렉터리를 동시에 저장소 밖으로 rename하는 경우까지 원자적으로 막는 것은 별도 파일시스템 격리 또는 협조 잠금이 필요함. 목록·개별 다운로드·업로드 등 이번 변경의 FD 적용 대상이 아닌 경로에도 로컬 파일시스템 동시 교체 잔여 위험이 있음.

업로드 본문은 메모리에 모으지 않고 multipart 파서로 스트리밍 전달하며, 수신 누적량이 초과하면 파서의 응답을 413으로 바꿈. 따라서 요청별 임시 저장 바이트는 상한 내에 묶이지만 다수 동시 업로드의 총 임시 저장량까지 제한하지 않음.
