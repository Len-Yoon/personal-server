# A5 Portal 파일 경계 설계

| 항목 | 내용 |
|---|---|
| 기준 | `docs/20260921_프로젝트보완_개발계획.md` A5, Portal 코드와 Caddy 설정 |
| 목적 | 저장소 밖 symlink 읽기·삭제 및 업로드 임시 저장 고갈 경로 차단 |
| 제외 | Caddy·Tunnel·K3s·PVC·운영 데이터·배포 정책 변경, N100 운영 적용 |

## 핵심 경계

| 경로 | 원본 | 동작 | 오류 |
|---|---|---|---|
| 목록 | 저장소 디렉터리 | symlink 항목 표시·추적 금지 | 정상 항목은 표시 |
| 직접 경로 | 조회·업로드·다운로드·삭제 | 루트 아래 구성요소의 symlink 접근 거부 | 기존 400/404 매핑 |
| 폴더 ZIP | 재귀 하위 항목 | symlink 트리 거부, 외부 바이트 미포함 | 400, 임시 ZIP 없음 |
| 폴더 삭제 | 재귀 하위 항목 | 삭제 전 symlink 트리 거부, 원본 보존 | 400 |
| 단일·다중 업로드 | 두 업로드 POST의 ASGI receive | multipart 파서 이전에 Content-Length·실제 수신 바이트 제한 | 초과 시 413 |

수신 상한은 저장 파일 상한에 multipart 여유 1 MiB를 더한 값으로 함. 기본 단일 26 MiB, 다중 31 MiB임. 외부 다중 요청에는 Caddy의 기존 30 MB 제한이 별도 적용되므로 실제 상한은 더 작은 값임. Caddy를 거치지 않는 요청과 기존 단일 업로드 경로는 애플리케이션 한도가 보호함. 저장 함수의 파일별·합계 한도는 유지함.

구성된 저장소 루트 자체가 symlink이면 그 실제 경로를 경계로 사용함. 그 아래 symlink는 내부 대상이라도 거부함. 동시 로컬 파일시스템 교체에 따른 검사·사용 간 경합은 경로 기반 검사만으로 완전히 막을 수 없으며 FD 기반 전 경로 처리는 후속 보안 과제로 남김. 수신 본문은 파서에 전달하기 전에 메모리에 최대 상한만큼 보관함. 따라서 요청별 디스크 임시 저장은 제한되지만 동시 요청의 총 메모리 사용량까지 제한하지 않음.
