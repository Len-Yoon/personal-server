## 3. 선택지와 결정

| 선택지 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 완료된 계획·설계를 삭제 | 문서 수 감소 | 변경 배경과 검증 근거를 잃음 | 선택하지 않음 |
| 모든 문서를 현재 문서로 갱신 | 한 위치에서 확인 가능 | 과거 판단을 현재 사실처럼 바꿀 위험이 큼 | 선택하지 않음 |
| 현재 운영 문서를 전면화하고 이력은 보관 | 운영자가 빠르게 찾고 과거 근거도 유지 가능 | 색인·상태 표기를 관리해야 함 | 적용함 |

## 5. 변경 설계

### 5.1 단일 진입점 보강

`docs/README.md`에 아래를 반영함.

- 운영자가 읽는 권장 순서: 운영 참조 → N100 또는 배포 → 공개 HTTPS 방식 → 작업 규칙
- 각 문서를 `현재 운영 기준`, `참고 자료`, `과거 이력`으로 분류함.
- “마지막 정합성 점검” 날짜를 실제 이번 점검일로 갱신하고, 점검 기준을 명시함.

### 5.2 현재 운영 문서 정합성 보강

- `agent-handoff.md`에 현재 브랜치·PR·CI·배포·정리 규칙을 `codex-work-loop.md` 기준으로 연결함.
- `operations-reference.md`에는 실행 명령보다 기준 문서를 우선하고, 공개 HTTPS 방식은 하나만 선택해 운영한다는 경계를 유지함.
- Tunnel·Caddy 문서에는 공통 도메인·포트 정보의 기준이 운영 참조임을 표시해 중복 갱신 위험을 줄임.
- `codex-work-loop.md`와 `agent-loop-evidence.md`에는 서로의 역할과 90일 artifact 보존 한계를 교차 연결함.

### 5.3 이력 보존과 명백한 중복 제거

- `docs/superpowers/README.md`에 설계·계획 파일은 완료 여부와 무관하게 이력으로 보관하며 현재 실행 지침이 아님을 명시함.
- 다음 두 plan의 본문 끝에 실수로 포함된 현재 문서 사본만 삭제함. 해당 현재 문서는 별도 파일에 존재함.
  - `2026-08-21-agent-loop-ci-gate.md`의 `# 에이전트 작업 루프 검증 증거` 이후 본문
  - `2026-08-21-codex-work-completion-loop.md`의 `# Codex 작업 완료 루프` 이후 본문
- 과거 QA 보고서와 개별 기능 설계·계획은 삭제하지 않음.

### 5.4 검증

- 문서 내 상대 Markdown 링크가 모두 존재하는지 확인함.
- 중복 본문이 제거된 두 plan은 각각 하나의 최상위 제목만 남는지 확인함.
- `python3 -m unittest tests.test_verify_change_scope tests.test_compose_config -v` 및 `git diff --check`를 실행함.

## 6. 완료 기준

1. `docs/README.md`만 읽어도 현재 운영 문서와 과거 이력을 구분할 수 있음.
2. 현재 운영 문서가 서로의 기준 역할을 명확히 연결함.
3. 설계·계획 이력은 보존되고, 명백한 복제 본문만 제거됨.
4. 상대 링크·문서 정책 테스트·공백 검사가 통과함.
5. 서버 기동·스케줄러·Compose·배포 workflow·서비스 코드 변경이 없음.
