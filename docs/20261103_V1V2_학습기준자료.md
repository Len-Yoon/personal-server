## 2. 먼저 잡을 전체 그림

**V1은 실제 서비스를 안전하게 운영하는 프로젝트이고, V2는 별도 환경에서 배포·관측·보안·복구를 연습하는 프로젝트입니다.** V2가 V1을 대체한 것은 아닙니다.

```text
V1: 사용자 요청 → Tunnel → Caddy → K3s 앱 → 서비스별 데이터
    운영 도구는 실행 주체·배포·관측·백업·복구를 관리

V2: 코드·이미지·Git 선언 → 수동 Argo Sync → 실습 앱
    지표·로그·trace·정책·별도 DB 복원을 연결해 검증
```

각 기술은 “이름이 무엇인가?”보다 “어떤 문제를 해결하며, 여기에서는 어디에 쓰이는가?”로 공부합니다.

## 6. 숫자와 경험을 읽는 기준

- 문서의 “질문 24개”는 학습 항목 수입니다. 사용자 숙련 점수나 테스트 수가 아닙니다.
- V2의 18개 Application·27개 관측 대상·143개 테스트는 각각 다른 개수이며, 해당 검증일의 기록입니다. 현재 실행 중이라는 뜻이 아닙니다.
- V1의 Portal 제한 롤링과 Book·YouTube·Crawler 단일 writer는 구분합니다.
- 에이전트 구현·자동 실행, 독립 검토, CI, 실제 운영 적용, 사용자 직접 수행은 서로 다른 근거입니다.
- 예시의 요청 ID `ABC`와 가상 수치는 이해를 돕기 위한 것입니다. 실제 Book 요청 ID는 UUID 형식이며 예시 문자열을 그대로 보내면 안 됩니다.
- 자료 저장은 새 배포·장애 주입·DB 복원을 수행했다는 뜻이 아닙니다. 현재 가동·직접 숙련은 별도 확인 필요입니다.

## 7. 학습 방법과 확인 필요 사항

한 주제를 읽고 답변을 가린 뒤 **문제 → 선택 → 동작 → 검증 → 한계**의 다섯 문장으로 설명해 보세요. 설명이 막히는 단어는 해당 장으로 돌아갑니다. 전체 스크립트를 외우는 대신 요청 하나·배포 하나·장애 하나를 끝까지 따라가는 것이 목표입니다.

확인할 것은 “읽었는가?”보다 “왜 그런지, 실패하면 무엇이 달라지는지 설명할 수 있는가?”입니다. 직접 실행 결과가 확인되기 전에는 학습 계획의 완료 상태를 갱신하지 않습니다.
