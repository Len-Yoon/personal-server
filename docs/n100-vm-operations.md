# N100 운영 구조와 재기동 기준

| 항목 | 내용 |
|---|---|
| 기준일 | 2026-11-24 |
| 대상 | 단일 N100의 Windows·Hyper-V Linux VM A/B·Portal 포함 앱 7개 |
| 기준 자료 | VM 기동 결과, 기존 기동 이력 대조, PostgreSQL 역할 검증, 외부 HTTPS 응답, Windows 서비스·예약 작업 조회 |
| 목적 | 현재 운영 상태와 다음 재부팅에 필요한 조건 공유 |

## 핵심 요약

공개 웹 요청은 Windows의 Cloudflare Tunnel과 Caddy를 거쳐 VM A의 앱에 도달함. VM A에만 DB 쓰기를 허용하고 VM B는 동기 복제를 받음. N100의 물리 호스트 장애와 재부팅 후 자동 복구는 별도 과제로 남아 있음.

## 현재 구성

[상세 운영 구조도](images/n100-vm-architecture.svg)에서 공개 요청, 쓰기 권한 확인, DB 복제 경로를 확인할 수 있음.

| 구성 요소 | 역할 | 마지막 확인 상태 |
|---|---|---|
| Windows · Hyper-V | VM A/B 실행 | 두 VM 실행 확인. 자동 시작 미설정 |
| Windows · Cloudflare Tunnel·Caddy | 공개 웹 요청 진입과 라우팅 | 실행 확인. 두 서비스 모두 수동 시작 |
| Windows · 쓰기 권한 서비스 | DB 권한 발급·연속성 확인 | 새 서비스 실행 확인. 수동 시작 |
| 격리 확인 서비스 | 후보 VM의 격리 상태 확인 | 운영 포트 974 연동 확인 |
| VM A | PostgreSQL 쓰기와 앱 7개, 내부 브로커 실행 | 앱 7개 준비, 브로커 실행, A 단일 쓰기 확인 |
| VM B | PostgreSQL 동기 대기 | B 동기 대기 확인 |
| 기존 WSL 작업 | 이전 실행 환경의 시작·유지 작업 | 서비스용 자동 시작·유지 작업 비활성, 실행 중인 WSL 프로세스 0개 확인 |

## 검증 결과

| 항목 | 확인한 결과 |
|---|---|
| 쓰기 전환 | A·B 쓰기 폐쇄 확인 후 A에만 권한 발급. B 동기 복제 확인 |
| 기록 인계 | 이전 종료·기동 기록을 보존하고 중단된 기동의 진행 기록을 검증해 재개 |
| 앱 기동 | Portal, 뉴스, 책, 영상, 차량관리, System Agent, HomeOps 실행기 모두 준비. 내부 브로커 별도 확인 |
| 공개 HTTPS | Portal 첫 화면 HTTP 200. Portal·뉴스·책·영상·차량 공개 health가 10초 간격 3회 모두 HTTP 200 |
| 권한 확인 지연 | 6초 제한을 유지하면서 같은 Windows 호출에서 읽기를 재확인. 실제 읽기 재확인 약 4.4~4.5초 |
| 코드 검증 | 운영 반입 기준 커밋 `da25bc3c`, 공식 검사 15개와 독립 검토 통과 |

## Windows 부팅 예약 작업

`N100HA-Start-VM-Guests`는 Windows 시작 45초 뒤 등록된 운영 VM 두 대만 B → A 순서로 시작함. 두 VM의 식별자와 설정을 먼저 대조하고, 실행 중인 VM은 그대로 사용함. 작업 등록에는 [예약 작업 스크립트](../infra/k8s/ha_control/windows-vm-boot-task.ps1), 부팅 시 실행에는 [VM 시작 스크립트](../infra/k8s/ha_control/windows-vm-boot.ps1)를 사용함.

예약 작업의 성공은 **VM 두 대 실행**을 뜻함. 현재 DB 권한 계획은 한 번의 부팅에 결합돼 있음. 재부팅 후 DB 권한과 앱을 자동 복구하려면 새 부팅 관측, 이전 종료·기동 기록 인계, A·B 쓰기 폐쇄 대조를 자동으로 처리하는 조정기가 필요함. Caddy·Tunnel과 Portal 응답 확인은 그 이후에 진행함.

## 재기동 시 확인 순서

1. 관리 창구에서 VM A/B와 복구에 필요한 Windows 서비스 상태를 확인함.
2. 이전 종료 기록, DB 복제 상태, 양쪽 쓰기 폐쇄를 확인함. 어느 한쪽의 상태를 확인할 수 없으면 권한 발급 단계에서 멈춤.
3. A에만 쓰기를 허용하고 B가 동기 대기로 돌아왔는지 검증함.
4. 기존 기록을 대조해 동일 범위의 앱 7개와 내부 브로커를 시작함. 중단된 요청은 실제 실행 상태와 기동 기록을 먼저 확인함.
5. Windows Caddy·Tunnel을 통한 Portal 첫 화면과 공개 health를 검증함.

## 확인 필요 사항

| 항목 | 완료 기준 |
|---|---|
| 전원 재기동 후 자동 복구 | 운영 Windows 재기동 뒤 VM A/B, A 단일 쓰기, B 동기 대기, 앱 7개, Portal을 순서대로 복구하고 증적 보존 |
| 장애 전환 | 실제 운영에서 VM 장애 뒤 복구 목표 시간과 데이터 손실 범위를 별도 계측 |
| 백업 복원 | VM 운영 데이터의 최신 백업을 격리 환경에서 복원해 응답과 데이터 확인 |

WSL 배포판과 기존 기동 작업을 정리하기 전에는 VM 경로의 재기동과 운영 데이터 복원을 먼저 확인함. [운영 로드맵](operations-roadmap.md)
