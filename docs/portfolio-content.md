# Personal Server V1 — 개인 서비스 운영과 데이터 보호

단일 N100에서 파일·책·영상·뉴스·차량 정보를 관리하는 서비스를 운영하는 프로젝트입니다. 기능 구현뿐 아니라 **실패가 사용자에게 어떻게 보이는지, 배포 중 데이터가 보존되는지, 백업으로 실제 복원할 수 있는지**에 초점을 두었습니다.

[저장소](https://github.com/Len-Yoon/personal-server) · [설계·검증 상세](https://github.com/Len-Yoon/personal-server/blob/main/docs/portfolio-devops.md)

## 프로젝트 개요

| 항목 | 내용 | 비고 |
|---|---|---|
| 기준일 | 2026-11-03 | 운영·검증 기록 대조 기준이며 실시간 상태 아님 |
| 환경 | Windows N100·Ubuntu WSL2·K3s·Docker Compose | 단일 물리 호스트 |
| 서비스 | Portal·파일함·News·Book·YouTube·차량관리·HomeOps | 기능별 API·데이터 책임 분리 |
| 핵심 기술 | Python·FastAPI·Jinja2·SQLite·GitHub Actions·Prometheus·Grafana·Cloudflare Tunnel·Caddy | 기술별 관리 범위는 저장소 참조 |
| 담당·지원 구분 | 요구사항·우선순위·변경 승인과 에이전트 지원 구현·자동 검증·독립 검토를 구분 | 본인 직접 작성·진단 범위를 확인해 설명 |

## 운영 구조와 선택 이유

| 설계 | 이유 | 비고 |
|---|---|---|
| K3s 웹 앱 + Compose 보조 서비스 | 앱의 Deployment·readiness·PVC 관리와 차량·호스트 보조 작업을 분리 | runtime marker와 실제 상태로 중복 실행 차단 |
| 서비스별 SQLite·파일 | 개인 데이터 규모에 맞춰 운영 부담과 데이터 책임을 제한 | Book·YouTube·Crawler 단일 writer, Portal은 별도 검증한 제한 롤링 |
| Tunnel → Caddy → K3s | 공개 요청과 내부 실행 위치를 연결 | 차량 OAuth callback은 별도 Tunnel 경로 |
| 제한 배포·외부 health | 코드 검사·이미지 공급·운영 적용·사용자 접근을 별도 확인 | main 병합이 모든 앱 자동배포를 뜻하지 않음 |

## 문제 해결 사례

| 문제 | 적용한 방식 | 검증·한계 |
|---|---|---|
| 일부 검색 서비스 지연·실패 | 병렬 조회·서비스별 상태·1.5초 조회 예산 | 실패한 대상과 정상 0건을 구분, 전체 브라우저 응답 보장 아님 |
| 동시 업로드·재시도·편집 충돌 | 배타적 파일 생성, 요청 ID/본문 해시/결과의 트랜잭션, 버전 검사 | 지정 경로의 중복 저장·덮어쓰기 방지 |
| 수집기는 멈췄지만 화면은 정상 | 마지막 성공 수집·시도·연속 실패·최신성 분리 | HTTP 200과 업무 최신성 구분 |
| 백업 존재와 복구 가능성 불일치 | 암호화 원격 사본 재다운로드·무결성·격리 복원·증거 만료 검사 | 업로드 성공만으로 복원 성공 판정하지 않음 |
| Grafana 결측·업그레이드 보존 | 실제 지표·필터·질의와 Helm 저장 manifest/live 대조 | WSL CPU·메모리, 결측 안내와 revision 7 보존을 검증 |

## 검증 결과와 현재 한계

2026-10-19 전체 다섯 단계 정기 백업·복원과 네 앱의 원격 사본 자동 삭제를 확인했습니다. Portal은 승인된 롤링 교체·온라인 백업 중 조회·저장·수정과 데이터 보존을 검증했고, 합성 경보 시험은 발생·복구 메시지의 단말 수신을 확인했습니다. 11월 2일에는 모니터링 Helm 업그레이드 후 대시보드 변경 보존을 확인했습니다. 11월 3일 뉴스 원시 관측 보존 확장을 적용했으나 새 형식 자연 실행·동일 기준 30일 SLO는 후속 확인 대상입니다.

별도 Linux VM·디스크 소실 후 합성 Book을 새 VM에 복원하는 실습도 완료했습니다. 이는 에이전트 지원 자동 실습이며 실제 운영 N100·물리 호스트·전체 서비스의 재해복구 결과와 구분합니다.

단일 호스트의 물리 HA, 전체 운영 RTO/RPO, 장기 SLO 달성은 주장하지 않습니다. 사용자 직접 실습과 에이전트 자동 실행·CI·독립 검토를 구분해 기록합니다.

## V2와의 관계

[V2](https://github.com/Len-Yoon/personal-server-v2)는 Mac의 별도 Kubernetes·GitOps 실습 프로젝트입니다. V1 일부 고정 소스를 재사용해 Argo 수동 Sync, 지표·로그·trace, 보안 정책과 별도 PostgreSQL 복원을 검증합니다. V1 운영 데이터 이전이나 전체 운영 전환은 아닙니다.

이 파일은 공개 포트폴리오용 원문입니다. 저장소 변경만으로 공개 페이지가 갱신되지는 않으며, 관리자 편집 화면에서 별도로 저장해야 반영됩니다. 이번 문서 갱신에서는 공개 페이지 저장·운영 배포를 수행하지 않습니다.
