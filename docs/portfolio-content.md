# Personal Server

개인 생산성과 홈 서버 운영에 필요한 기능을 하나의 웹 플랫폼으로 통합한 개인 프로젝트입니다. Windows N100과 WSL2 환경에서 Docker Compose 기반으로 운영하며, 포털·파일함·운영 현황·뉴스·메모·공개 포트폴리오를 서비스별 책임으로 분리했습니다.

저장소: [GitHub 저장소](https://github.com/Len-Yoon/personal-server)

## 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 개발 기간 | 2026년 7월~현재 |
| 담당 역할 | 문제 정의, 기능 우선순위, 보안 정책, 운영 구조, 배포 기준 및 최종 변경 판단 |
| 핵심 기술 | Python, FastAPI, Jinja2, SQLite, Docker Compose, Cloudflare, GitHub Actions, Windows/WSL2 |

## 구현 내용

### 개인 서비스 통합 포털

- 파일함, 관리자 상태, 뉴스 허브, YouTube 메모, 책 메모를 단일 포털에서 연결하고 통합 검색을 제공했습니다.
- 공개 포트폴리오는 별도 호스트에서 제공하고, Markdown 기반 관리자 편집 기능을 분리했습니다.

### 시장 뉴스 수집과 중요 알림

- Investing.com RSS와 Google News RSS를 수집·보관하는 뉴스 허브를 구현했습니다.
- 나스닥 관련성과 시장 충격 여부를 분류해, 확정된 중요 기사만 Telegram으로 알림 처리했습니다.
- 전망성 금리 기사가 즉시 알림으로 분류되지 않도록 재현 테스트를 작성했습니다.

### 서버 상태와 HomeOps 운영 보조

- Windows host가 기록한 실제 수집 시각을 기준으로 CPU·메모리·디스크·백업·컨테이너 상태를 표시했습니다.
- Compose 서비스만 대상으로 제한된 진단과 재시작을 허용하고, health 검증·쿨다운·시간당 실행 한도·SQLite 이력을 적용했습니다.

### 보안과 배포

- 관리자·파일함·메모 쓰기·포트폴리오 편집을 역할별 세션 인증으로 분리했습니다.
- Origin 검증, HTTP-only·SameSite 쿠키, CSP 및 보안 헤더, 영속형 인증 실패 제한을 적용했습니다.
- `main` 브랜치의 CI 성공 시에만 Windows self-hosted runner가 N100 배포와 서비스 health 확인을 실행하도록 구성했습니다.

## 문제 해결 사례

### 뉴스 알림의 정확도 개선

시장에 영향을 줄 가능성이 낮은 기사까지 즉시 알림이 되는 문제를 줄이기 위해, RSS 수집·관련성 분류·알림 단계를 분리했습니다. 확정된 시장 충격 기사는 Telegram으로 발송하고, 전망성 기사는 보관함에서 확인하도록 정책을 구현했습니다.

### 상태 정보의 기준 시각 명확화

화면을 연 시각이 아닌 Windows host의 실제 수집 시각을 상태 판단 기준으로 사용했습니다. 오래된 상태 데이터는 별도 상태로 표시해, 사용자에게 현재 상태와 수집 시점을 혼동하지 않도록 했습니다.

### 공개 쓰기 기능의 보안 경계 설정

읽기 공개와 쓰기 권한을 분리하고, 세션 인증과 Origin 검증을 적용했습니다. 인증 실패 제한은 상태 파일과 파일 잠금을 사용해 재시작 후에도 유지되도록 구현했습니다.

## 검증

- 포털·뉴스·HomeOps·메모·Compose·운영 스크립트에 대한 서비스별 단위 테스트를 구성했습니다.
- 파일함과 포트폴리오의 인증·세션·교차 출처 요청 차단을 테스트했습니다.
- GitHub Actions CI와 N100 배포 후 health check를 배포 게이트로 사용합니다.
