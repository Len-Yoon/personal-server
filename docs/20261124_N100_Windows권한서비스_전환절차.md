# N100 Windows 쓰기 권한 서비스 전환 절차

| 항목 | 내용 |
|---|---|
| 대상 | Windows의 구버전 쓰기 권한 서비스와 VM A의 격리 확인 서비스 |
| 목적 | PostgreSQL 단일 쓰기와 기존 앱 기동 기록을 보존하면서 새 버전으로 전환 |
| 완료 기준 | VM 앱 7개 준비 완료 및 Portal 외부 접속 성공 |

## 준비

| 확인 항목 | 통과 조건 |
|---|---|
| 이전 서비스 | Windows 현재 부팅, 서비스 계정, 프로세스 시작 시각, 이전 실행 파일과 계획의 해시를 확인함 |
| VM A | 앱 7개와 브로커가 모두 정지했고 시작 시각 변경이 마지막 기동 기록과 일치함 |
| 확인 서비스 | 공급자 격리 확인, 기동 확인, Windows 레거시 차단 확인의 실행 주체가 서로 다름 |
| 새 서비스 | 승인된 Windows 실행 파일, 새 설치 경로, VM 패키지 및 기존 격리 확인 포트 설정을 별도로 검증함 |
| 실패 시 복구 | 이전 실행 파일과 인자를 보존하며, 새 격리 확인 서비스가 실패하면 같은 포트에 기존 격리 서비스만 복원할 수 있음 |

## 전환

| 단계 | 작업 및 통과 조건 |
|---|---|
| 권한 반납 | 정상 종료 요청을 지원하면 전용 요청을 보냄. 구버전은 준비 목록을 모두 통과한 뒤 교체 대상 격리 확인 서비스만 중지함. 구버전 권한 프로세스가 자체적으로 종료하고 보호된 종료 기록을 남겼는지 확인함. |
| DB 확인 | 인증된 읽기 전용 세션으로 A·B 양쪽의 정확한 다음 revision, 같은 만료 시각, 쓰기 닫힘, 동기 복제 및 재생 위치, 외부 요청 격리 기록을 확인함. |
| 격리 확인 교체 | 기존 포트의 이전 프로세스 종료와 새 포트 소유자를 대조함. 새 관측기가 보호된 계획에 연결된 새 요청에 응답해야 통과함. |
| 기동 기록 인계 | 이전 계획과 최신 기동 요청·승인·진행 기록을 대조해 별도 인계 기록을 발급함. 새 계획에 인계 기록 해시를 고정하고 원본 정지와 기동 기록을 보존함. |
| 실행 파일 전환 | 실제 A·B 닫힘을 다시 확인함. 이전 서비스가 정지 및 사용 안 함 상태일 때 ArmPostbootHost로 이전 상태를 봉인하고 새 Windows 경로를 지정함. 이 단계의 Windows 권한 서비스는 정지 상태임. |
| 앱 기동 | A·B 닫힘을 재확인한 뒤 새 권한 서비스를 시작함. A만 쓰기 가능하고 B가 동기 복제를 유지하는지 확인함. 새 서비스 인스턴스로 승인하고 앱 7개의 준비 완료를 실제 VM에서 확인함. |
| 외부 확인 | Portal 첫 화면 HTTP 200과 10초 간격 상태 확인 세 번 HTTP 200을 확인함. |

구버전에서 실제 반납이 성공해도 종료 기록에 lease_lost가 남을 수 있음. 실제 반납 검증에는 양쪽 DB 확인을 함께 사용함. 만료 시각만 확인됐거나 DB revision이 일치하지 않으면 전환을 보류함.

변경 명령의 응답이 끊기면 서비스·포트·경로·기록의 실제 상태를 먼저 읽음. 이전 기록의 덮어쓰기와 중복 기동을 방지하기 위해 적용 여부가 확인될 때까지 같은 요청을 다시 보내지 않음.

## 기동 이력 인계 실행

VM A의 검증된 설치본에서 root가 인계 전용 명령을 실행함. 요청 두 건, 이전 계획, 최신 이력은 각각 별도의 소유자 전용 읽기 파일과 SHA-256으로 고정함.

```sh
python3 -m ha_control.native_guest_postboot \
  --request "$DRAFT_REQUEST" --request-sha256 "$DRAFT_REQUEST_SHA256" \
  --predecessor-request "$PRIOR_REQUEST" --predecessor-request-sha256 "$PRIOR_REQUEST_SHA256" \
  --predecessor-plan "$PRIOR_PLAN" --predecessor-plan-sha256 "$PRIOR_PLAN_SHA256" \
  --history "$PRIOR_HISTORY" --history-sha256 "$PRIOR_HISTORY_SHA256"
```

인계 승인 값은 새 기동 확인 서비스와 최종 서비스 계획 양쪽에 동일하게 고정함. 이전 정지 기록과 기존 기동 시도의 해시를 유지함. 명령 출력에는 발급 결과와 인계 해시만 포함함.

초안 요청의 `postboot_plan_sha256`, `postboot.predecessor_seal_sha256`, `postboot.carryover_receipt_sha256`에는 인계 발급 전 값을 나타내는 64자리 0을 사용함. 실제 인계 해시를 발급받은 뒤 폐쇄 증명과 봉인, 최종 계획에 실제 해시를 고정함.

## 전환 단계와 결과 기록

전환 조정기는 소유자 전용 디렉터리에 단계별 요청과 관측 결과를 각각 보존함. `status`로 다음 단계와 읽기 전용 대조 필요 여부를 확인함. `step`은 한 단계만 요청함. 응답이 불명확하면 `observe`로 그 요청의 실제 결과를 확인함.

```sh
python3 -m ha_control.sameboot_transition status --journal "$JOURNAL" \
  --scope "$SCOPE" --scope-sha256 "$SCOPE_SHA256"
```

| 항목 | 적용 조건 |
|---|---|
| 운영 실행기 | `step` 및 `observe`에 전달할 실행기 파일의 SHA-256을 전환 범위에 고정함. 대상 Windows·VM의 인증된 상태를 확인하고, 이미 발급된 요청은 읽기 전용으로 대조해야 함. |
| 권한 반납 | 구버전의 격리 확인 서비스만 중지할 대상임을 확인함. Windows 구버전이 스스로 남긴 종료 기록을 대조한 뒤 그 인스턴스가 정지 및 사용 안 함으로 조회되어야 함. |
| 새 권한 준비 | A·B 쓰기 폐쇄 확인의 해시, 이전 종료 기록, 인계 기록, 새 이미지·계획의 해시가 모두 연결된 Windows 입력을 검증한 뒤에만 새 서비스 경로를 지정함. |
| 격리 확인 실패 | 새 관측기가 준비되지 않았음이 확인되면 기존 관측기 복귀 단계만 진행함. 복귀 결과는 관측기 복구로 기록하고 DB 권한 발급과 앱 시작은 차단함. |
| 완료 | VM A 단일 쓰기, VM B 동기 복제, 앱 7개 및 브로커 준비 완료를 확인함. Portal은 공개 주소에 직접 접속해 첫 화면과 10초 간격 상태 확인 3회가 모두 HTTP 200이어야 함. |

조정기를 운영에 사용하기 전에 해당 서버의 권한 반납, 폐쇄 확인, 관측기 교체·복귀, Windows 런타임 설치, 서비스 시작과 앱 승인 명령을 인증된 운영 실행기로 연결하고 독립 검토함. 조정기 테스트나 임시 포트 리허설은 실제 운영 전환 기록으로 사용하지 않음.

실행기 인터페이스는 `guard`, `apply`, `observe`, `arm_material`을 제공함. `guard`는 변경 전의 실제 상태를 인증하고, `observe`는 발급 기록에 고정된 같은 요청을 읽기 전용으로 대조함. `arm_material`은 검증할 네이티브 계획과 봉인 원본을 반환함. 상세 입력과 출력은 [전환 조정기](../infra/k8s/ha_control/sameboot_transition.py)의 단계별 계약을 참조함.
