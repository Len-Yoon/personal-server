# N100 전체 서비스 이중화 구현 기록

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-11-06, Asia/Seoul |
| 목적 | 실제 7개 앱의 데이터·역할 계약을 먼저 구현하고 AS 후 AA를 검증함 |
| 기준 | 사용자 인계 설계 및 최신 자원 재계획, 현재 저장소 소스 |
| 현재 상태 | 맥 로컬 보호쓰기·역할 admission 계약 및 격리 PG 시험 도구 구현·자기 검증 완료. 앱 연결 전 단계임 |
| 운영 적용 | 미수행. VM·PG·앱·bootstrap·scheduler·ingress·Secret 변경 없음 |

## 핵심 요약

첫 구현은 [보호쓰기·역할 계약](../infra/k8s/tools/n100_ha_contract.py)과 [장애 경계 검사](../tests/test_n100_ha_contract.py)임. 실제 7개 앱을 이 계약에 연결하거나 DB를 이전한 상태가 아님. 전달받은 관측값의 허용 여부를 판단하며, PostgreSQL 증거 수집·프로세스 차단·승격 명령은 수행하지 않음.

성공 응답·동일 요청 재시도·외부 작업 모두 현재 역할 세대와 복제 보호 증거를 확인해야 함. 앱 역할과 DB 역할을 분리하며, B에서 앱을 제공하면서 정상 DB A를 유지할 수 있음. 동기 상대 소실 시 새 보호쓰기 성공을 제한하는 정책을 보존함.

서비스별 Dockerfile과 안전배포 archive는 각 서비스 디렉터리만 포함함. 현재 도구 파일은 운영 이미지에 들어가지 않음. 후속 앱 연결 시 패키징·실제 이미지 포함·독립 검토가 필요함. 현재 검사는 실제 앱 HA 통합 검사가 아님.

## 구현된 계약

| 경계 | 구현 내용 | 비고 |
|---|---|---|
| 요청 식별 | 서비스·요청 ID·operation·payload/result SHA256·관리 대상 노드를 양 DB 원장과 대조함 | canonical payload·응답 해시는 adapter가 실제 bytes 기준으로 생성해야 함 |
| 역할 세대 | cluster·epoch·revision·primary·partner·timeline 및 전후 권한 snapshot 동일성 확인 | 입력 인증·권한 발급·락·재시작 방지는 미구현임 |
| 관측 신선도 | 검증 시도 nonce 일치, 같은 verifier의 monotonic 시간, 권한 발급 이후 관측 확인 | 로컬 계약 상한: 권한5초·관측2초. 운영 수용값 아님. verifier 재시작 후 timestamp 재사용 금지 |
| 복제 보호 | 정확한 동기 상대, 양 DB 역할·내구성 설정, 현재 source timeline, 보호된 WAL watermark 및 flush/replay 확인 | 실제 관측·설정 이력·fencing은 adapter 구현 및 시험 필요 |
| 재시도 | 기존 원장 행·driver 반환만으로 성공 허용하지 않음 | 모호한 commit은 새 시도의 보호증명으로 판정함 |
| 외부 작업 | 동일 보호 검사 후 worker 단일 소유 및 명시 대상 노드 바인딩 확인 | 실행 중 세대 lock, provider 멱등성·응답 유실 확인은 미구현임 |
| 제공 역할 | 4개 Web/API는 AS/AA 역할 확인, 노드 관리 조회는 명시 대상 확인 | serving 허용은 DB 쓰기·외부 작업 허용이 아님 |
| 쓰기 제한 | 쓰기 닫힘 상태에서 보호쓰기·외부 작업 거절, 유효 읽기 역할 유지 | 각 앱의 실제 읽기/쓰기 분류·응답 변환은 미연결임 |

후속 PostgreSQL adapter는 인증된 직접 연결과 제한 권한으로 실제 데이터를 읽어야 함. 정확히 commit된 요청 결과를 읽은 **뒤** 해당 commit을 덮는 WAL insert/end watermark 또는 새 WAL-producing barrier를 확보하고, 동일 검증 시도에서 지정 상대의 flush/replay와 결과 바인딩을 확인해야 함. 단순 현재 flush 값은 불충분함. 권한 snapshot은 실제 단일 제어 락과 연결해야 함. 임의 JSON·앱 self-report·TCP health를 보호 증명으로 간주하면 안 됨.

현재 모듈은 stateless임. adapter가 매 검증마다 예측 불가 nonce를 새로 생성해야 하며, 동일 nonce·proof의 반복 호출을 이 모듈 자체가 소비·차단하지 않음. 보호결과 판정은 외부 작업의 exactly-once 보장이 아님.

기준은 [PostgreSQL 동기복제](https://www.postgresql.org/docs/current/warm-standby.html#SYNCHRONOUS-REPLICATION), [복제 통계](https://www.postgresql.org/docs/current/monitoring-stats.html#MONITORING-PG-STAT-REPLICATION-VIEW), [WAL 내구성 설정](https://www.postgresql.org/docs/current/runtime-config-wal.html)임. commit 대기 취소·WARNING 이후 로컬 행이 보이는 경우도 새 보호증명을 요구함.

주 담당(현재 Codex 세션)이 구현·자기 검증을 수행함. `gpt-6.1-sol` 높은 추론 전문 검토자는 소스·원본·격리 증거 대조와 보조 검사66개를 수행했고 파일 수정 없음. 엄격 작성 이력 검증에서 테스트 실행도 잠재 작성자로 분류하므로, 별도 `gpt-6.1-sol` 높은 추론 최종 검토자가 실제 diff·원본 검사 로그를 읽기 전용으로 대조함. 최종 검토자는 파일 수정·테스트 실행·운영 접근 없음. DB·외부 부작용·운영 보호 위험 및 독립성 증거 분리를 위해 주 담당 포함3명으로 수행함. 파일 동시 수정 없음.

격리 시험은 [PG 시험 도구](../infra/k8s/tools/n100_ha_pg_lab.py)를 맥에서 명시 실행함. 기존 `postgres:17-bookworm`의 실행 image ID는 `sha256:8942ba4a60918c2b98bcad5c842453a765898854a9fec87f64ec816bf44559be`였음. 도구는 매번 로컬 이미지 ID를 기록하며 태그를 운영 버전 고정으로 간주하지 않음. `orbstack` 로컬 socket을 매 명령에 고정하고 UUID label·정확 ID로 소유권을 검증함. 외부 포트·호스트 데이터 마운트·실제 자격 증명 없이 internal network·일회용 tmpfs만 사용함. 생성 응답 유실 시 재생성하지 않고 소유 label 조회 후 정리함. 이 도구는 상시 실행·운영 배포 도구가 아님.

## 후속 조치

같은 실제7앱 범위에서 PG 관측 adapter·취소/재시도 시험, 서비스별 상태 이전·역할 가드·패키징을 구현함. 전체 데이터·ID·파일 정합과 복원을 검증하고 Windows 제어·네트워크·VM 실측을 준비함. 운영 전환 직전 대상 커밋·허용 동작·보호 대상·실행 순서·중단 기준을 구체화해 별도 승인 기준을 적용함. 현재 개발 시작 승인을 운영 배포나 새 재부팅 승인으로 확대하지 않음.
