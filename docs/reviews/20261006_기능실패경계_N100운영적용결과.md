## 3. 상세 내용

### 3.1 변경 내용과 운영 경계

| 대상 | 보완 내용 | 운영 검증·비고 |

| Portal | 파일 삭제 부분 결과·ZIP 404·숨김 이름 차단·포트폴리오 로그인 초안·HomeOps 관리 집합 검사 | K3s 단일 writer, 이미지 외 Deployment spec 불변 확인 |
| Book·YouTube | 형제 폼 초안 보존·요청 ID 기반 재시도·편집 버전 충돌·Book 검색 전체 장애 구분 | 추가형 version·write_requests 초기화, 기존 행·본문·태그 보존 확인 |
| Crawler | 실제 RSS 실패·archive 갱신 실패를 오류로 전달하고 이전 수집·만료·알림 상태 보존 | 기존 archive 스키마·writer·백업 상태 유지 |
| 차량 | 토큰 갱신 실패 안내·unknown 경고·잘못된 OAuth state 보존 | 기존 worker 1개 및 DB unknown_warnings_json 추가형 초기화 |
| HomeOps 실행기 | 인증된 실제 관리 집합과 같은 snapshot의 진단 목록 전달 | 기존 관리 대상 3개·socket proxy·bridge 연결·권한 상한 유지. Portal·실행기 양측 인증값 미설정으로 실제 연동은 미검증 |

지정된 쓰기 경로에만 멱등성 기록을 적용함. 기존 등록 클라이언트의 요청 ID 누락은 호환되며 모든 쓰기의 exactly-once를 보장하지 않음. version이 없는 구 편집 폼은 409로 차단될 수 있어 새로고침 후 최신 원본을 확인해야 함. sessionStorage는 같은 탭의 임시 보관이며 탭 종료 후 복구를 보장하지 않음.

### 3.2 배포 전 DB 복원점

| 대상 | 방법·보존 위치 범주 | 검증 | 비고 |
|---|---|---|---|
| Book | 기존 PVC 내부 소유자 전용 신규 백업 | quick_check=ok, 원본 컬럼·행 수·내용 해시 기록, 파일 0600 | WAL 파일의 단순 복사가 아닌 SQLite backup API 사용 |
| YouTube | Book와 동일 | quick_check=ok, 원본 컬럼·행 수·내용 해시 기록, 파일 0600 | 기존 글·태그·영상 보존 기준 |
| 차량 | 기존 tmpfs에서 coherent snapshot 생성 후 WSL 접근 제한 저장소에 보존 | 전달 전후 SHA-256·WSL 복사본 quick_check=ok, 파일 0600 | Windows bind의 기존 권한을 변경하지 않음. OAuth/인증 파일은 복제하지 않음 |

Book·YouTube 백업 디렉터리는 소유자 접근 0700이며 기존 fsGroup의 setgid 상속(2700)을 허용함. 다른 사용자 접근 허용이나 기존 PVC chmod/chown은 수행하지 않음. 신규 파일을 덮어쓰지 않으며 완료된 백업은 해시·정합성 재확인 후 재사용함. 이 로컬 복원점 검사는 원격 암호화 백업·재해 복구 전체 재검증을 뜻하지 않음.

Book·YouTube의 추가형 DB 초기화는 재시작이 아닌 목록 조회 시 수행됨. 공개 홈 HTTP 200 확인 뒤 version·write_requests와 기존 컬럼 기준 전체 행 해시를 대조함. Windows 체크아웃의 줄바꿈과 이미지 원본을 혼동하지 않도록 실행 코드 해시는 `git show <커밋>:<경로>`의 원본 바이트로 비교함.

### 3.4 중단·원복과 원인 조치

| 관측 | 원인·조치 | 비고 |
|---|---|---|
| Docker 반입 후 ID 비교 차이 | 실제 N100 manifest/config 연결과 원본 바이트·레이어를 대조함 | 서비스 교체 전 중단. 검사 완화가 아닌 식별자 계약 확인 |
| Book 백업 디렉터리 검사 차이 | PVC의 setgid 상속을 확인하고 owner-only 700/2700·UID/GID 조건 유지 | 기존 권한 변경 없음 |
| 차량 백업 제한 권한 미적용 | Windows bind 대신 기존 tmpfs와 WSL 접근 제한 저장소 사용 | 운영 DB·OAuth 파일 권한 변경 없음 |
| HomeOps 새 컨테이너 시작 실패 | bridge 주소 변수 누락으로 기존 바인딩과 달라짐. 정상 기존 연결 정보를 메모리에서 사용하고 목표 HostConfig와 원본 해시 대조 | 다른 서비스 교체 전 중단. 주소·비밀값은 파일·문서·로그에 저장하지 않음 |
| HomeOps 원본 설정 해시 비교 실패 | 의미가 없는 Env·Mounts 배열 순서를 실제 변경과 혼동함. 직전 이미지로 원복해 healthy 확인 후 실제 환경 값·이미지 기본값·원본 mount 값 대조 및 순서 정규화 | 원복 1회 사용. 환경 이름 중복은 차단하고 원본 before 증적은 유지함 |
| 차량 교체 중 공개 health 502 | 컨테이너 교체 중 일시적으로 관측함. 이후 healthy와 최종 3회 HTTP 200 확인 | 장애 지속 시간은 측정하지 않음. 무중단 배포로 표현하지 않음 |
| HomeOps 연동 검사 차단 | Portal의 기존 환경과 참조 Secret에 실행기 인증 key 없음. 실행기도 공유 인증값 미설정 | 환경 값·Secret 전후 불변으로 기존 설정 누락 확인. Secret 신규 등록·임의 주입은 미수행 |

K3s는 기존 검증 도구의 읽기 전용 check 후 UID·resourceVersion·기존 이미지 조건부 JSON Patch로 이미지 필드만 교체함. YouTube에는 동일 조건부 절차를 직접 적용함. Compose는 기존 파일·관리 범위와 이미지 전용 override를 사용하고 대상만 `--no-build --no-deps`로 교체함. 전역 백업 잠금·활성 Job 없음·단일 writer를 매 단계 확인함. 이미지 원복에 DB 백업 덮어쓰기는 포함하지 않음.

## 5. 확인 필요 사항

- Portal·실행기 양측에 공유 인증값을 안전하게 구성하는 별도 승인이 필요함. 실제 관리 집합 header와 진단 연동은 그 후 읽기 전용으로 검증해야 함. Secret 변경을 이번 일반 앱 배포 승인으로 확대하지 않음.
- 실제 사용자 계정의 세션 만료 후 재로그인·메모 저장·운영 데이터 삭제 시험은 미수행함. 관련 UX는 격리 브라우저에서 검증함.
- 현대 API의 실제 오류·OAuth 실패·Telegram 최종 수신 재현은 미수행함. 다음 정상 운영 관측과 기존 감시로 확인함.
- 차량 토큰 파일 자체의 읽기 오류·JSON 손상 감지 확대, 요청 기록의 자동 만료는 이번 수정 범위 밖임. 운영 손상이 있다는 증거는 없음.
- 로컬 DB 복원점은 동일 호스트 자산임. 원격 암호화 백업과 호스트 전체 재해 대비를 대체하지 않음.

## 6. 후속 조치

승인된 6개 이미지 적용은 완료·소진된 승인 이력에 기록함. 문서는 후속 PR·main CI로 반영하며 운영 이미지 소스 `8889dc5`와 문서 커밋을 구분함. HomeOps 인증 연결은 승인 밖 후속 판단 대상임. 이미지·DB 복원점은 보존하고, 새로운 쓰기가 발생한 DB를 과거 백업으로 자동 덮어쓰지 않음. 기존 자동화 일정·보호 자원은 유지함.

잔여 경계: Docker 일반 restart는 인증 환경을 유지하지만, 기존 bootstrap·일반 Compose 재생성은 Secret의 키를 자동 재공급하지 않음. 해당 경로의 자동 연동은 이번 승인에서 제외했으며 별도 승인 필요함. 재생성 이후에는 [읽기 전용 확인·제한 구성](../operations-reference.md#homeops-공유-인증-확인제한-구성)을 사용함.
