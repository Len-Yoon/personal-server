### 3.3. 외부 응답 및 실행 근거

읽기 조사·기능 영향 없는 문서 기록이므로 주 담당 1명이 작성·자기 검수함. 하위 에이전트 및 새 독립 검토는 미사용이며 독립 검토 완료로 표현하지 않음. 코드·테스트·CI·배포 절차·설정은 수정하지 않음. 문서 계약 검사·PR/CI·병합 결과는 해당 PR 기록으로 구분함.

## 5. 확인 필요 사항

- 과거 공개 probe 실패 8일 각각의 HTTP 원인 및 당시 외부 관측 연속성은 확인 필요함.
- 10/26 백업 완료 Job이 현재 보존 목록에 없어 당시 실행 성공의 새 직접 대조는 확인 필요함. 10/27 성공을 전날 성공 증거로 대신하지 않음.
- 계획 정지를 SLO에 포함하는 정책·동일 기준의 30일 원시 자료·시간 기반 에러 버짓은 확인 필요함. 이번 점검으로 정책·retention을 바꾸지 않음.
- 사용자 직접 1주차 요청 추적·설명·진단 완료는 확인 필요함. 에이전트 점검으로 주차를 진급하지 않음.

## 6. 후속 조치

[SLI·SLO 기준](../slo-baseline.md)의 기존 집계·수집을 유지함. 당시 probe 보완 뒤 22일 정기 성공과 신규 freshness 기준 7일 정기 성공을 확인했으므로 이미 해결한 수집 경계를 다시 구현하지 않음. 다음 점검은 기존 자연 실행에서 동일 기준의 증적 누적과 새로운 실패·누락 유무를 확인하는 것임. 새 실패가 발생하면 해당 평가 구간·실행 출처부터 조사함. 30일 일일 판정의 0%를 가동률로 표시하거나 정상 서비스를 재시작하지 않음. 새 기능·계측·운영 변경은 확인된 결함과 범위를 기준으로 별도 진행함.
