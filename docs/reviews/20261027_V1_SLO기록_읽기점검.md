### 3.2. 최신 Portal failed 재구성

최신 행은 10/27 02:15:02 KST 수집이며 평가 구간은 10/26 02:15:02~10/27 02:15:02임. 그 시각에 고정한 Prometheus range query를 15초 간격으로 실행함. available/desired 각각 1개 시계열·5,761개 평가 표본을 확인함. 표본 시각은 질의 평가 시각이며 원본 scrape 시각이나 정확한 장애 시작·종료 시각이 아님.

| 평가 표본 시각 KST | available | desired | 대조 근거·해석 | 비고 |
|---|---:|---:|---|---|
| 10/26 02:30:47·02:31:02 | 0 | 0 | 기존 02:30 백업 일정·scale 0 절차와 일치하는 관측 | 당시 완료 Job은 현재 목록에 없어 실행 성공과 직접 연결은 확인 필요 |
| 10/26 17:24:17·17:24:32 | 0 | 1 | [업로드 안전성 운영 적용](20261026_Portal업로드안전성_운영적용결과.md)의 17:24 Portal 교체와 시각 일치 | replica 1·Recreate 배포의 교체 구간과 정합적임 |

available 0은 총 4평가 표본, desired 0은 그중 2표본임. 이를 60초 또는 30초의 정확한 서비스 중단 시간으로 환산하지 않음. 과거 30일 Portal failed 모두를 백업 때문이라고 일반화하지 않음. 최신 남아 있는 백업 Job 성공은 해당 실행 완료 근거이며 별도의 아카이브 다운로드·전체 복원 시험을 새로 수행한 근거가 아님.

### 3.3. 외부 응답 및 실행 근거

10/27 09:14:58·09:15:08·09:15:18 KST 시스템 curl의 TLS 검증을 유지한 공개 health 조회 3회 모두 HTTP 성공·JSON status=ok를 확인함. 최초 제한 환경의 이름 조회 실패와 네트워크 허용 후 로컬 Python 인증서 검증 실패는 서비스 HTTP 실패로 합산하지 않음. 별도 curl 상태 코드 조회는 HTTP 200임. 인증서 검증 우회·로컬 인증서 설정 변경은 하지 않음.

| 구분 | 실행·증거 | 비고 |
|---|---|---|
| 운영 읽기 | 기존 SSH 연결에서 ConfigMap GET·Deployment GET·Job LIST·Prometheus query_range GET | 리소스·설정·일정·운영 데이터 변경 없음 |
| 자기 검증 | 기존 validator·summary 함수로 30행과 날짜·기준 버전 대조 | 원본 재작성 없음 |
| 로컬 재현 자료 | `/tmp/v1-slo-readonly-20261027/records.json`, `summary.json`, `detail.json` | 임시 경로이며 장기 보존 보장 없음 |
| 외부 점검 도구 오류 | 로컬 Python `SSLCertVerificationError`, 시스템 curl은 성공 | 서비스 장애로 분류하지 않음 |
| 원격 접근 초기 오류 | 제한 환경의 호스트 이름 조회 실패 후 허용된 네트워크 접근으로 조회 성공 | N100 장애·수집기 실패로 기록하지 않음 |

## 4. 검토 결과

읽기 조사·기능 영향 없는 문서 기록이므로 주 담당 1명이 작성·자기 검수함. 하위 에이전트 및 새 독립 검토는 미사용이며 독립 검토 완료로 표현하지 않음. 코드·테스트·CI·배포 절차·설정은 수정하지 않음. 문서 계약 검사·PR/CI·병합 결과는 해당 PR 기록으로 구분함.

## 5. 확인 필요 사항

- 과거 공개 probe 실패 8일 각각의 HTTP 원인 및 당시 외부 관측 연속성은 확인 필요함.
- 10/26 백업 완료 Job이 현재 보존 목록에 없어 당시 실행 성공의 새 직접 대조는 확인 필요함. 10/27 성공을 전날 성공 증거로 대신하지 않음.
- 계획 정지를 SLO에 포함하는 정책·동일 기준의 30일 원시 자료·시간 기반 에러 버짓은 확인 필요함. 이번 점검으로 정책·retention을 바꾸지 않음.
- 사용자 직접 1주차 요청 추적·설명·진단 완료는 확인 필요함. 에이전트 점검으로 주차를 진급하지 않음.

## 6. 후속 조치

[SLI·SLO 기준](../slo-baseline.md)의 기존 집계·수집을 유지함. 당시 probe 보완 뒤 22일 정기 성공과 신규 freshness 기준 7일 정기 성공을 확인했으므로 이미 해결한 수집 경계를 다시 구현하지 않음. 다음 점검은 기존 자연 실행에서 동일 기준의 증적 누적과 새로운 실패·누락 유무를 확인하는 것임. 새 실패가 발생하면 해당 평가 구간·실행 출처부터 조사함. 30일 일일 판정의 0%를 가동률로 표시하거나 정상 서비스를 재시작하지 않음. 새 기능·계측·운영 변경은 확인된 결함과 범위를 기준으로 별도 진행함. [직접 학습 계획](../20261026_V1_고도화학습계획.md)은 첫 미완료 과제를 유지함.
