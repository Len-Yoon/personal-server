# 서비스별 PVC 원격 백업 보존 정책 설계 및 검증

## 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-09-27 | Asia/Seoul 기준 |
| 대상 | Book·YouTube·Crawler PVC 암호화 백업 | Portal 백업 제외 |
| 목적 | 일일 전체 백업은 유지하면서 원격 보관량을 제한함 | 배포·삭제는 별도 최종 승인 대상 |

## 핵심 요약

세 서비스의 일일 전체 백업과 격리 복원 검증은 유지함. 각 서비스 원격 폴더에서 30일이 지난 백업 중 최신 7개를 제외한 파일만 정리 후보로 삼음. 기본 실행은 후보 확인이며 실제 영구 삭제는 명시적인 정리 모드와 최종 운영 승인에서만 수행함. 백업 CronJob은 변경하지 않으며, 정리 기능은 운영 배포 전까지 실행되지 않음.

## 상세 설계

| 경계 | 정책 | 비고 |
|---|---|---|
| 대상 폴더 | `PersonalServer-encrypted-backups/{book-memo,youtube-memo,crawler-worker}` 중 명시한 한 서비스 | Portal 루트 파일과 다른 서비스 폴더 접근·삭제 금지 |
| 대상 파일 | runner가 생성하는 `YYYYMMDDTHHMMSSZ-숫자.tar.age` 형식만 허용 | 예상 밖 항목·미래 시각은 삭제 차단 |
| 기간·최소 개수 | 30일 초과 파일만 후보, 최신 7개는 항상 유지 | 복구 지점 감소를 제한함 |
| 안전 전제 | 유효기간 안의 최근 24시간 이내 성공한 업로드·격리 복원 증적과 원격 최신 파일명이 일치하고 시작 전 백업 잠금이 비어 있어야 함 | 삭제 동안 같은 잠금을 원자적으로 점유함. 증적 부재·불일치 시 차단 |
| 실행 | 후보 확인 모드가 기본, 영구 삭제 모드는 명시적으로 지정 | 삭제 직전 원격 목록·증적 만료 재검증. 계정 전체 휴지통 정리 금지 |
| 오류 | 목록 조회·증적 검증·삭제 실패는 실패로 보고하고 추가 삭제를 중단 | 기존 백업 성공을 소급 취소하지 않음 |
| 자동 실행 | 이번 변경에는 추가하지 않음 | 세 서비스 원격 백업 자체가 아직 미활성화 상태 |

## 검토 결과

기존 Portal 백업, Secret, PVC, K3s scheduler와 운영 데이터는 변경하지 않음. 정리 모드는 기존 백업 이미지의 별도 명령 `--prune-preview`와 `--prune-go`로만 실행되며 백업 CronJob의 기본 `--go`에는 연결하지 않음. 백업 CronJob에서 파생한 Job을 이용하면 PVC가 읽기 전용으로 마운트될 수 있으나 정리 명령은 PVC와 writer를 읽거나 변경하지 않음.

원격 최신 암호문의 바이트 해시를 정리 때 재계산하지는 않음. 성공한 업로드·재다운로드·격리 복원 증적과 원격 파일명·크기·수정 시각을 신뢰하고 최신 7개를 남기는 정책임. 미리보기와 실제 삭제 사이 원격 상태가 바뀔 수 있으므로 운영자는 삭제 직전에 미리보기를 다시 확인해야 함. 삭제 모드는 자체 목록을 다시 조회하고, 삭제 파일마다 재조회함.

검증 결과: 보존 정책 및 진입점 집중 테스트 16건 통과, 관련 백업·문서·테스트 매트릭스 검증을 포함한 집중 테스트 140건 통과, maintenance 492건 통과, K3s 계약 테스트 727건 통과함. Python 3.12 전용 3개 그룹은 필수 의존성을 임시 가상환경에 설치해 재실행한 결과 모두 통과함. Linux AMD64 백업 이미지 3개 빌드도 통과함. 독립 운영·보안 검토에서 공유 백업 잠금과 증적 만료 확인을 보완했고 재검토에서 차단 이슈가 없음을 확인함. 전체 테스트 첫 실행은 호스트 Python 3.12에 FastAPI가 없어 2개 그룹이 실패했으며, 해당 그룹을 임시 가상환경에서 재실행해 통과를 확인함.

## 확인 필요 사항

- 실제 정리 전에 새 서비스의 Google OAuth 연결, 서비스별 age 복구키의 외부 암호화 보관, 전용 Secret, 수동 백업·격리 복원 성공이 필요함.
- 보존 기간 30일·최소 7개 정책은 운영 배포 전 최종 검토에서 조정 가능함.

## 후속 조치

1. PR·CI·Agent Review를 확인하고 저장소에 반영함.
2. 서비스별 백업 활성화 조건과 정리 직전 미리보기를 확인함.
3. 실제 N100 이미지 교체와 영구 삭제 실행은 최종 운영 승인에 포함해 진행함.
