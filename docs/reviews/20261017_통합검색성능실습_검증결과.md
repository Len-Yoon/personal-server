## 2. 핵심 요약

로컬 샘플 HTTP 서버 세 개와 실제 `search_all`을 연결해 36셀, 측정 1,080건·준비 180건을 완료함. 모든 셀의 고정 결과 계약·자식 정상 종료·정리 검사가 통과했고 CPU·RSS 증적 누락은 없음. timeout·503은 정상 두 대상 보존과 books unavailable을 확인함.

전체 9개 로컬 검사 묶음은 최종 유효 결과 기준 2,701건 중 2,700건 통과·1건 건너뜀임. 독립 전문 검토는 APPROVE임. 저장소 PR/필수 CI/병합 상태는 해당 PR의 실시간 체크로 별도 판정하며 이 로컬 결과로 대신하지 않음.

normal에서 동시성 1→10으로 높일 때 처리량은 약 101~105→112~114호출/초로 증가하지만 p95는 약 10~11→128~138ms로 증가함. 이 실습 환경에서 동시성 증가가 처리량의 비례 증가로 이어지지 않음을 관측함. 클라이언트 생성·부하 발생기·샘플 서버 중 어느 비용이 지배적인지는 프로파일링 전 확정하지 않음.

자원은 프로세스별 누적 CPU user/system 시간과 high-water RSS로 원본에 보존함. 기동·준비 호출을 포함한 셀 수명 전체 값이며 순간 피크·물리 호스트 지표가 아님. 30건의 p99는 작은 표본이므로 신뢰할 수 있는 tail latency 추정으로 사용하지 않음.

## 5. 확인 필요 사항

- 고정 샘플·함수 단위·closed-loop 결과이며 실제 DB·HTML·브라우저·공개 경로·운영 용량·사용자 SLO는 미측정임.
- 요청별 클라이언트 생성과 부하 발생기·샘플 서버의 비용을 구분하는 프로파일은 미수행임. 본 결과만으로 원인이나 공유 클라이언트 도입 효과를 확정하지 않음.
- promtool 기반 기존 경보 규칙의 실제 계산은 이번 로컬 환경에서 미검증임. 새 실습의 검사 누락과 구분함.
- 장애 진단·복구 및 배포 표준화 단계는 후속 설계 대상이며 구현 완료로 표시하지 않음.

## 6. 후속 조치

제품 성능 개선은 보류함. 현재 결과는 측정 환경에서의 응답 분포와 실패 격리를 보여주며, 개선을 정당화할 병목 원인까지 규명한 것은 아님. 필요 시 같은 환경에서 클라이언트 생성 비용·실제 DB 질의를 분리한 프로파일링을 먼저 수행함.

주 담당이 구현·검증·통합하고 독립 전문 검토 담당(gpt-6.1-sol / high)이 diff·금지 영역·실제 프로세스 경계·통계 회귀를 검토함. 프로세스 수명·격리·보안 경계의 실패 비용을 고려해 Sol high를 선택했으며 동시 파일 수정은 수행하지 않음. 새 worktree는 만들지 않고 같은 목적의 기존 기능 브랜치를 재사용함.
