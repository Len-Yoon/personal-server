## 2. 핵심 요약

운영 감사의 이름 한정 읽기 권한 누락과 runner의 집계 실패를 0으로 보고하는 문제를 보완함. Crawler의 900초 수집 주기와 900초 신선도 한계가 같아 짧은 지연으로 반복 실패하는 경계를 1800초로 정합화함. 새로운 기준은 신규 기록에만 버전을 붙이며 기존 15분 기록과 혼합 시 동일 기준 30일 통과로 표시하지 않음. 실제 운영 적용은 미수행임.

## 5. 운영 적용 준비

1. 정확한 CI 통과 소스의 후보 이미지와 보안 검사·실행 검증을 준비함.
2. 사용자에게 대상·이미지·측정 기준 변경·검증 결과·순서를 보고하고 운영 적용 직전에 확인받음.
3. N100 저장소 clean·대상 커밋·보호 스냅샷 확인 후 승인된 fast-forward만 수행함.
4. 새 형식과 기존 형식을 모두 읽는 relay를 먼저 반영·health 확인함.
5. 감사 3종의 이미지 필드만 교체하고 일정·suspend·기타 spec을 보존함.
6. `slo-audit-read-access.py --check`의 UID와 규칙 해시로 승인된 `--apply`를 수행하고 실제 공식 SA 읽기 권한을 확인함. 권한 수신자가 달라지면 차단함.
7. 수집기 이미지를 마지막에 교체하고 일정·과거 records.json을 보존함. 신규 기준은 이후 생성된 행에만 적용함.
8. 승인된 격리 시험과 실제 보고·알림 수신, 원본·보호 대상·시험 자원 정리 및 외부 health를 실행자와 별도 검토자가 확인함.

새 기준 행 생성 뒤에는 구 runner가 이를 읽지 못하므로 호환 reader를 유지함. 수집기 문제 시 수집기만 기존 이미지로 되돌릴 수 있으나 기록을 지우거나 버전 표식을 제거하지 않음. RBAC 원복이 필요한 경우 이번에 추가한 규칙만 UID·현재 규칙 전제로 제거하며 다른 권한·binding은 변경하지 않음. 응답 불완전 시 재실행 전 실제 상태를 조회함.

## 6. 확인 필요 사항

- 실제 운영 적용·새 기준 정기 실행·실제 알림은 이 변경의 배포 승인 전 미수행임.
- 30분 기준 적용은 앞으로의 측정 정의 변경이며 과거15분 기록이 정상으로 바뀐다는 뜻이 아님.
- Portal의 계획 정지를 SLO 분모에서 제외하는 정책은 도입하지 않음. 무중단 백업·가용성 목표 변경은 이번 수정 범위 밖임.
- 30일 시간 기반 SLO와 에러 버짓은 일일 기록만으로 산정할 수 없음.
