## 핵심 요약

맥·GitHub·N100의 저장소 커밋은 일치했으나 Book 실행 이미지의 `host_urls.py`는 현재 소스와 달랐음. 2026-09-28 13:00 KST 뉴스 백업 정기 Job은 `preflight`에서 실패하고 잠금을 해제했으며, 이번 실행의 성공 증적은 없음. 일일 SLO의 세 `failed` 항목은 수집 성공과 별개의 실제 관측 결과이므로 성공으로 보정하지 않음. 맥에서 수정·검증한 이미지와 제한된 운영 적용 순서를 준비하고 실제 N100 변경 전 보고함.

### SLO 실패 시간대 추가 대조

- Portal 백업 Job은 9월 28일 03:00:00~03:12:15 KST에 성공함. writer pause는 03:00:46, desired replica 0은 03:01:15~03:12:00, available replica 0은 03:01:15~03:12:30에 관측됨. 해당 0은 백업 중 실제 writer 정지와 일치하며 가용 상태로 재분류하지 않음.
- 뉴스 수집 성공 간격 26분 21초는 9월 27일 23:57:28~28일 00:03:58 수동 PVC 백업에 따른 Pod 교체 및 새 Pod의 첫 수집 전 900초 대기와 일치함. 그 밖에 08:46~12:31 KST에는 15분 간격의 단일 0 표본이 반복됨. 수집 주기 900초와 `<=900` 판정의 경계 충돌로 설명되지만, 이 관측을 소급하여 성공으로 바꾸지 않음.
- 공개 health의 과거 02:15 KST 비-200 HTTP 코드는 기존 기록에 없어 확인 불가함. 새 이미지 배포 후 비-200이 다시 발생하면 코드만 확인하고 경로·응답 본문·자격 증명은 로그에 남기지 않음.

## 승인 후 제한 적용 순서

1. 최종 병합 커밋, N100 브랜치·추적 변경, 활성 Job, Book·뉴스 단일 writer, PVC Bound, 기존 세 이미지, Secret **존재 여부만**, 네 공개 health를 읽기 전용으로 재확인함. 확인값이 바뀌면 변경 동작을 중단함.
2. 승인된 정확한 커밋만 N100에 fast-forward함. 맥에서 빌드한 세 archive를 전송하고 각각 전체 SHA-256을 재확인한 뒤 기존 이미지의 rollback alias를 보존하며 `k3s-app-image-import.sh --go`로 반입함.
3. Book은 `k3s-app-upgrade.sh --check` 후 현재 이미지 digest를 기대값으로 고정해 `--go`를 1회 실행함. 도구는 이미지 필드만 조건부 patch하고 내부 health·공개 Book health 3회를 확인하며 실패 시 기존 이미지로 단회 원상복구함. Portal과 Book의 공개 health를 별도로 3회 확인함.
4. 뉴스 백업은 [운영 목표 상태](../../infra/k8s/backup-automation/production-cronjob-state.json)와 활성 CronJob의 스케줄·상태를 대조함. `service-pvc-backup-production-state.py`는 이미지 변경을 수행하지 않으므로, 기존 CronJob의 UID·resourceVersion·두 컨테이너의 현재 이미지를 JSON Patch `test`로 고정하고 initContainer와 backup 컨테이너의 **두 image 필드만** 새 digest로 `replace`함. 두 값이 달라졌거나 Job이 활성화되면 적용하지 않음. 변경 직후 두 이미지·일정·활성 상태를 직접 읽기 검증하고, 기존 실패 Job 종료와 lock 공백을 확인한 뒤 수동 Job **1회**로 원격 암호화 백업·격리 복원·성공 증적을 검증함. 목표 상태 도구 `--check`는 `completed` 상태와 성공 증적을 요구하므로 수동 Job 성공 **후** 실행함. 실패하면 고정 stage와 writer·lock을 확인하고 임의 반복 실행을 중단함.
5. SLO CronJob은 증적 ConfigMap·기존 `suspend=false`와 기타 spec을 보존하며 **이미지 필드만 기대값 검사 후 변경**함. [설치용 manifest](../../infra/k8s/slo-evidence/slo-daily-evidence-cronjob.yaml)는 `suspend: true`와 빈 ConfigMap을 포함하므로 운영에 전체 재적용하지 않음. 같은 날짜의 수동 Job은 해당 날짜 기존 기록을 교체하므로, 기록을 보존해야 하면 다음 KST 날짜의 정기 실행 결과를 검증하거나 정기 실행 전 수동 Job 1회만 수행함. 비-200이 재현되면 코드만 확인하고 실패 판정은 유지함.
6. 변경 대상과 Portal의 공개 health를 각각 10초 간격 3회 확인함. Book Pod imageID, 백업 CronJob 이미지·writer·잠금·증적, SLO CronJob 이미지·증적, Relay 상태를 확인하고 `저장소 병합 / N100 동기화 / 이미지 반입 / 수동 검증 / 자동 실행 / 외부 health`를 각각 기록함.

## 검토 결과와 확인 필요 사항

- 맥에서 전체 CI 대응 서비스 묶음 9개가 통과함. K3s 계약 750건·유지보수 492건을 포함하며 Book 서비스 35건과 이미지 업그레이드 도구 검증도 통과함. 정적 검사·문서 계약 검사와 독립 운영 검토에서 배포 차단 결함은 발견되지 않음. PR #296의 14개 검사, Agent Review·Trivy와 병합 후 `main` CI가 통과함.
- 병합 커밋 `2eaa788`의 `Deploy N100`은 `action=blocked`, `reason=blocked_path`로 분류됐고 실제 `deploy` Job은 건너뜀. 맥 `main`과 GitHub `main`은 일치하고 작업 트리는 깨끗함. 네 공개 health는 병합 후 각각 10초 간격 3회 모두 HTTP 200임.
- 뉴스 백업의 2026-09-28 실패를 30초 원격 조회 시간초과로 **확정하지 않음**. 새 코드의 고정 실패 분류와 수동 검증으로 원인을 다시 확인해야 함.
- SLO의 과거 비-200 코드·원인과 계획 정지의 목표 포함 여부는 **확인 필요**. 현재 `failed` 기록을 성공으로 바꾸지 않음.
- 9월 28일 뉴스 정기 백업 실패 이후 성공 Job은 없고 상태는 `failed / preflight`, 잠금·성공 증적 없음으로 재확인됨. 운영 적용·N100 이미지 반입·수동 Job 실행은 **미수행**. 본 문서는 실행 전 보고를 위한 준비 자료임.
