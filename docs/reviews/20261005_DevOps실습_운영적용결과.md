## 핵심 요약

N100 동기화·전용 실패 배포 및 HTTP 복구 훈련·Loki 데이터 보존 rollback 및 재설치·SLO image-only 교체는 성공함. Ansible의 CRLF·locale 호환 문제를 수정·병합하고 후속 승인으로 `0789890` 동기화·실제 훈련을 수행함. 소유권·baseline·drift 감지는 통과했지만 단일 파일 bind의 구 inode 참조로 원복·복구는 실패함. 전용 sample만 1회 재생성하여 원본 HTTP를 복구했고 실패 결과는 성공으로 대체하지 않음.

### 실패 원인 및 처리

| 구분 | 원인·실제 처리 | 비고 |
|---|---|---|
| Ansible 응답 | Windows checkout의 CRLF를 LF literal과 비교하여 초기 검사가 실패함 | 원본·권한 변경 없이 주입 보류. 고정 템플릿 원시 bytes와 응답을 정확히 비교하고 newline을 보존하도록 보완 |
| Ansible 실행 환경 | `LC_ALL=C`를 강제해 N100 Ansible의 UTF-8 요구사항에 맞지 않음 | 설치된 영문 UTF-8 locale 선택 및 미지원 시 실행 차단으로 보완 |
| Ansible 실제 원복 | template가 host 파일을 atomic rename하여 교체해도 Compose configs의 단일 파일 bind는 기존 drift inode를 계속 참조함 | host 원본·HTTP drift·mount inode 불일치를 독립 확인. 파일 변경 또는 정상 파일과 실제 응답 불일치 시 전용 sample만 재생성하도록 후속 보완함. 정상 반복 실행의 무변경과 check mode 보호 유지 필요 |
| SLO smoke 보조 검사 | 검사 호출 코드가 수집기의 `standard_urlopen` 별칭 대신 존재하지 않는 `urlopen`을 참조함 | 실제 수집기 결함과 구분함. 호출만 수정해 공개 요청 PASS, 실패·성공 probe Pod 모두 삭제 |
| Loki 추가 비교 검사 | kubectl 다중 JSON 처리와 API의 `hostIPC=false` 기본값 생략을 보조 검사에서 잘못 해석함 | 설정 차이·외부 소유 자원으로 확정하지 않음. JSON stream 처리와 명시적 false 기본값만 정규화 후 비교 |
| 작업 절차 미흡 | 추가 manifest 비교 검사 실패를 해소하기 전에 고정 named rollback을 실행함 | 성공으로 숨기지 않음. 실제 지정 자원·PVC·기존 monitoring 보존 및 재설치 결과를 확인함. 후속 작업은 추가 비교 실패도 다음 mutation을 차단하도록 점검 필요 |

## 확인 필요 사항

- 단일 파일 bind 원복 보완의 필수 검증·독립 검토·병합 및 새 SHA 운영 적용 승인·실제 재훈련이 남아 있음. `0789890` 훈련의 실패를 로컬 테스트나 수동 복구로 통과 처리하지 않음.
- 새 SLO 이미지의 다음 정기 수집 성공, Grafana 화면 렌더, CNI 접근 정책 집행, Loki 24시간 보존 이후 실제 삭제는 별도 확인 필요함.
- local-path의 1Gi 요청은 디스크 강제 quota가 아님. 전체 시간 기반 SLO·에러 버짓 확보로 과장하지 않음.

## 후속 조치

1. 단일 파일 bind의 변경·부분 적용 후 복구 경로를 보완하고 검토·검증·PR·CI·main 병합 결과는 해당 PR에 기록함.
2. 새 수정 SHA 동기화·Ansible 재훈련 승인 후 해당 단계만 수행함. Loki rollback·SLO 교체를 반복하지 않음.
3. 다음 정기 수집과 시간 경과가 필요한 증거는 실제 결과를 확인한 후 별도로 기록함.
