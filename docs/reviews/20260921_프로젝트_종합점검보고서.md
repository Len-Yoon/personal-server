## 2. 핵심 요약

**새 기능 확대보다 통합 검색, HomeOps 실행 안전성, 파일 저장 동시성, 요청 지표의 메모리 사용, CI 테스트 누락을 먼저 보완할 필요가 있음.** 기존 테스트가 많이 구축되어 있으나 실제 모듈 연결부와 동시 요청·실패 후 재시도 경로를 놓치는 사례가 확인됨.

- 통합 검색: 실제 서비스 주소 생성 함수를 연결하면 상대 URL 결과에서 HTTP 500이 재현됨.
- HomeOps: 저장소의 스케줄 요청은 Origin 검사에서 403으로 차단됨. 승인 요청 경쟁 시 fake executor가 동일 건을 2회 실행하며, 정상 샘플을 사이에 둔 장애도 연속 장애로 처리됨.
- 파일함: 같은 이름의 동시 업로드 2건이 모두 성공하지만 파일은 1개만 남는 덮어쓰기가 재현됨.
- 관측성: 요청 시간 원본을 무한 누적함. 10만 요청을 입력하면 10만 샘플이 그대로 남음.
- 검증: 테스트 모듈 84개 중 22개가 CI 실행 목록에서 누락됨. 로컬 runner는 환경 변수를 지나치게 제거하여 정상 테스트가 실패함.
- 문서: Trivy의 report-only 설명은 실제 차단형 workflow와 다름. 기본 suspended/sentinel 설정 자체는 안전장치이므로 운영 미적용의 증거로 취급하지 않음.

## 7. 확인 필요 사항

## 8. 후속 조치와 역할별 결과

1. F01·F02~F06·F13의 회귀 재현을 정식 테스트로 편입하고 기능별 작은 변경으로 보완함.
2. CI 누락 22개와 test dependency를 서비스별 격리 원칙에 맞게 반영함. 기본 runner 환경 차이를 함께 해결함.
3. 조회 부작용·관계 무결성·응답 타입·재시도 멱등성을 수정함.
4. 문서에는 저장소 계약, N100 적용, 이미지 반입, 수동 검증, 자동 실행 활성화, 외부 health 검증을 분리 기록함.
5. 그 이후 백업 범위 확대·검색 병렬화·저장소 트랜잭션화 등을 별도 설계함.

| 역할 | 사용 여부·담당 | 결과 | 비고 |
|---|---|---|---|
| 주 검토 | 사용, Portal·Book·YouTube·서비스 연결·전체 테스트·재현·결론 통합 | 실제 결함 재현 및 원인 분리, 근거 검수 | 코드 수정 없음 |
