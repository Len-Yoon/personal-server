## 2. 핵심 요약

세 종류의 알려진 로컬 장애를 각 3회 실행하여 총 9회 모두 통과함. 실제 제품 함수·실제 SQLite 오류를 사용했으며 모든 실행에서 8개 이벤트 순서, 소유 자식 정상 종료·회수, fixture 삭제를 확인함. 실패 후 논리 데이터 보존과 동일 요청 재전송의 단일 적용을 확인함. 운영 신뢰성 수치·사람의 진단 능력 평가로 확대하지 않음.

| 자동배포 분류 | action=blocked, reason=blocked_path | 배포 제외이며 서비스 장애를 뜻하지 않음 |

최초 회귀는 도구 부재로 RED 확인 후 구현함. 검토에서 SQLite 실패 관측 전에 snapshot을 검증하여 원인 확인 시간이 탐지에 섞이는 P2를 발견함. probe/evidence 명령을 분리하고 .15초 지연 회귀로 RED→GREEN을 확인함. 독립 실제 FULL + .8초 snapshot 지연 재현에서도 탐지 약 .00065초·원인 확인 약 .807초로 분리됨. 프로토콜 보완 중 실행된 이전 Book 검사는 불일치·정지 상태여서 해당 테스트 프로세스만 종료하고 최종 Book 묶음을 재실행함. 정리 실패 회귀의 잘못된 patch 대상은 수정 후 재검증함. 전체 검사에서 다른 서비스의 유효 결과는 유지함.

첫 9회 측정은 전체 회귀가 일시 생성한 파일로 dirty=true였으므로 최종 원본에서 제외함. 기록된 제품·도구 해시 일치는 별도 확인했고, 깨끗한 소스 상태의 두 번째 측정을 보관함. 최초 측정과 최종 측정을 섞어 분모를 늘리지 않음.

## 5. 확인 필요 사항

운영 알림·Prometheus 경보 발화·사람의 수동 RCA 시간·실사용자 영향·앱 HTTP 오류 처리는 미검증임. 운영 MTTD/MTTR·RTO/RPO를 산출하지 않음. SQLite FULL은 OS ENOSPC 증거가 아님. 전체 9개 로컬 검사·필수 PR/main CI·Agent Review·병합 커밋과 정리는 해당 PR의 최종 검증 기록으로 확인함. 필수 검사 완료 전 병합하지 않음.
