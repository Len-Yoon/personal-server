## 4. 검토 결과

- 기존 정책의 다음 달까지 일별 전체 백업 누적과 Portal 정리 미지원 문제를 보완함.
- 삭제 직전마다 증거의 최근 백업·복원 성공, 최신 파일 일치, 파일명·크기·수정 시각·Drive 객체 ID를 재확인함.
- 원격 목록 변경·중복 이름·예상하지 않은 서비스 파일·만료 증거·삭제 실패는 즉시 중단함. 삭제 요청의 응답이 모호하면 재시도하지 않음.
- Portal은 공용 루트의 `portal-*.tar.age`만 다루고 다른 서비스 폴더와 무관한 파일은 보존함.
- 보관 정리 실패 시 새 백업의 검증 성공 증거를 지우지 않음. 백업 실패와 정리 실패의 알림을 구분함.
- Portal의 기존 유효기간 설정과 증거 재사용 보호를 유지함. 기본 증거 유효기간 24시간은 파일 보관 기간과 별개임.
- 주 담당은 공통 정책·Portal·통합·기록, Sol 중간 추론 구현 담당은 세 서비스와 실패 보고 계약, Sol 높은 추론 전문 검토자는 삭제·잠금·증거·알림 경계를 담당함. 이미지 담당은 exact source 격리 빌드·검사를 수행함. 담당 파일을 분리하고 같은 파일 동시 수정 없음.

## 5. 확인 필요 사항

정리 잠금 획득·해제 자체가 실패하면 신뢰 가능한 정리 결과를 확정할 수 없어 기존 실행 확인 불가 분류가 남을 수 있음. 자동 삭제는 중단하고 잠금 상태를 확인해야 함. Relay의 새 소비자 계약을 먼저 반영한 뒤 네 백업 이미지를 적용해야 하며 이전 Relay와 신규 백업의 부분 배포는 허용하지 않음.

Drive 목록 비교는 원격 삭제의 원자적 CAS가 아님. 잠금을 따르지 않는 외부 변경을 완전히 막는다고 보장하지 않음. 보존 대상은 선택된 시점의 전체 스냅샷이며 그 사이의 모든 변경 이력은 보존하지 않음. 백업 하나의 크기가 증가하면 보존 개수가 같아도 총용량은 증가함.

### 승인 후 운영 실행 순서

1. Portal 및 관련 서비스 외부 health와 timer까지 남은 시간, 진행 중 Job·잠금·단일 writer·보호 리소스를 읽기 전용 확인함.
2. CI 통과 병합 커밋을 N100에 fast-forward하고, 다섯 OCI를 체크섬 검증 후 canonical image ref로 반입함. hook·작업공간 변경은 덮어쓰지 않음.
3. 새 Relay 소비자 이미지를 먼저 한 필드 조건부 교체하고 readiness·실제 imageID를 확인함. 새 host sequence 코드와 호환됨을 확인함.
4. 네 백업 CronJob의 본/초기화 image 두 필드만 조건부 교체함. 전체 manifest 재적용·timer·schedule·suspend·Secret·PVC·앱 이미지 변경은 수행하지 않음.
5. 새 백업의 원격 업로드·복원 검증 후 보존 정책을 실행함. 사전 계산 후보 44개는 고정 삭제 목록이 아니며 해당 시점 증거·목록을 다시 검증해 후보만 정리함. 휴지통을 거치지 않는 영구 삭제임.
6. 네 서비스 최신 검증 증거·정리 결과·잠금 해제·보존된 원격 파일·용량·소비자·단일 writer와 외부 health를 독립 사후 확인함. 첫 정기 실행은 실제 관측으로 별도 확인함.

### Relay 적용 전 발견한 기존 형식 호환 오류

기존 Relay Pod는 2026-09-29 생성·재시작 0회이며 새 Relay digest의 ReplicaSet이 없어 이번 이미지 교체 이전부터 NotReady였음을 확인함. 실제 순차 백업 상태의 `portal_evidence_refresh=passed`를 기존·최초 준비 Relay 코드가 모두 미등록 필드로 거부하고 polling에서 ValueError·healthz 503을 반복함. 기존 상태·Secret을 고치는 대신 소비자가 해당 선택 필드의 `passed`·`failed` 두 값만 허용하도록 최소 보완함. 그 외 미등록 필드·잘못된 값의 거부 계약은 유지함. 회귀 100개 중 2개 실패 재현 후 관련 156개 통과, 수정된 parser의 실제 운영 상태 읽기 전용 검증 통과, 새 Relay 실제 이미지 100개·HIGH/CRITICAL 0건 확인함. 이전 전체 검사 중 변경 영향 없는 결과를 재사용하고 PR/main 필수 CI는 새 커밋에서 실행함.
