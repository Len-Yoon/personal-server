## 핵심 요약

호스트 유지보수의 `prune-news`와 일일 `all`은 뉴스 보관 파일을 더는 읽거나 쓰지 않음. 뉴스 수집기 자체의 보관 기간 정리만 사용하며, 호스트의 백업·로그 정리 동작은 유지함. 이전에 보관한 runtime marker 기반 수정안은 Compose 모드의 동시 쓰기 위험을 남겨 그대로 적용하지 않았음. [PR #313](https://github.com/Len-Yoon/personal-server/pull/313)의 병합 커밋 `d2d30dbdf52adfd2fcc8050029963acf91595ccc`를 맥과 N100에 반영하고, 호스트 뉴스 파일 불변과 서비스 상태를 확인함.

## 검토 결과

독립 코드 검토에서 변경 하네스의 오래된 차단 경로 예시를 발견해 보완함. 독립 운영 검토에서는 향후 `maintenance.py` 변경에도 정책 예외가 적용되는 점을 지적해 필수 검사를 전체 서비스로 강화함. 운영 전 읽기 전용 점검에서 N100 호스트 뉴스 파일은 9월 22일 이후 수정되지 않았고 활성 K3s PVC 경로와 분리된 것으로 확인함. PV 파일의 실제 inode 동일성은 접근 권한 때문에 **확인 필요**이나, API상 경로는 분리됨.

## 확인 필요 사항

| 항목 | 상태 | 후속 조치 |
|---|---|---|
| 다음 정상 bootstrap의 일일 유지보수 | 확인 필요 | `all`의 실행 기록과 백업·로그 정리 결과를 읽기 전용으로 확인 |
| 뉴스 수집기 보관 기간 정리 | 확인 필요 | 주기적 수집·정리의 실제 증적을 확인. 호스트의 과거 뉴스 파일은 임의 삭제하지 않음 |

## 후속 조치

호스트 뉴스 보관 파일을 별도 정리하지 않고 보존함. 다음 정상 유지보수 실행의 결과를 확인하며, 이상 발생 시 수집기 상태와 archive 증적을 먼저 조사함. 이번 적용에서는 서비스 재시작, 운영 데이터·PVC·Secret·Caddy·Tunnel 변경을 수행하지 않았음.
