최초 기능 부재를 확인하는 경계 검사의 실패는 구현 전 재현임. 이후 YouTube 검사 fixture의 export API 차이를 교정함. 일반 sandbox 실행에서는 기존 로컬 HTTP 서버 bind 검사가 제한되어 소켓 허용 환경에서 전체 검사를 다시 실행함. 필수 검사를 생략하거나 workflow를 변경하지 않음. 전체 k8s 실행은 검토 보완 중 테스트 모듈을 먼저 로드해, 이전 `tests_whole_pod` 기대값과 최종 UID/resourceVersion/image CAS 구현을 함께 검사한 상태였음. 전체 pod 출력은 자격 증명 노출 방지를 위해 제거한 것으로, 최종 테스트가 이를 확인함. 주 담당과 독립 검토가 최종 고정 코드의 관련 25건을 각각 성공 확인하고, 영향 없는 기존 검사 결과만 재사용함.

## 확인 필요 사항

- 휴지통 미리보기는 프로세스 내 서명 키를 사용하므로 재시작하면 만료됨. 현재 단일 worker 구성을 유지하며, 향후 여러 worker로 확장할 때 공유 확인 상태 설계가 필요함. 읽을 수 없거나 복원 완료된 기록은 별도 제외 개수로 표시하며, 항목별 10,000개/깊이 64 한계를 넘으면 크기는 확인 필요로 표시하고 영구 삭제 대상에서 제외하되 목록·복원 접근은 유지함. 총 크기도 불완전 집계임을 표시함.
- N100 신규 이미지 반입·세 앱 운영 적용은 아래 기록과 같음. 실제 계정으로 운영 데이터를 편집·영구 삭제하는 시험은 미수행임.
- 세 앱 자원 제한과 `/ready`를 실측 후 적용함. NetworkPolicy와 Portal read-only rootfs 전환은 아래 사유로 미적용임. Crawler는 변경 대상에서 제외하고 기존 상태를 보존함.
- 휴지통 영구 삭제는 사용자 화면에서 미리보기와 확인을 거친 항목에 한하며, 작업 중 운영 데이터 삭제는 수행하지 않음.

### 미적용·미검증 경계

- NetworkPolicy: 실제 DNS에서 외부 제공자의 다중 IPv4/IPv6 주소를 확인했으나 유지 가능한 CIDR 근거와 Caddy 실제 진입 source·CNI enforcement 증거가 부족함. 넓은 허용으로 우회하지 않았으며 정책 생성·적용 및 CNI smoke는 미수행임.
- Portal rootfs 보안 전환: 현재 writable `/tmp` emptyDir와 pod seccomp가 없어 전체 하드닝 생성 도구가 차단함. 이번 적용은 resources와 readiness 경로만 변경했으며 mount·securityContext는 보존함. Book·YouTube는 기존 read-only rootfs·RuntimeDefault·drop ALL을 유지함.
- 백업 자동 실행 활성화·일정 변경·운영 데이터 삭제·사용자 계정으로 실제 편집·영구 삭제는 미수행임. 다음 정기 백업과 신규 이미지24시간 부하는 확인 필요함.

### 최종 사후 검증

Portal·Book·YouTube·News 외부 health를 10초 간격으로 3회씩 확인하여 총12/12 HTTP 200을 확인함. 별도 담당의 읽기 전용 원격 사후 조회1회에서 정확 커밋·미추적 파일2개 보존·세 앱 목표 digest·자원값·`/ready`200·4개 단일 writer·restart0/OOM 없음·데이터 해시 일치·PVC5개 Bound·Secret/Cron/비대상 앱 불변·백업 잠금 해제·NetworkPolicy0개를 확인함. Portal rootfs rw 유지와 Book·YouTube ro 유지, Crawler 전체 spec 불변도 확인함. 사후 노드 현재값은 CPU545.5m, 메모리6,479,278,080bytes이며, 앱 메모리는 Portal46,075,904 / Book55,816,192 / YouTube41,869,312 / Crawler60,891,136bytes임. 신규 이미지 장기 안정성이나 다음 자동 백업 성공으로 확대 해석하지 않음. 이번 세 앱 배포 승인은 완료·소진됐으며 보류한 보안·통신 정책 적용이나 추가 재실행 승인으로 재사용하지 않음.
