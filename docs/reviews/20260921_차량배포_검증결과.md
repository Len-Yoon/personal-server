## 최종 사후 검증

- main CI `35595556522`, Trivy `35595556444`, Deploy N100 `35595556651` 성공함. 배포 로그에서 writer pause·data ownership·health PASS를 확인했으며 rollback 단계는 실행되지 않음.
- 새 이미지 `sha256:f303b9d851b5ca2a85f2acdf24d5df5314caacea744969f68b0e4ee173cec590` 실행, Docker healthy·failingStreak 0·검사 제한 15초를 확인함.
- 명령 처리 결과 테이블의 update_id·reply_text·processed_at 생성 확인함. 정비·타이어·알림 상태의 전체 행 SHA는 배포 전후 일치함. 차량 최신 스냅샷은 단일 행을 유지하되 내용 지문이 갱신되어, 내용 불변으로 표현하지 않음. 관측 시각이 컨테이너 재기동 이후임을 읽기 조회로 확인했으며, 기동 직후 차량 조회·단일 행 UPSERT 경로도 독립 검토로 확인함.
- 실행 중 store·telegram 파일은 원시 바이트 SHA 비교에서 실패했으나 CRLF를 LF로 정규화한 뒤 모두 Git 원본과 일치함. 코드 내용 변경이 아닌 줄바꿈 차이로 원인을 분리함.
- 전문 검토 담당의 사후 결론은 배포 PASS, P0~P2 없음임. 실제 Telegram 명령을 보내는 추가 운영 쓰기 검증은 수행하지 않음.
