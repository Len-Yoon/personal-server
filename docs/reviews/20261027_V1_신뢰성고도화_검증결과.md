## 2. 핵심 요약

누락·오래된 표본을 정상으로 계산하지 않는 읽기 전용 분석 도구를 구현함. 실제 최근 7일 요청 구간의 평가 표본은 10,081개이며 유효 7,946개·미관측 2,135개임. 관측 표본 성공률은 약 99.9748%이지만 전체 coverage가 약 78.8215%이므로 기간 전체 가동률·에러 버짓으로 사용하지 않음. 원시 실패 2표본은 그대로 보존함.

검색 HTTP 성공·지연과 의존 검색 완전성의 차이를 정의함. 이미지 원복·데이터 복원·writer 전환과 복원 필수 자산을 원본 코드 기준으로 정리함. 실행 가능한 도구/문서와 시간이 필요한 동일 기준 관측·직접 실습·운영 복구 시험을 구분함.

### 3.2 실제 7일 요청 구간의 평가 표본

N100의 기존 Prometheus API를 GET으로 읽음. 원본 label은 원격 메모리에서 네 응답의 일치를 검증하고 비민감 source 해시와 대상 namespace/deployment로 치환한 뒤 로컬 입력에 저장함. 자격 증명·내부 주소·원문 label을 로컬 증거·Git에 기록하지 않음.

| 항목 | 값 | 해석·비고 |
|---|---|---|
| 요청 구간 UTC | 2026-10-20 00:25:30~2026-10-27 00:25:30 | KST 10/20 09:25:30~10/27 09:25:30 |
| 평가 간격·분모 | 60초, 양 끝 포함 10,081표본 | 분당 관측이며 1분 미만 상태 변화를 놓칠 수 있음 |
| 유효 관측 | 7,946표본 | available/desired 및 두 원본 timestamp가 모두 있고 신선함 |
| 정상·실패 | 정상 7,944·실패 2표본 | 정확한 중단 시간·요청 실패 건수 아님 |
| 미관측 | 2,135표본, 모두 missing | stale/nonfinite/future 0. 누락을 성공으로 채우지 않음 |
| 최초 반환 평가점 | 10/21 21:00:30 KST | 네 응답 모두 동일하며 이후 평가점은 연속됨 |
| 관측 표본 성공률 | 99.9748301032% | 관측된 7,946표본만의 비율 |
| 전체 coverage | 78.8215454816% | 요청 구간 전체 10,081표본 대비 |

| desired 0·available 0 후보 | 0표본 | 백업 정지가 없었다는 뜻 아님. 분당 평가의 누락 가능성 유지 |
| 시간 기반 SLO·버짓 | not_calculable | 30일 관측이나 정확한 지속시간 자료가 아님 |

7일을 15초 간격으로 한 번에 요청한 최초 조회는 API 오류로 차단됨. Prometheus의 query_range 표본 상한을 고려하여 60초 간격으로 줄인 뒤 성공함. 최초 실패의 응답 분류는 query_failed였으며 당시 정확한 오류 본문은 저장하지 않았으므로 서버 상한이 직접 원인이었다고 확정하지 않음. 운영 수집·scrape 간격·보존 기간은 변경하지 않음.

### 3.3 보존 설정과 실제 가용 범위

실제 가장 오래된 TSDB 시각은 UTC 10/21 12:00:00(KST 21:00:00)으로, 반환 표본의 시작 경계와 일치함. 설정의 7일이 언제나 조회 가능한 정확한 7일 원시 자료를 보장하는 것은 아님. 조회 시 저장 block 용량은 2,612,281,299바이트임. 보존 제한·compaction 이력의 개별 삭제 근거를 새로 조회하지 않았으므로 특정 삭제 원인을 확정하지 않음.

| 계층 | 관측값 | 비고 |
|---|---|---|
| 선언 CR | retention=7d·retentionSize=3GB | 설정 변경 없음 |
| 기존 CLI flags | retention.time=1w·retention.size=0B | 새 버전에서 설정 파일이 우선할 수 있어 이것만으로 size 미적용을 단정하지 않음 |
| 실효 보존 | runtimeinfo storageRetention=`1w or 3GiB` | 선언된 시간·용량 제한과 정합적임. CLI size=0B만으로 미적용이라고 판단하지 않음 |

[Prometheus 공식 설정](https://prometheus.io/docs/prometheus/latest/configuration/configuration/)은 `storage.tsdb.retention`의 설정 파일 값이 deprecated CLI flag보다 우선한다고 설명함. 값의 표시 계층을 구분하고 실행 중 보존 범위를 확인한 뒤 판단함.

## 6. 후속 조치

실행 가능한 도구·정의·복구 준비 자료를 구현·검증·검토·PR/CI·병합까지 진행함. 기존 수집·백업·복구 자동화를 유지하며 새로운 실패나 명확한 계측 요구가 확인되면 해당 범위만 변경함. 기간이 필요한 관측·직접 실습·전체 DR를 완료로 바꾸지 않음. 운영 배포·N100 소스 동기화·이미지 반입·설정 reload·추가 예약·V2 변경은 이번 작업에서 해당 없음.
