## 2. 핵심 요약

사용자의 운영 진행 승인 범위에서 N100 저장소를 `8534e59`로 fast-forward하고 세 백업 이미지의 새 Linux AMD64 OCI archive를 SHA-256·manifest digest 검증 후 containerd에 반입함. 세 서비스의 Secret·상태 ConfigMap·CronJob 및 수동 Job은 생성·실행하지 않음. age 복구키가 N100 외부 암호화 저장소에 보관돼 있는지 확인되지 않아 이 단계에서 중단함. 자동 실행과 원격 백업 파일 삭제는 승인 범위에서 제외함.

## 4. 검토 결과

주 담당은 N100 기준 상태·fast-forward 경계·이미지 전송 해시와 health를 확인함. 독립 운영·보안 검토는 Secret 복제 방식, 단일 writer, 잠금·실패 복구, 부분 생성 위험을 점검함. 기존 Portal Secret의 네 키를 새 Pod에 직접 mount하지 않고 새 서비스 Secret에 메모리 경유로 복제하는 일회성 절차를 준비했으나 실행하지 않음. 동일 Google OAuth 토큰과 age identity를 재사용하면 어느 한 백업 Pod 침해 시 Portal을 포함한 전체 백업 접근·복호화로 영향이 확대되는 잔여 위험이 있음. 생성 중 오류는 자동 재시도·삭제하지 않고 생성 여부를 확인한 뒤 멈춰야 함.

## 5. 확인 필요 사항

| 항목 | 상태 | 후속 조건 |
|---|---|---|
| age 복구키의 N100 외부 암호화 보관 | 확인 필요 | 키 값·경로를 공유하지 않고 보관 여부만 확인함 |
| 동일 OAuth 계정의 실제 N100 원격 읽기·쓰기 | 미검증 | Secret 준비 뒤 `--check`와 순차 수동 Job에서 확인함 |
| 새 Secret·상태 ConfigMap·CronJob | 미생성 | 기존 대상 부재·원본 Secret 버전 확인 후 최초 생성. CronJob은 중지 유지 |
| 수동 백업·격리 복원 | 미수행 | Book→YouTube→Crawler를 하나씩 실행하고 writer 1/1·잠금 해제·복원 증적·외부 health 확인 |
| 자동 실행·보존 삭제 | 미수행 | 이번 적용 범위 제외. 별도 조건·운영 승인 필요 |

## 6. 후속 조치

1. age 복구키의 외부 암호화 보관 여부를 확인함.
2. 확인 시 승인된 범위에서 전용 Secret과 중지 상태 리소스를 생성하고 세 서비스 수동 Job을 순차 검증함. 실패하면 다음 서비스로 진행하지 않음.
3. 실패 알림 실전 확인과 보존 정리 미리보기 후 자동 실행·실제 삭제 여부를 별도로 결정함.
