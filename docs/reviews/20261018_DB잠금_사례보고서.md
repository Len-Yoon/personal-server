## 2. 핵심 요약

별도 프로세스의 실제 SQLite writer 잠금으로 Book 메모 수정을 실패시킨 뒤, 잠금 해제와 동일 요청 재전송으로 복구를 검증함. 2026-10-18 11:28 신규 자동 실행 1회에서 코드 5·실패 원자성·단일 반영·무결성·자원 정리를 확인함.

## 3. 상세 내용

| 단계 | 관측·판단·조치 | 비고 |
|---|---|---|
| 증상 | 제품 `update_memo` 호출이 약 5초 대기 후 `SQLITE_BUSY=5`로 실패함 | 신규 탐지 5.200274초 |
| 원인 근거 | 별도 연결의 `BEGIN IMMEDIATE`가 writer 잠금을 유지함 | 제품 연결의 기본 timeout 약 5초 유지 |
| 분류 | 코드 5는 쓰기 경쟁임. 코드 13은 별도 페이지 제한 실습의 `SQLITE_FULL`임 | 잠금과 용량 문제를 구분함 |
| 실패 영향 | 관련 8개 테이블의 논리 snapshot이 baseline과 같음 | 부분 반영 없음 확인 |
| 복구 | 잠금 소유 프로세스 rollback·close 후 동일 요청 ID·내용·버전으로 두 번 재전송함 | 전체 서비스 재시작 없음 |
| 검증 | 메모 version=2·revision=1·write_request=1, 자료 보존·integrity 정상 | 고정 fixture와 지정 요청 범위 |
| 정리 | 자식 정상 종료·회수, fixture 삭제 | 신규 1회 확인 |

## 4. 검토 결과

신규 1회의 자동 원인 확인은 0.001699초, 조치 시작→복구 확인은 0.028249초임. [기존 3회 원본](20261017_장애진단복구실습_측정원본.json)의 조치 시작→복구 확인 0.020270~0.027527초와 분리해 기록함. 알려진 장애를 자동 해제·검사한 시간이며 사람의 진단 능력·운영 MTTR·RTO/RPO 근거로 사용하지 않음. 구현·독립 검토 내역은 [기존 검증 결과](20261017_장애진단복구실습_검증결과.md)를 참조함.

## 5. 확인 필요 사항

사용자 직접 RCA, 운영 알림·HTTP 오류 처리·실사용자 영향은 미검증임. FULL의 페이지 제한 실습은 호스트 디스크 ENOSPC 증거가 아님.

## 6. 후속 조치
