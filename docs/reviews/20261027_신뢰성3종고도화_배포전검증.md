## 2. 핵심 요약

HTTP 200과 의존 검색의 부분 실패를 구분하는 지표를 추가함. 기존 Prometheus 보존·일일 collector를 유지하며 완료 UTC 일자의 원본을 별도 저장하는 도구와 중지된 신규 PVC/CronJob 설치 자산을 준비함. 기존 Docker 경계를 재사용해 새 볼륨·컨테이너의 합성 Book 복원과 제한된 RTO/RPO 관측을 구현함.

운영 적용은 배포 전 대상·검증·순서 보고 및 유효 승인 확인 전 수행하지 않음. 같은 Mac/daemon의 합성 복원을 실제 N100 백업의 독립 호스트 DR나 운영 데이터 RPO로 표현하지 않음.

| 무결성 | 구조·날짜·원본 시각·SHA256·압축/해제 상한 검증 | 체크섬은 서명·위조 방지 보장이 아님 |
| 보존·공간 | 35일 경계·8MiB/일 상한·compressed quota384MiB·free reserve64MiB, 신규 PVC2Gi | 실제35일 완전 관측이 이미 존재한다는 뜻 아님 |
| 만료 | 명시 prune 시 전체 검증된 만료 파일만 삭제 | 경계일 유지·교체 파일 retained FD/inode 대조. 꽉 찬 과거 보관분은 별도 prune-expired 가능 |
| 실패 | 모르는 파일·손상·권한/link·quota·동일일자 충돌은 보류, HTTP protocol/deflate 오류도 고정 실패 | crash pending/link는 소유/지문 확인 후 복구. 임의 삭제·우회 없음 |
| 네트워크 | 내부/loopback endpoint, redirect 거부·bounded read1, 협력적45초 예산·I/O10초 | DNS/대기 I/O까지 hard45초 보장 아님. Job activeDeadline180초·종료 grace20초 별도 |

[신규 설치 명세](../../infra/k8s/slo-evidence/archive/cronjob.yaml)는 suspend=true·image pending·pull Never의 안전 기본값임. 검증된 immutable 이미지로 준비하기 전 활성화하지 않음. UID/GID10001·read-only root·cap drop ALL이며 Secret/API token mount는 없음. 외부 비협조 writer의 stat/unlink 사이 동시 조작까지 원자적으로 차단하지는 않음.

실제 UTC10/24~10/26의 각 replica5,760점을 읽어 저장·재검증함. available0은2·2·6점, unknown0임. 당시 검색 series가 없어 empty_or_missing으로 보존함. 자료는 `/tmp/reliability-phase2/inputs`, `observations`, `observation-results.json`이며 3일 확보·나머지 missing·시간 기반 SLO 산정 불가로 판정함. N100에는 GET만 수행했으며 신규 예약/Pod·소스 동기화·Secret 조회는 하지 않음.

### 3.3 새 목적지 복원

| 단계 | 검증·측정 | 비고 |
|---|---|---|
| 원본/복원점 | 소유 source volume의 합성 Book seed→bounded snapshot→추가 실제 ACK 쓰기1건 | 운영 DB·Secret·OAuth 사용 없음 |
| 손실/새 목적지 | source stop 확인 후 새 container/volume, source mount 미참조 증거 | source volume는 cleanup까지 보존 |
| 복원/검사 | 고정64KiB 이내 JSON·고정 테이블 트랜잭션·FK, exact snapshot/schema/supporting hash·HTTP health/ready·기능 읽기 | 임의 SQL/경로/URL 불허 |
| 이미지/설정 | 고정 Git 이미지와 허용 설정 SHA256 | image archive export/import·독립 호스트 공급은 not_exercised |
| RTO | source stop 확인→새 목적지 준비·읽기·데이터 검증 완료 | 탐지·물리 호스트/Secret 공급을 포함한 전체DR RTO 아님 |
| RPO 근거 | snapshot 포함 쓰기/후속 ACK 간격, 실제 유실1건, loss 시점 snapshot 나이 각각 기록 | snapshot age를 실제 운영 RPO로 치환하지 않음 |
| 실행/정리 | network none·포트 미공개·UID10001·read-only root, 기록ID/owner로 container→volume→image 정리 | 출력/JSONL 오류도 cleanup을 우회하지 않음. daemon 설정·V2 리소스·prune 미변경 |

[새 실행기](../../book-memo/tools/independent_restore_lab.py)는 기존 [Docker adapter](../../book-memo/tools/container_runtime.py)를 재사용함. 실제 source/image/container/volume·수치·JSON/JSONL은 PR에 고정하며 단위 검사 PASS를 실제 Docker 복원 PASS로 대용하지 않음.

실행 준비에서 Docker socket이 없어 기존 로컬 엔진이 꺼져 있음을 확인하고 OrbStack를 시작함. 엔진 reset·설정 변경·K3s 재시작 명령·V2 리소스 적용은 수행하지 않음.

| 역할 | 담당·모델 | 비고 |
|---|---|---|
| root | 관측 보존·통합·문서·실행/배포 준비 | 자기 검증 |

| reliability_phase2_review | 전체 diff·원본·실측·보안·운영 경계, gpt-6.1-sol high | 구현·테스트 실행에 참여하지 않는 최종 검토 |

같은 파일 동시 수정 없음. 초기 Book 통합 실패에서 새 import가 단독 로더를 깨뜨린 회귀를 확인하고 단일파일 stdlib 계측으로 보완함. 새 Dockerfile을 기존 digest 거버넌스 대상에 추가해 예외 제외하지 않음. 출력 실패 cleanup, quota/만료, 교체 파일, bucket 표기 및 protocol/deflate 오류를 보완·재검토함. 최종 커밋·전체 검사·실제 실행·strict receipt·PR/main CI는 PR의 최종 기록에서 구분함.

## 6. 후속 조치

일반 개발·검증·독립 검토·PR/CI·안전한 병합과 배포 준비를 진행한 뒤 실제 운영 변경 직전에 소스/이미지·검증·대상·실행 순서·원복/제외 범위를 한 번 보고함. 운영 승인 확인 전 N100 동기화·이미지 반입·Deployment 교체·PVC/Job 생성·예약 활성화는 수행하지 않음.
