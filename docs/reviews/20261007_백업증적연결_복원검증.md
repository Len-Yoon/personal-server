# Portal 백업 증적 연결 및 격리 복원 검증

이 문서는 당시 설계·검증 기록임. 최신 Portal 증적 연결·새 Production 인증·실제 백업/복원·소비자 갱신 결과와 남은 확인 사항은 [2026-10-08 실패 복구 기록](20261008_Portal백업_실패복구.md) 및 [후속 완료 상태](20261008_백업장기인증_배포진행현황.md#7-production-인증-및-실패-복구-후속-완료)를 따름. 당시 미수행·보류·원본 증적은 역사로 보존함.

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-10-07 | Asia/Seoul |
| 목적 | 실제 암호화 백업 증적을 SystemAgent에 연결하고 격리 복원으로 확인함 | 운영 데이터 덮어쓰기 없음 |
| 승인 | 사용자 `진행해 승인할게` | 백업 증적 연결·격리 복원 범위 |
| 기준 | 기존 Portal PVC 백업 생산자·증적 검증 계약 | 기존 증적을 재작성하지 않음 |

## 2. 핵심 요약

기존 백업 생산자의 authoritative ConfigMap 증적을 그대로 검증·원자 게시하고, SystemAgent가 전용 디렉터리를 읽기 전용으로 참조하도록 함. 별도 일회성 복원 Job은 기존 암호화 객체만 내려받아 scratch에서 검증하며 운영 PVC를 사용하지 않음. 실제 적용·최종 CI 결과는 저장소 반영 이후의 로컬 운영 완료 기록을 따름.

## 3. 상세 내용

| 경계 | 처리 | 비고 |
|---|---|---|
| 원본 | 고정 `personal-server/portal-pvc-backup-evidence` ConfigMap | 원본 바이트·ID·시각·만료 보존 |
| 검증 | 24시간 나이·원본 만료·k3s-pvc·두 SHA256·명시적 복원 검사 성공 필수 | 만료를 연결 시각으로 연장하지 않음 |
| 게시 | 운영자가 `export-portal-backup-evidence.py --output-dir <증적 디렉터리>` 실행 | root/앱에 API 자격 증명 추가하지 않음 |
| 출력 보호 | 운영자 소유, 다른 사용자가 쓰지 못하는 디렉터리, 증적 0444, 원자 교체 | symlink·비정규 파일·hardlink 거부 |
| 소비 | SystemAgent `BACKUP_EVIDENCE_PATH`, 디렉터리 ro bind | 기존 `/data:ro`·이미지·인증·네트워크 보존 |
| 복원 | `portal-backup-restore-job.py`로 immutable 기존 백업 이미지의 Job 렌더 | production PVC·hostPath·API token 없음 |
| 자격 증명 | 기존 Secret 세 키는 ro mount, 암호화 rclone config만 Memory 16Mi 전용 scratch에 0600으로 복사 | passphrase·identity 복제 및 비밀값 출력·환경 변수 저장 없음 |
| 검증 순서 | 암호문 digest → 복호화 → 안전한 tar 추출 → manifest·두 tree digest → SQLite quick_check | 새 백업 업로드·원본 증적 갱신 없음 |
| 추출 보호 | 절대 경로·상위 경로·중복·링크·장치·sparse·과대 archive 거부 | scratch emptyDir만 쓰기 |

`BACKUP_EVIDENCE_DIRECTORY`는 운영자 소유의 전용 증적 디렉터리로 지정함. 기본 개발 경로는 `./data/system/backup-evidence`이며 bind의 `create_host_path: false`로 누락된 경로를 자동 생성하지 않음. 게시 실패는 FAIL이며 이전 snapshot의 원본 만료는 그대로 유지함. 현재 권한으로 증적을 읽지 못하거나 만료되면 SystemAgent는 `backup_unverified`로 판정함.

| 구현 담당 | 격리 복원 checker·회귀 테스트 | GPT-6.1 Sol 중간 추론, 독립 구현 경계 |
| 독립 전문 검토 | 증적·자격 증명·데이터·복원·운영 적용 전후 | GPT-6.1 Sol 높은 추론, 구현과 분리 |

전체 9개 검사 묶음과 문서 계약·정적 검사·독립 검토를 수행한 뒤 필수 PR/main CI를 확인함. 최종 검증 수와 결과는 PR의 공개 코드 검증 기록을 따름. 운영 구성·상세 증적은 로컬 완료 기록으로 보존함.

### 4.1 최초 PR #345 로컬 검증

| 검사 | 결과 | 비고 |
|---|---|---|
| 전체 9개 묶음 | 최종 유효 결과 2,080건 통과 | 앱596·K8s884·유지보수600 |
| 대상 회귀 | 29건 통과 | 원본 보존·만료·권한·경로·WAL·Job 경계 |
| 매트릭스 계약 | 28건 통과 | 신규 모듈 두 개의 기대 목록 동기화 |
| 문서 계약·링크 | 29건 통과 | 기존 링크 보존 |
| 독립 전문 검토 | 미해결 P1/P2 없음 | 코드와 실행 전 운영 도구 검토 |
| 서버 dry-run | Job spec 비교 통과 | 실제 리소스 생성 없음 |

검토 중 코드가 수정된 최초 인프라 실행은 이전 expiry 테스트 조건과 새 코드가 혼합되어 실패했으며 해당 묶음의 결과를 폐기함. 최종 소스의 새 프로세스에서 인프라884건을 재검증함. 유지보수 최초 실행의 새 테스트 모듈 기대 목록 누락은 목록을 동기화한 후 전용28건·유지보수600건 재검증으로 해소함. 변경 영향을 받지 않는 앱 결과는 재사용하며, Book은 아래 CI 보완 후75건을 재검증함. 최초 실패를 성공으로 소급하지 않음.

PR CI에서 Book 테스트 서버가 HTTP 헤더 전 EOF를 종료 건수에 반영하지 못하는 오류를 재현함. 앱 코드와 검색 시간 제한은 유지하고 fixture를 보완해 기존 두 연결 종료·0.5초 제한·잔여 task 없음 검사를 보존함. 결정적인 EOF 회귀를 추가한 Book75건과 독립 관련7건을 통과함.

## 5. 확인 필요 사항

- 수동 snapshot 방식이며 새 scheduler·bootstrap·상시 동기화 서비스를 추가하지 않음. 새 원본 증적이 생성돼도 export를 실행하기 전에는 이전 snapshot을 표시하며, 원본 만료 후 미검증 상태로 돌아감.
- 정기 백업의 suspend·일정은 이 작업에서 변경하지 않음. 자동 백업·자동 증적 갱신 활성화는 별도 범위임.
- 격리 복원은 백업 객체의 내용·해시·SQLite 무결성을 확인하며 운영 데이터 교체나 실제 장애 복구를 수행하지 않음.
- 단일 N100 호스트·디스크·네트워크 장애까지 해결하는 고가용성 검증은 아님.

## 6. 후속 조치

유효한 원본의 export와 격리 복원 PASS를 먼저 확인한 뒤 SystemAgent만 기존 이미지로 재생성함. 전후 원본 CM·CronJob·Secret/PVC·운영 데이터·비대상 컨테이너를 보존하고, 앱 UID의 증적 읽기·쓰기 차단 및 `/metrics`의 `backup_verified`를 검증함. Portal 외부 health를 10초 간격으로 3회 확인함. 불완전한 원격 응답은 실제 상태부터 조회하며, 실패 시 해당 SystemAgent의 mount/env만 원복하고 운영 데이터를 덮어쓰지 않음.


## 7. 후속 수정: 암호화 설정의 임시 메모리 갱신

최초 저장소 반영 후 실제 격리 검증의 외부 명령 실패로 소비자 연결을 보류함. 진단에서 읽기 전용 파일시스템 오류 패턴을 확인했으며, 원문을 보존하지 않았으므로 설정 갱신과의 인과 및 실제 복원 성공은 후속 검증 대상으로 남김. 사용자 `응 진행해 어떻게든 고쳐야 하잖아 다 승인할테니 고쳐봐`로 암호화 설정의 임시 메모리 복사·추가 복원 검증·수정 반영과 운영 적용이 승인됨. 이미 병합된 PR #345의 운영 검증에서 발견된 문제이므로 후속 수정 PR로 추적함.

| 보완 경계 | 구현 | 비고 |
|---|---|---|
| 원본 | projected Secret 단일 open·fstat 정규 파일·1MiB 제한 읽기 | 검증한 동일 바이트만 복사, 원본 재작성 없음 |
| 임시 설정 | 별도 tmpfs 전용 mount, Memory 16Mi·디렉터리 0700·파일 0600 | config와 데이터 scratch 분리, 디스크 경로 거부 |
| 암호화 | 첫 유효 행의 RCLONE_ENCRYPT_V0 marker 검사 | 평문 config 복사 거부, 암호화 해독은 rclone만 수행 |
| 갱신 | rclone --config만 임시 설정으로 변경 | passphrase·identity는 원본 Secret ro 참조 |
| 사후 검사 | O_NOFOLLOW·fstat 정규 파일·현재 UID·0600·암호화 marker·원본 바이트 불변 | provider 성공·실패 모두 확인 |
| 정리 | context exit에서 임시 config 삭제, Job 삭제로 memory volume 제거 | 신규 영속 자격 증명·Secret 수정 없음 |
| 원본 보존 | 기존 증적 시각·만료·digest·Secret·PVC·writer·Cron 상태 유지 | 자동 백업 활성화 제외 |

주 담당이 후속 checker·renderer·회귀·문서를 구현하고 GPT-6.1 Sol 높은 추론의 전문 검토 담당이 diff·검증·운영 전후 상태를 독립 검토함. 같은 파일 동시 수정은 하지 않음. 단일 기능의 공용 경계 보완이므로 별도 구현 에이전트를 추가하지 않음.

후속 대상 단위 35건이 통과함. 평문·과대 설정·tmpfs가 아닌 경로·상위/하위 중첩 경로·원자적 Secret 전환·쓰기 후 평문/권한/링크 퇴행·원본 보존·실패 정리 및 기존 archive/WAL 검사를 포함함. Mac /var → /private/var 경로 정규화에 따른 테스트 비교 실패는 resolved 경로로 비교하여 보완함. 실제 provider 접근·OAuth 갱신·격리 복원·소비자 연결 성공은 로컬 운영 검증 기록에서 별도로 확인함.

## 8. 후속 수정: 단일 파일 복사와 크기 필터의 충돌

PR #346 후 후보 인증의 파일 메타데이터 조회는 성공했으나, 실제 다운로드는 복호화 전에 종료됨. [rclone v1.60.1 단일 파일 처리](https://github.com/rclone/rclone/blob/v1.60.1/cmd/cmd.go)와 [필터 판정](https://github.com/rclone/rclone/blob/v1.60.1/fs/filter/filter.go)에서 단일 파일 `copyto`가 활성 필터를 거부하며 양수 `--max-size`가 해당 필터를 활성화함을 확인함. N100의 설치 바이너리·패키지 무변경 검사 후 비밀값 없는 작은 로컬 파일로 같은 옵션 충돌과 대안을 검증함. 이 재현은 실제 원격 백업 다운로드 성공과 구분함.

| 경계 | 보완 | 비고 |
|---|---|---|
| 특정 파일 선택 | 기존 backup ID의 단일 객체 `copyto` 유지 | 디렉터리 전체 복사·새 객체·업로드 없음 |
| 호환성 | `--max-size` 필터를 제거하고 같은 상한의 `--max-transfer --cutoff-mode hard` 사용 | `--buffer-size 0`·`--multi-thread-streams 0` 적용 |
| 파일 쓰기 상한 | rclone 자식 프로세스에 같은 크기의 `RLIMIT_FSIZE` 적용 | 부모 한도 변경 없음, 더 엄격한 기존 한도 보존 |
| 내용 검증 | 기존 파일 크기·암호문 SHA·age·manifest·source digest·SQLite 검사 유지 | 실패 시 후속 단계 진행 없음 |
| 자격 증명·증적 | 암호화 config만 임시 Memory에 복사, 원본 Secret·시각·만료·digest 보존 | 새로운 운영 Secret·writer·Cron 변경 없음 |
| 네트워크 한도 | hard transfer와 kernel 파일 상한을 결합함 | 버퍼 읽기 때문에 실제 네트워크 수신량의 정확한 바이트 상한으로 표현하지 않음 |

같은 N100 바이너리의 로컬 시험에서 기존 옵션의 정확한 필터 거부·출력 파일 미생성, 대체 옵션의 복사·SHA 일치, 1KiB 경계 성공, 초과 실패·파일 상한 및 임시 자원 정리 모두 통과함. 실제 백업 객체와 Secret은 사용하지 않음.

주 담당은 브랜치·전체 검증·문서·운영 검증을 맡고, GPT-6.1 Sol 중간 추론의 구현 담당은 checker·회귀 테스트만 수정하며, GPT-6.1 Sol 높은 추론의 전문 검토 담당은 diff·파일 상한·보호 경계를 독립 검토함. 같은 파일 동시 수정 없음. 실제 후보 복원, 장기 OAuth 수명, 운영 Secret 적용·소비자 연결은 별도의 로컬 운영 결과에서 구분하며, 사용자 요청에 따라 운영 배포 전 보고함.

저장소 구현은 복원 회귀29건을 통과했고 전문 검토는 복원·export40건을 독립 실행하여 통과함. 실제 자식 프로세스의 경계 크기 성공·초과 실패·더 엄격한 상속 한도·부모 한도 불변을 포함함. 미해결 P1/P2 없음. 전체 9개 묶음 2,092건(앱596·K8s896·유지보수600) 통과함. 필수 CI·실제 후보 복원 결과는 후속 결과와 PR 원본에서 확인함.
