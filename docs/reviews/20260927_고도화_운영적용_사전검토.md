# 고도화 변경의 N100 운영 적용 사전 검토

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-09-27 | Asia/Seoul 기준 |
| 기준 자료 | PR #270~#280, `docs/20260921_프로젝트보완_개발계획.md`, 각 서비스의 백업 설계·검증 문서 | 문서 PR과 최종 main 커밋·CI 재확인 필요 |
| 목적 | 저장소 반영과 실제 N100 운영 적용을 분리하고, 한 번의 운영 승인에 포함할 대상·순서·중단 조건을 명시함 | 이 문서 작성 자체는 운영 변경이 아님 |

## 2. 핵심 요약

Portal 검색 계측, Relay 갱신 도구·백업 상태/Job 실패 알림, Book·YouTube·Crawler PVC 백업 도구는 저장소에 반영됨. YouTube 타임스탬프·편집 인증 PR #270은 병합 시 N100 자동배포 workflow를 시작하므로 운영 승인 전 병합하지 않음. 세 백업 CronJob은 저장소에서 `suspend: true`이고 미설정 이미지로 배포 차단됨. N100 저장소 동기화·이미지 반입·K3s 리소스 적용·새 백업 수동 검증·자동 실행 활성화는 아직 수행하지 않음.

## 4. 제안 실행 순서와 성공 기준

| 순서 | 동작 | 확인 기준 |
|---:|---|---|
| 1 | 승인 대상 PR·커밋, PR/main CI·Trivy·Agent Review, 자동배포 classifier를 재확인함. N100 브랜치·커밋·작업 트리·runtime marker·단일 writer·리소스 UID를 읽기 전용으로 확인함 | 미확인 또는 예상 밖 변경이 있으면 해당 단계 중단 |
| 2 | 운영 승인 뒤 YouTube PR #270을 병합하고 Deploy N100 workflow의 실제 분류와 self-hosted 실행 결과를 확인함 | K3s 소유 서비스의 Compose 변경이 발생하지 않아야 함 |
| 3 | N100 저장소를 승인된 커밋으로 fast-forward하고, 각 앱·Relay·백업 이미지의 amd64 산출물 digest를 검증해 순차 반입함 | 강제 reset·기존 작업 덮어쓰기 없음 |
| 4 | Relay 읽기 전용 RBAC와 이미지 갱신을 먼저 검증한 뒤 Portal·YouTube 이미지를 각각 단일 Deployment의 이미지 항목만 교체함 | 원래 imageID 기록, Ready 1/1, Portal 및 변경 서비스 외부 health 각 10초 간격 3회 |
| 5 | 세 서비스 전용 Secret의 4개 key·원격 prefix 권한을 준비함. 상태 ConfigMap은 없을 때만 bootstrap하고, 중지 상태 CronJob/RBAC를 적용함 | Secret 값의 파일·환경 변수·로그·Git 복제 없음. 기존 lock·증적 덮어쓰기 없음 |
| 6 | Book→YouTube→Crawler 수동 Job을 한 번씩 실행함. 각 서비스의 writer 중지·재가동, 원격 암호문 업로드·재다운로드, 격리 복원·해시·원본 검사와 외부 health를 확인함 | 서비스별 `backup_status=success`, `restore_status=success`, 잠금 해제와 실제 Job 성공 확인 |
| 7 | Job 실패 감시의 RBAC·Relay health·수동 실패 시나리오 알림을 확인한 뒤에만 CronJob 자동 실행을 활성화함 | 실패 감시·수동 Job 성공·실제 알림 중 하나라도 미확인인 서비스는 `suspend: true` 유지 |

작업 중 Deployment UID·PVC UID·runtime marker·Secret 또는 원격 권한이 달라지면 관련 서비스의 다음 동작을 보류함. image 교체 실패는 기록한 원래 imageID로 해당 서비스만 rollback하고, 백업 실패는 CronJob을 중지한 채 잠금·원격 암호문을 보존해 원인을 확인함. 전체 K3s 재시작이나 중복 writer 실행은 수행하지 않음.

## 6. 확인 필요 사항

| 항목 | 확인 필요 내용 |
|---|---|
| 서비스별 자격 증명 | Book·YouTube·Crawler 전용 Secret을 승인된 암호화 저장소에서 시딩할 출처와 각 원격 prefix의 최소 권한·공유 ACL 확인 필요. 기존 Portal Secret을 새 Pod에 직접 mount하지 않음 |
| 백업 복구 경계 | mode·UID/GID·ACL·xattr, 앱 UID 쓰기 가능성, WAL 논리 일관성은 로컬 격리 복원 테스트만으로 확인되지 않음. 운영 수동 Job·복구 drill 확인 필요 |
| Job 감시 공백 | PR #280은 Job terminal 실패 감시를 추가했고 PR CI·Trivy·Agent Review를 통과함. Relay 장기 중단이나 Job TTL 만료 뒤에는 놓칠 수 있어 운영 감시와 보존 기간 확인 필요 |
| 30일 SLO | Prometheus 7일 보존과 공개 감시 실행·원시 결과 누락으로 정확한 30일 SLI·에러 버짓 산정 불가 |

## 7. 후속 조치

1. 모든 PR·main 검사를 완료하고 문서의 병합 커밋·운영 상태를 최신화함.
2. N100 운영 적용 대상·동작·순서·자격 증명 출처를 하나의 최종 승인 요청으로 제시함.
3. 승인 범위 안에서 순차 적용하고 `저장소 병합 / N100 동기화 / 이미지 반입 / 수동 검증 / 자동 실행 활성화 / 외부 health`를 별도로 기록함.
