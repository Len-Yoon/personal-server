## 2. 핵심 요약

Google Drive 백업 루트와 세 서비스 폴더·최신 암호문의 권한 메타데이터를 확인함. 조회 대상은 모두 소유자만 접근 가능하고 공유되지 않은 상태였음. 각 서비스에 같은 이름의 폴더가 두 개씩 발견되어, 내용이 없는 이전 폴더 3개만 ID로 지정해 고유한 이름으로 변경함. 삭제하거나 백업 암호문을 이동하지 않았음. 변경 후 서비스별 원래 이름의 폴더는 각각 하나이며, 최신 암호문이 있는 폴더 ID와 일치함.

Mac에서 받은 YouTube 암호문의 SHA-256이 N100 최신 백업 증적과 일치함. N100의 기존 age identity와 Mac 로그인 키체인 저장본이 일치함을 별도 프로세스로 다시 확인하고, 동일 키를 프로세스 메모리에서 Mac의 `age`에 전달해 암호문 복호화·tar 형식 검증을 통과함. 평문과 키를 파일·명령 인자·로그에 저장하지 않았음. 이 검증은 Mac에서의 복호화 가능성을 입증하지만, Mac 분실 시 별도 기기에서 키체인 항목을 복구할 수 있는지는 확인하지 않음.

세 CronJob은 여전히 `suspend: true`, active Job 0건이며, 기존 성공 증적과 잠금 해제 상태를 유지함. 중지 해제 시 놓친 일정의 즉시 실행 가능성을 제한하도록 저장소 CronJob에 `startingDeadlineSeconds: 300`을 추가해 검증 중임. 실제 N100 CronJob 설정·자동 실행은 변경하지 않았음.

## 3. 검증 결과

| 항목 | 결과 | 비고 |
|---|---|---|
| 원격 공유 범위 | 확인 | 백업 루트·세 서비스의 작업 폴더·최신 암호문은 `shared=false`, 권한 목록은 소유자 1건. 외부 계정으로 접근을 시도한 별도 시험은 미수행 |
| 중복 폴더 | 해소 | 각 서비스의 빈 이전 폴더만 이름 변경. 원래 서비스명 폴더가 각 1개이며 최신 암호문 보유 폴더와 ID 일치. 삭제·파일 이동 없음 |
| Mac 복구키·암호문 | 통과 | 키체인 저장본과 N100 원본 일치, 내려받은 암호문과 N100 SHA-256 증적 일치, Mac `age` 복호화·tar 형식 확인 |
| Relay 상태 알림 | 일부 확인 | Relay 1/1. 과거 Book 실패 상태 2건은 Telegram API 성공 응답 뒤 기록된 전달 이력으로 확인. 수신자 단말의 도착·열람은 미확인 |
| CronJob Job 실패 알림 | 미검증 | CronJob 소유 실패 Job의 실제 전달 이력 0건. 기존 수동 Job은 이 감시 대상이 아님. 운영 실패를 인위적으로 만들지 않음 |
| 자동 백업 | 중지 유지 | 세 CronJob `suspend: true`, active Job 0건. 시작 마감 설정은 저장소에서 준비 중이며 N100 미적용 |
| 보존 삭제 | 미수행 | 현재 확인한 서비스별 작업 폴더에는 암호문이 각각 1개이므로 30일·최근 7개 기준의 삭제 후보 없음. 영구 삭제 경로의 폴더·파일 ID 고정 검증은 별도 필요 |

## 4. 자동 실행 전 적용·검증 순서

1. 시작 마감 설정의 저장소 PR·필수 CI·독립 검토를 완료함. 병합된 설정은 N100에서 각 CronJob의 `startingDeadlineSeconds` 필드만 검증·적용하고 `suspend: true`를 유지함.
2. Google Drive 부모 폴더를 다시 조회해 서비스별 이름 중복 0건과 최신 암호문 보유 폴더 ID 일치를 확인함. 세 서비스의 Secret key 수, 고정 이미지 digest, 단일 Ready writer, PVC Bound, 잠금·현재 백업 증적, Relay 상태와 외부 health를 재확인함.
3. 각 서비스의 예정 시각 뒤 300초 이내를 피해 CronJob을 하나씩 중지 해제함. 매번 신규 Job·Pod의 예상치 않은 즉시 생성 여부와 단일 writer·잠금·외부 health를 확인하고 이상 시 다음 서비스로 진행하지 않음.
4. 다음 정기 실행의 Job 성공·복원 증적·Relay 전달 상태를 확인함. 300초를 넘겨 놓친 실행은 Job이 생성되지 않아 기존 Failed Job 알림만으로는 감지할 수 없으므로 신선도 감시가 필요함.

## 5. 검토 결과

주 담당은 Drive 객체 ID·빈 폴더·공유 권한·Mac 복호화·N100 증적 일치를 확인하고 설정 변경을 테스트 우선으로 준비함. 독립 운영·보안 검토는 N100의 CronJob·Relay 현황, 놓친 일정의 즉시 실행 조건, 이름 중복과 영구 삭제 위험, 설정 diff와 회귀 테스트를 확인함. 같은 파일의 동시 수정은 없음.

## 7. 후속 조치

자동 실행의 N100 적용·중지 해제는 설정과 사전 검증 완료 후 별도 운영 승인 범위에서 진행함. 보존 삭제는 후보가 없으므로 실행하지 않으며, 향후 후보가 생기면 삭제 대상 ID 검증과 사전 preview를 별도로 수행함.
