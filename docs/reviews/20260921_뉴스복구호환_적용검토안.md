## 핵심 요약

구 버전으로 단순 복구하면 새 버전의 `telegram_outbox` 필드가 다음 archive 저장에서 삭제됨. 구 버전에 해당 필드를 그대로 보존하는 2줄을 추가한 복구 호환 이미지를 먼저 적용하고, 그 이미지를 10차 배포의 복구 기준으로 사용하도록 제안함.

## 상세 내용

| 순서 | 동작 | 성공 기준·비고 |
|---:|---|---|
| 1 | 현재 이미지·신뢰 가능한 runtime marker·Docker writer·기존 archive의 outbox 존재 여부를 읽기 전용 확인 | 이미 outbox가 있으면 최초 구 이미지로의 복구도 재판단 필요 |
| 2 | 기존 소스 879966f에 첨부된 2줄 보존 패치만 적용한 호환 이미지 반입 | OCI SHA-256 및 linux/amd64 확인 |
| 3 | 기존 이미지에서 호환 이미지로 image-only 교체 | Recreate 1개, 이미지 외 Deployment spec·PVC 유지, Portal·뉴스 외부 health 각 3회 |
| 4 | 호환 이미지를 expected-current-image로 지정하여 2482f80 이미지 적용 | 실패 시 호환 이미지로 1회 복구 |
| 5 | 목표 이미지·실행 코드 해시·단일 writer·외부 health 검증 | 대기 목록을 출력하거나 운영 데이터를 임의로 쓰지 않음 |

변경은 `load_archive()`가 `telegram_outbox`가 존재할 때 값을 그대로 되돌려 주는 것으로 한정함. 알림 발송·수집·스케줄·기존 데이터 형식·소유권·공개 경로는 변경하지 않음.

```python
if "telegram_outbox" in data:
    archive["telegram_outbox"] = data["telegram_outbox"]
```

## 확인 필요 사항

이 이미지는 기존 운영 소스에 최소 보존 패치를 더한 별도 복구용 빌드임. 단순히 최신 main 이미지를 한 번 교체하는 절차에 비해 중간 이미지 적용 1회가 추가됨. 보존 패치는 이미 발송한 알림의 중복 방지나 정확히 한 번 전송을 보장하지 않음. 응답·저장 유실에 따른 기존 중복 가능성은 유지됨.
