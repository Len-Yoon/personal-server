| 항목 | 내용 | 비고 |
|---|---|---|
| 기준일 | 2026-09-21 | 사용자 표시 시각은 서울 기준 |
| 승인 범위 | PR #234 병합·차량 서비스 자동배포·운영 검증 | 승인 유지 |
| 현재 상태 | 병합·운영 배포 보류 | 기존 Docker health 오탐 |

## 확인 결과

- N100 추적 파일 무변경, 현재 소스 879966f 확인함.
- Portal·차량 외부 health 각각 10초 간격 3회 200임. 차량 내부 HTTP도 200임.
- Docker health는 unhealthy이며 최근 검사가 모두 5초 제한을 초과함. 실제 검사 실행은 약 6초, Python import·HTTP 구간은 4.3초로 측정됨. Docker restart 0, OOM 없음.
- 운영 DB quick_check 정상이며 기존 4개 업무 테이블을 확인함. 명령 결과 보조 테이블은 아직 없음.
- OAuth 볼륨 ownership은 기존 서비스 UID/GID와 일치함. 업무 데이터 bind ownership은 기존 안전 배포 도구의 정렬 대상임.

## 최소 보완안

차량 서비스에 한해 Docker health timeout을 5초에서 15초로 조정하고 urllib HTTP 요청 timeout을 3초로 명시함. 검사 주기 30초·재시도 3회·공개 경로·CPU/메모리·다른 서비스 설정은 유지함. 늦어진 검사로 장애 판정이 지연될 수 있지만 요청 자체의 대기를 제한함.

Compose 변경은 안전 자동배포 대상이 아니므로 PR #234에 섞어 분류를 바꾸지 않음. 별도 변경으로 검증한 후 운영 설정 동기화·차량 컨테이너 재생성 승인 범위에서만 적용함. 정상 Docker health 기준을 확보한 뒤 기존 승인된 PR #234 배포를 진행함.

## 확인 필요 사항

사용자가 보완 설정 저장소 반영·N100 적용·차량 재생성·실패 시 원복과 이후 9차 배포 진행을 명시 승인함. 현재 적용 준비 단계임. 운영 비밀값·OAuth 데이터·DB 행은 수정하지 않음. 이 보완의 운영 적용에는 N100 Compose 설정 동기화와 차량 컨테이너 재생성이 포함됨. 실패 시 이전 5초 설정을 복원하고 차량 컨테이너를 재생성하며 PR #234 배포는 계속 보류함. 기존 safe deploy의 자동 rollback은 앱 source만 되돌리고 현재 Compose를 사용하므로 이 설정 복원은 별도 수동 절차임.

## 보완안 검증 결과

필수 8개 서비스·maintenance 묶음 전체 통과함. Compose 구조 비교에서 차량 health timeout 및 HTTP 요청 timeout 두 항목만 변경됨을 확인함. diff·하네스 및 독립 운영 검토 통과함. 실제 실행 중인 차량 컨테이너에서 보완 HTTP 검사 명령을 읽기 전용으로 수행하여 15초 제한 안의 10초에 HTTP 200 성공함. 설정 반영·재생성·PR #234 병합은 아직 수행하지 않음.
