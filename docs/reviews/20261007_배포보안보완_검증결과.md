## 2. 핵심 요약

기존 최종 이미지의 OS/Python 취약점 검사가 실패하여 N100 동기화·반입·서비스 교체 전에 차단함. Portal·Book·YouTube·Crawler 각각 HIGH 66·CRITICAL 3건, 실행기·SystemAgent 각각 HIGH 64·CRITICAL 3건이었음. 각 이미지에는 수정 버전 미제공 44건이 포함됨. 수치는 패키지-CVE 발견 건수이며 같은 CVE의 여러 패키지 발견을 포함함.

보안 검사를 완화하거나 OS 패키지 DB를 삭제하지 않고, Python minor를 유지한 공식 Alpine 기반과 호환 Python 의존성으로 보완함. 실제 운영 적용 결과는 이 문서의 저장소 반영 시점 이후에 결정되며, [관련 PR 원본](https://github.com/Len-Yoon/personal-server/pulls?q=is%3Apr+image-security-remediation)에서 최종 CI·병합·N100 결과를 확인함. 이 문서는 저장소 반영 전의 검증 기록임.

공식 [FastAPI 의존성](https://github.com/fastapi/fastapi/blob/0.142.2/pyproject.toml)과 [Starlette 변경 이력](https://starlette.dev/release-notes/)을 확인함. [Starlette 보안 공지](https://github.com/Kludex/starlette/security/advisories/GHSA-82w8-qh3p-5jfq)의 수정 버전과 호환 범위를 함께 적용함. [Debian util-linux](https://security-tracker.debian.org/tracker/CVE-2026-76642)·[ncurses](https://security-tracker.debian.org/tracker/CVE-2025-69720)의 미수정 상태와 실제 최신 slim 후보 스캔을 대조하여, 이전 기반의 단순 업데이트만으로 성공을 주장하지 않음.

## 4. 검토 결과

| 역할 | 담당 범위 | 모델·비고 |
|---|---|---|
| 주 담당 | 템플릿·빌드 도구·정책 계약·통합·배포 | 같은 파일 동시 수정 없음 |
| 구현·이미지 담당 | 6개 Dockerfile/requirements·후보 및 최종 이미지·호환성 smoke | GPT-6.1 Sol 중간 추론, 독립 이미지 준비 |
| 전문 검토 | OS/의존성·파일 원자 이동·복구 명령·데이터·운영 경계 | GPT-6.1 Sol 높은 추론, 구현과 분리 |

Alpine 후보에서 libc `renameat2`, 실제 exclusive move/trash/restore·충돌 시 원본 보존, SQLite backup/quick_check, TLS·DNS, Asia/Seoul, Python·BusyBox 복구 도구를 확인함. 운영 Pod의 DB·사용자 파일에는 시험 데이터를 넣지 않음. 서비스별 격리 환경과 전체 CI 검사는 별도로 수행함.

## 5. 검증 결과

| 검사 | 결과 | 비고 |
|---|---|---|
| 전체 로컬 회귀 | 9개 묶음 2050건 통과 | Portal208·System14·Crawler125·Executor36·YouTube60·Book74·차량78·K8s856·유지보수599 |
| 정책·도구·문서 | 60건 통과 | 마지막 문구 갱신 후 문서 계약·링크를 다시 확인함 |
| 보완 후보 이미지 | 6개 HIGH/CRITICAL 0건 | 작업 트리 후보 결과, 확정 커밋의 최종 이미지 검사는 별도 PR 완료 기록을 따름 |
| 독립 검토 | 소스 및 운영 준비의 미해결 P1/P2 없음 | SystemAgent는 존재하는 /health·metrics 검사, 불완전 응답은 실제 상태부터 확인함 |
| 정적 검사 | Python 구문·git diff 공백 검사 통과 | 운영 실행 없음 |

빈/SINGLE-LF placeholder와 OCI directory 입력 실패를 각각 재현한 뒤 회귀로 확인함. 기존 이미지 준비 실패와 최신 보완 이미지 결과를 혼동하지 않음. 로컬 소켓 제한으로 실패한 최초 샌드박스 실행은 성공으로 재분류하지 않고, 허용된 환경의 전체 재실행으로 확인함.

## 6. 확인 필요 사항

- 실제 사용자 계정의 운영 저장·가져오기·삭제·재시작 POST는 수행하지 않음. 격리 회귀와 읽기 전용 운영 검증을 구분함.
- SystemAgent에 authoritative Portal 백업 증적 파일이 연결되어 있지 않아 `backup_unverified`가 남을 수 있음. 증적·mount를 임의로 생성하지 않음.
- 이번 앱 이미지 검사 통과는 변경 대상 밖의 차량·SRE·백업 이미지 또는 호스트 전체의 보안 완료를 뜻하지 않음.
- 스캔 결과는 당시 Trivy DB 기준이며 새 CVE 발생 후에도 0건을 보장하지 않음.

## 7. 후속 조치

전체 검사·독립 검토·PR/main CI 후 승인된 N100 적용을 수행함. 실제 결과는 저장소 병합 / N100 동기화 / 이미지 반입 / 수동 검증 / 자동 실행 활성화 / 외부 health로 나누어 PR 완료 기록에 남김. 기존 백업·보호 자원·사용자 파일을 보존하며 원복에 운영 DB 덮어쓰기를 포함하지 않음.
