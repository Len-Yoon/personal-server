| 승인 | Caddy 전용 고정 IPv4 bridge, Caddy Portal upstream의 기존 ClusterIP 전환, 같은 이미지로 Caddy만 재생성, 네 앱 정책 순차 생성 및 소유 변경 원복 | 사용자 명시 승인 확인함 |

## 핵심 요약

- 기존 동적 주소의 Book 격리 진단은 운영 고정 출처의 증거로 재사용하지 않음.
- 고정 주소 설정·현재 Caddy 연결·대상 Service 및 Pod·별도 격리 진단을 묶는 `fixed_pre_nat_ip` 검증 계약을 추가함.
- 고정 주소는 설정의 지속성을 의미함. Caddy만의 인증된 신원을 뜻하지 않으며 노드 통신 예외와 기존 egress는 유지됨.
- 운영 적용 및 최종 검증은 확인 필요임. 로컬 검사와 CI 성공을 운영 적용 성공으로 처리하지 않음.

## 상세 내용

| 경계 | 수행 내용 | 보존 대상·비고 |
|---|---|---|
| Caddy | 소유 표시가 있는 외부 bridge를 만들고 고정 주소와 우선 gateway를 설정함 | 기존 공유 bridge 및 다른 컨테이너 보존 |
| Portal 경로 | Caddy의 `PORTAL_UPSTREAM`만 기존 Portal ClusterIP/port로 변경함 | Portal 앱·Service·NodePort 변경 없음 |
| 운영 설정 | 기존 무시된 bridge override와 환경 파일에 필요한 설정만 추가함 | 자격 증명 원문 복사·증거 원장 저장 금지 |
| 이미지 | 실제 실행 중인 Caddy 이미지와 같은 로컬 이미지로 재생성함 | 이미지 빌드·교체·pull 없음 |
| 정책 | Book → YouTube → Crawler → Portal 순서로 create-only 적용함 | 기존 리소스 덮어쓰기 금지 |
| 허용 통신 | Caddy, Portal의 직접 fanout, 현재 Prometheus scrape를 실제 관측함 | 각 정책 전후 검사 |
| 차단 통신 | 같은 소유 검사 Pod에서 앱 PodIP 및 Service 경로를 검사함 | 정상 baseline과 차단 후 결과의 UID·spec 결합 |
| 원복 | 소유 정책만 UID/spec/RV 조건으로 삭제하고 연결 복구를 검사함 | Caddy 설정과 같은 이미지로 원복, 소유 빈 새 네트워크만 제거 |
| 중단 복구 | 변경 의도와 실제 UID/spec을 비밀정보 없는 원장에 기록함 | 불명확한 변경 응답은 읽기 확인 후 판단하며 즉시 재실행하지 않음 |

주소는 의도한 운영 환경 설정과 Docker IPAM에 지속됨. 진단 결과의 `raw_address_persisted=false`는 증거·로그에 원문 주소를 기록하지 않는다는 뜻임. 필요한 비자격 증명 원복 설정은 제한된 권한의 운영 계획에만 보관함.

Portal은 접속 로그를 비활성화한 상태이므로 로그 활성화로 우회하지 않음. 실제 NC 프로세스의 시작 시점·socket inode·Service 연결·HTTP 응답과 단일 대상 Pod의 동시 TCP 관측 및 Endpoint 불변을 검증하는 별도 `endpoint_socket_http` 방식으로 구분함. 접속 로그 방식의 `http_marker_bound`를 이 방식에서 성공으로 표시하지 않음.

추가 회귀에서는 immutable Caddy 이미지 ID를 forward·rollback 양쪽의 마지막 입력에 고정함. 외부 Git 설정·속성·필터의 실행을 차단하고, 생성 응답이 불명확한 임시 검사 자원은 현재 조회에서 없더라도 미완료로 유지함. 뒤늦은 API 적용 가능성을 단순 부재 조회로 취소 처리하지 않음.

로컬 전체 검사 결과: Portal 223개, system 14개, Crawler 125개, homeops 36개, YouTube 62개, Book 78개, car 78개, K8s 1,135개, maintenance 605개 성공함. 이후 보완 영향은 관련 검사를 다시 실행하고 PR·main 필수 CI로 확인함. socket을 사용하는 검사는 로컬 sandbox 제한 밖에서 실행함. maintenance 최초 실패는 매트릭스 등록 도중 파일 생성·기대값 변경과 검사 실행이 겹친 결과이며, 변경 완료 후 재실행에서 성공함.

## 추가 사전 점검: Windows 접근 권한

| 항목 | 실측 결과 | 비고 |
|---|---|---|
| Linux 표시 권한 | 운영 환경 파일과 bridge override 모두 0777로 표시됨 | Drvfs의 표시만으로 실제 보호 여부를 확정하지 않음 |
| 실제 Windows ACL | 환경 파일과 Compose 입력 3개에 일반 사용자 그룹의 쓰기 허용이 확인됨 | 자격 증명 원문 출력 없이 ACL 메타데이터만 확인함 |
| 부모·드라이브 경계 | 확인한 비신뢰 주체의 effective DeleteChild 및 권한 변경 허용은 없음 | 프로젝트 폴더에는 일반 사용자 그룹의 쓰기 권한이 존재함 |
| 하위 영향 규모 | 읽기 전용 목록에서 파일 5,813개·디렉터리 855개, reparse 항목 0개를 확인함 | 목록은 권한 보완 또는 전체 원복 성공의 증거가 아님 |
| 하위 권한 분류 | 추적 소스의 명시 쓰기·비신뢰 소유자는 0개, Git 관리 파일의 명시 쓰기는 17개로 확인함 | 무시된 항목 등에는 명시 쓰기 316개·별도 소유자 69개가 있으며 내용은 열람하지 않음 |
| Git 명시 권한 보완 | Git 관리 파일 17개는 상위 폴더 상속 교정만으로 해결되지 않음 | 기존 권한 요청에 없는 명시 교정 범위이므로 운영 차단 유지, 기타 무시된 항목의 명시 ACL·소유자는 자동 교정하지 않음 |
| 추가 승인 범위 | 프로젝트 폴더·상속 하위 파일 및 실행 입력 4개의 접근 권한 제한을 확인 요청함 | 파일 내용·자격 증명 값·기존 소유자 유지, 실제 권한 변경 미수행 |
| 운영 적용 | 안전 파일 접근 검사가 차단됨 | 승인된 Caddy 전환·정책 적용은 아직 수행하지 않음 |

기존 임시 권한 변경안은 중단 후 원복 영속성과 하위 상속 복구를 보장하지 못해 사용하지 않음. 권한 보완은 DACL만 변경하고 원래 소유자·그룹·감사를 유지하며, 첫 변경 전 암호화된 원본 메타데이터와 변경 의도를 영속 저장하고 실제 변경 대상만 식별해 복구할 수 있어야 함.

기본 파일 보호 검사를 완화하지 않음. Drvfs에 한해 현재 Windows ACL과 파일 식별자를 검증하는 신뢰된 callback을 제공해야 하며, 넓은 쓰기 권한을 그대로 신뢰하는 callback은 허용하지 않음. 운영 override는 기존 파일의 inode 및 ACL을 유지하도록 prefix 추가·정확한 suffix 제거 방식으로 처리함.

## 후속 조치

통합 실행기는 `--prepare`로 운영을 읽기 전용 점검하고 제한된 Linux 경로에 준비 계획과 해시를 저장함. `--execute`는 외부 검토한 같은 해시와 정확한 커밋을 요구하며 재측정 값이 다르면 변경 전에 차단함. `--status`는 영속 상태만 확인하고 복구 변경을 수행하지 않음. 불명확한 운영 변경은 `HELD` 상태로 sequence 잠금을 유지하며, 프로세스가 종료되어도 미완료 원장이 새 실행을 차단함.

운영 진입은 외부에서 CI 커밋의 wrapper 원문 해시를 확인하고 같은 바이트를 실행하는 신뢰된 launcher를 사용해야 함. 쓰기 가능한 저장소의 wrapper 파일을 먼저 실행한 뒤 자체 검사하는 방식은 허용하지 않음.

필수 검사·독립 검토·PR 및 main CI를 완료한 정확한 소스를 운영에 동기화한 뒤 승인된 Caddy 전환과 격리 검증을 수행함. 실제 연결·복구·정리가 성공한 경우에만 순차 정책 적용을 진행함. 실패하거나 소유 상태가 불명확하면 추가 정책을 생성하지 않고 소유 변경만 복구하며, 확인되지 않은 상태는 완료로 보고하지 않음.
