## 2. 핵심 요약

Portal 백업이 실행 중 앱 확인 단계에서 서버의 정상 목록 형식을 거부해 실패함. 데이터 읽기·전송 및 writer 중단 전에 차단됐으며, 다른 세 백업은 성공함. 허용 형식을 제한적으로 수정하고 기존 검증·단일 writer 보호를 유지함. 정확한 이미지의 배포와 새 백업·복원은 단계별 실제 성공을 확인한 뒤 기록함.

## 5. 확인 필요 사항

새 이미지 아카이브·manifest digest·Linux AMD64 검증 후 N100 캐시 반입을 완료함. 로컬 전체 9개 묶음 2,120개 PASS이며 필수 PR/main CI·제한 Cron 적용은 진행 중임. 전체 Kubernetes 최초 검사에서 테스트 준비 2건이 실패하여 최소 환경의 명시 경로와 자식 PID 기록 이후 준비 marker 생성 순서를 보완했으며, 이후 전체 Kubernetes 924개 PASS임. PR CI에서는 별도 SRE 설치 테스트가 이미지 입력을 소비하지 않고 종료하는 준비 문제로 import 단계에서 실패함. 독립 검토에서 미소비 pipeline의 SIGPIPE 가능성을 재현하여 성공 import 모형만 입력을 소비하도록 보완함. SRE 관련 37개 재검증 PASS이며 제품 설치 코드와 의도적 실패 조건은 유지함. 필수 PR CI는 새 커밋에서 재실행함. 운영 생산자 소스와 고정 이미지 내용은 이 테스트 보완으로 바뀌지 않음. 새 사용자 동의·refresh 확인·운영 설정 조건부 채택·실제 새 업로드·격리 다운로드/복호화/SQLite 검증·증적 export/소비자 갱신은 미수행임. 이번 원인 확인으로 기존 OAuth의 실제 유효성을 확정하지 않음. 생산 데이터 내용 동일성은 미검증임.

Compose 최초 복합 비교는 false였으나 필드별 확인에서 두 컨테이너 구성 보존·running·healthy를 확인함. 최초 순간 원인은 미확정으로 보존함. 다른 세 백업 성공에 따른 상태 갱신과 구성 변경을 구분하며 RV 전체 동일을 주장하지 않음.

## 6. 후속 조치

필수 검사 통과 후 검토된 정확한 커밋을 N100에 fast-forward하고 승인된 새 이미지로 Portal 백업 Cron 본/초기화 image만 조건부 교체함. Secret·PVC·Portal 앱 이미지·다른 서비스·timer·일정·suspend는 보존함. 충분한 timer 여유 및 Job·잠금·단일 writer를 확인한 뒤 새 인증·새 수동 백업·격리 복원·증적 갱신을 수행함. 성공과 미수행을 분리하여 최종 결과를 갱신함.
