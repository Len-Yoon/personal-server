## 2. 핵심 요약

Portal 백업이 실행 중 앱 확인 단계에서 서버의 정상 목록 형식을 거부해 실패함. 데이터 읽기·전송 및 writer 중단 전에 차단됐으며, 다른 세 백업은 성공함. 허용 형식을 제한적으로 수정하고 기존 검증·단일 writer 보호를 유지함. 정확한 이미지의 배포와 새 백업·복원은 단계별 실제 성공을 확인한 뒤 기록함.

## 5. 확인 필요 사항

새 이미지 아카이브·manifest digest·Linux AMD64 검증 후 N100 캐시 반입을 완료함. 로컬 전체 9개 묶음 2,120개 PASS, PR/main CI·Trivy·Agent Review PASS이며 정확한 병합 커밋의 N100 동기화와 제한 Cron 적용을 완료함. 전체 Kubernetes 최초 검사에서 테스트 준비 2건이 실패하여 최소 환경의 명시 경로와 자식 PID 기록 이후 준비 marker 생성 순서를 보완했으며, 이후 전체 Kubernetes 924개 PASS임. PR CI에서는 별도 SRE 설치 테스트가 이미지 입력을 소비하지 않고 종료하는 준비 문제로 import 단계에서 실패함. 독립 검토에서 미소비 pipeline의 SIGPIPE 가능성을 재현하여 성공 import 모형만 입력을 소비하도록 보완함. SRE 관련 37개 재검증 PASS이며 제품 설치 코드와 의도적 실패 조건은 유지함. 보완된 새 커밋과 병합 커밋의 필수 전체 CI가 모두 통과함. Deploy N100의 blocked_path는 정책상 자동배포 제외이며, 실제 백업 이미지 적용은 승인된 수동 경로에서 완료함. 운영 생산자 소스와 고정 이미지 내용은 이 테스트 보완으로 바뀌지 않음. 실제 새 업로드·생산자 검증과 별도 격리 다운로드/복호화/무결성/SQLite 검증을 완료함. 격리 검사의 보호·자원·정리 18개와 launcher 6개 boolean 모두 true, provider 오류 flag 모두 false임. 공식 atomic export 후 원 CM 보존·소비자 fresh·backup_verified=true를 확인함. Google 보안 경고 직접 확인이 필요한 새 사용자 동의는 완료되지 않았으며 이전 흐름은 만료·취소됨. Production 게시 이후 새 refresh 검증·운영 설정 조건부 채택은 미수행임. 이번 수동 성공을 기존 OAuth의 장기 유효성이나 Production 새 인증 전환 완료로 확대하지 않음. 생산 데이터 내용 동일성은 미검증임.

Compose 최초 복합 비교는 false였으나 필드별 확인에서 두 컨테이너 구성 보존·running·healthy를 확인함. 최초 순간 원인은 미확정으로 보존함. 다른 세 백업 성공에 따른 상태 갱신과 구성 변경을 구분하며 RV 전체 동일을 주장하지 않음.

## 6. 후속 조치

검토된 정확한 커밋을 N100에 fast-forward하고 승인된 새 이미지로 Portal 백업 Cron 본/초기화 image만 조건부 교체 완료함. Secret·PVC·Portal 앱 이미지·다른 서비스·timer·일정·suspend는 보존함. 충분한 timer 여유 및 Job·잠금·단일 writer를 확인한 뒤 새 수동 백업·격리 복원·증적 export 및 소비자 갱신을 완료함. 사용자 직접 보안 경고 확인이 가능한 때 새 인증 흐름을 연결하고 실제 동의·refresh 검증을 마친 뒤 조건부 Secret 채택과 후속 검증을 진행함. 성공과 미수행을 분리하여 최종 결과를 갱신함.

로컬 기본 Python의 CA 부재와 신뢰 CA 지정 후 기본 urllib HTTP 403, 제한 환경 curl DNS 실패는 공개 서비스 장애와 구분함. 네트워크 허용 환경의 표준 system curl로 기본 TLS 검증·기본 User-Agent를 유지한 공개 HTTP 200을 주 담당과 독립 검토자가 각각 3회 확인함. 보안 정책·인증서 검증을 완화하지 않음.
