# Windows 권한 잔여 20개 복구

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-10-12 | Asia/Seoul |
| 기준 | PR #377·#378, 이전 암호화 HELD 기록, 현재 권한 읽기 결과 | 과거 실패를 성공으로 대체하지 않음 |
| 목적 | 전체 운영 데이터 목록과 충돌하는 기존 경로를 분리하고 남은 20개만 보완함 | 권한 적용 완료, 후속 전환 전 수집기 조사 중 |

## 2. 핵심 요약

- 사용자가 새 복구 방식으로 전환하는 제안에 `진행해`로 승인함. 기존 3/3 실패 이력은 보존하며, 새 방식의 구현·검증·정확한 계획 검토 후 단일 운영 실행 범위에 적용함. 새 방식 실패 시 자동 재시도하지 않음.
- 직접 대상은 `docker-compose.n100.yml`, `docker-compose.portal-bridge.yml` 및 기존 승인 목록의 Git 디렉터리 18개임. 전체 23개를 다시 적용하지 않음.
- 프로젝트 루트·`.env`·`docker-compose.yml`의 현재 목표 권한 일치를 별도 읽기 대조로 확인함. 세 대상의 쓰기 핸들·직접 setter·원복을 새 경로에서 차단함.
- PR #379 병합 및 main CI 성공 후, 2026-10-12 10:39 실제 잔여 20개 권한 적용을 완료함. Caddy 전환·통신 차단 정책은 미적용이며, 저장소 CI가 성공하거나 시험이 통과한 사실과 실제 운영 결과를 구분함.

## 6. 후속 조치

1. 완료된 권한 적용은 반복하지 않고 과거 HELD와 새 성공 증거를 함께 보존함.
2. 확인된 보조 속성 부재를 실제 `DirectoryInfo` 타입 판별로 보완하고, 엄격한 객체 종류·권한 거부 기준을 유지하여 검증함.
3. 보완 소스의 CI·독립 검토 및 실제 사전 상태 확인 후, 승인된 N100 동기화·Caddy 전환·차단 정책을 이어감.
4. 실제 운영 변경 전후 외부 health·허용/차단 통신·정책 UID/spec을 확인하고 적용 후 관찰 시작 시각을 별도 기록함.
