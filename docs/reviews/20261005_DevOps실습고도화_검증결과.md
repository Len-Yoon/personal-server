## 핵심 요약

Loki 검증의 기동 직후 대기를 보강하고, 격리된 readiness 실패·정상 HTTP 복구 훈련과 Ansible 응답 drift·원복·멱등성 훈련을 구현함. 기존 SLO 증적을 읽기 전용으로 집계하여 수집 성공과 서비스 정상 상태를 구분함. 실제 운영의 urllib 기본 식별자 HTTP 403을 재현하고 정직한 고정 User-Agent로 새 요청을 보완함. 기존 실패 기록은 변경하지 않음.

### 공개 probe 진단

같은 N100에서 URL·Python urllib·요청 시점을 유지하고 User-Agent만 변경해 기본 식별자 403, `personal-server-slo-monitor/1.0` 200, curl 식별자 200을 확인함. 현재 요청 경로의 식별자 차이는 재현됐지만 모든 과거 실패의 원인이 같다고 확정하지 않음. 403은 성공으로 바꾸지 않고 계속 failed로 처리함. 운영 수집기 이미지 교체 전에는 새 식별자가 정기 Job에 반영되지 않음.

## 검토 결과

- 전문 독립 검토에서 Ansible timeout 뒤 남은 자식의 늦은 쓰기를 실제 프로세스로 재현해 보완함.

## 확인 필요 사항

- N100 새 실패 배포·Ansible drift 훈련 및 새 Loki 검증 도구 실행은 미수행임.
- Grafana 화면 렌더, 실제 CNI 규칙 집행 원인, Loki 실제 rollback·datasource DB 삭제, 24시간 보존 이후 실제 삭제는 미검증임.
- local-path 1Gi는 디스크 강제 상한이 아님. 디스크 경보와 실제 삭제 증거를 별도로 확인해야 함.
- SLO 원시 지표 30일 보존·계획 정지 분류·목표값 확정은 후속 운영 결정 대상임.

## 후속 조치

1. 필수 CI·독립 검토·병합 후 정확한 SHA와 실행 순서를 제시함.
2. 최종 승인 후 전용 실습만 실행하고 정상 상태로 종료함. Loki PVC 삭제는 하지 않음.
3. SLO 운영 이미지 교체는 기존 증적·일정을 보존하는 별도 대상임. 과거 기록을 재작성하지 않음.
