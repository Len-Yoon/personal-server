## 2. 핵심 요약

기존 Portal age 개인키를 N100에서 Mac 로그인 키체인으로 전송·저장함. 원본 개인키에서 유도한 공개 수신자가 기존 설정과 일치했고, Mac 키체인에 저장된 값을 별도 프로세스에서 다시 읽어 원본과 바이트 단위로 일치함을 확인함. Mac에서 실제 백업 암호문을 복호화하는 시험과 키체인의 iCloud 동기화 여부는 미확인임.

N100에 세 서비스 전용 Secret·빈 상태 ConfigMap·전용 RBAC·중지된 CronJob을 생성하고 고정 이미지 digest를 확인함. Book 사전 검사 Job은 통과했으나 첫 수동 백업 Job이 writer 중단 전 `preflight` 단계에서 실패함. 이후 읽기 전용 세부 진단은 3회 모두 통과해 당시 실패의 세부 원인은 확인되지 않음. Book 재실행과 YouTube·Crawler 수동 Job은 보류함. 세 CronJob은 계속 중지 상태이며, 세 writer는 각각 1/1임.

## 4. 운영 상태·검토 결과

| 대상 | 상태 | 비고 |
|---|---|---|
| Book | writer 1/1, 잠금 없음, CronJob 중지 | 백업 상태는 `failed/preflight`, 새 복원 증적 없음 |
| YouTube | writer 1/1, 잠금 없음, CronJob 중지 | Secret·상태·실행 리소스만 준비됨 |
| Crawler | writer 1/1, 잠금 없음, CronJob 중지 | Secret·상태·실행 리소스만 준비됨 |

주 담당은 외부 health·N100 상태·리소스 생성·Job 결과를 확인함. 독립 보안 검토는 Mac 키체인 전송 경로와 비밀값 비출력, 기존 항목 덮어쓰기 금지를 확인함. 독립 운영 검토는 Secret 복제, CronJob 생성 전 중지 상태·이미지·읽기 전용 PVC 검증, Book Job과 실패 후 writer·잠금 경계를 확인함. 같은 파일의 동시 수정은 없음.

## 5. 확인 필요 사항

| 항목 | 상태 | 필요한 판단·후속 조치 |
|---|---|---|
| Book 첫 Job `preflight` 실패 원인 | 확인 필요 | 사후 개별 검사는 모두 통과함. 재현 시 원인 단계를 식별하는 표식을 추가한 실제 백업 재실행이 필요함 |
| Book 진단 재실행 | 보류 | 실제 `--go`를 다시 실행하면 writer 일시 중단·원격 쓰기가 발생함. 자동 승인 검토가 이 동작의 구체적 승인 부족을 이유로 거부함. 우회 실행하지 않음 |
| Mac 복구본의 실제 복호화 | 미검증 | Mac 저장본으로 기존 백업 암호문 복호화 시험 필요 |
| Mac 복구본의 추가 가용성 | 확인 필요 | 로그인 키체인 항목의 iCloud 동기화·별도 기기 복구 가능 여부 미확인. Mac 단독 손실 위험 남음 |
| 서비스별 복원 성공·실패 알림 | 미검증 | Book 원인 해결 후 순차 수동 검증 필요 |
| 공유 자격 증명 영향 | 잔여 위험 | 동일 OAuth·age identity를 세 서비스에 재사용하므로 한 백업 Pod 침해 시 다른 백업에도 영향 가능 |

## 6. 후속 조치

1. Book Job의 구체적 진단 재실행 승인 여부를 확인함. 승인 시 상태·health를 재확인하고 한 번만 실행하며, 실패하면 재실행하지 않고 writer·잠금·원격 상태부터 확인함.
2. Book 성공·복원 증적·외부 health가 확인된 뒤 YouTube, Crawler의 `--check`와 수동 `--go`를 순차 실행함.
3. Mac 복구본으로 실제 암호문 복호화 시험을 수행하고 추가 복구 경로를 확인함.
4. 자동 실행 활성화와 보존 삭제는 별도 운영 판단 대상으로 유지함.
