## 2. 핵심 요약

기존 Portal age 개인키를 N100에서 Mac 로그인 키체인으로 전송·저장함. 원본 개인키에서 유도한 공개 수신자가 기존 설정과 일치했고, Mac 키체인에 저장된 값을 별도 프로세스에서 다시 읽어 원본과 바이트 단위로 일치함을 확인함. Mac에서 실제 백업 암호문을 복호화하는 시험과 키체인의 iCloud 동기화 여부는 미확인임.

N100에 세 서비스 전용 Secret·빈 상태 ConfigMap·전용 RBAC·중지된 CronJob을 생성하고 고정 이미지 digest를 확인함. Book 사전 검사 Job은 통과했으나 첫 수동 백업 Job이 writer 중단 전 `preflight` 단계에서 실패함. 이후 읽기 전용 세부 진단은 3회 모두 통과함. 사용자가 승인한 Book 진단 재실행은 실제 `--go`로 1회 수행했으나 `writer-pause` 단계에서 실패함. Book 잠금은 유지됐고 writer는 1/1로 확인됨. 조건부 `kubectl scale`에 필요한 scale `update` 권한이 세 서비스 Role에 없음을 확인했으나, 실패 명령의 원인 stderr는 미확인임. YouTube·Crawler 수동 Job은 보류했고 세 CronJob은 계속 중지 상태임.

|---|---|---|

| 원본 age 설정 | 통과 | N100 내부에서 개인키의 공개 수신자와 기존 암호화 수신자를 비교함. 값은 출력하지 않음 |
| N100 사전 상태 | 통과 | 저장소 `90151b4`, 세 writer 1/1, PVC Bound, 대상 리소스 부재, 반입 이미지 digest 확인 |
| 전용 Secret | 완료 | 기존 Portal Secret의 필요한 네 값을 메모리 경유로 세 전용 Secret에 복제하고 생성 결과를 재조회해 일치 확인 |
| 상태·실행 리소스 | 완료 | 세 상태 ConfigMap 초기 잠금·증적이 빈 값임을 확인. 전용 RBAC·CronJob 생성 전 server dry-run과 독립 검토 통과. 세 CronJob 모두 `suspend: true` |

| Book 승인된 진단 재실행 | 실패 | 실제 `--go` Job 1회 실행. `writer-pause`에서 외부 명령 실패, 상태 `failed`, 잠금 유지, 복원 증적 없음. writer 1/1 확인. 추가 재실행 없음 |

## 4. 운영 상태·검토 결과

| 대상 | 상태 | 비고 |
|---|---|---|
| Book | writer 1/1, 잠금 유지, CronJob 중지 | 최신 백업 상태는 `failed/writer-pause`, 새 복원 증적 없음. 잠금 해제·재실행 보류 |
| YouTube | writer 1/1, 잠금 없음, CronJob 중지 | Secret·상태·실행 리소스만 준비됨 |
| Crawler | writer 1/1, 잠금 없음, CronJob 중지 | Secret·상태·실행 리소스만 준비됨 |

주 담당은 외부 health·N100 상태·리소스 생성·Job 결과를 확인함. 독립 보안 검토는 Mac 키체인 전송 경로와 비밀값 비출력, 기존 항목 덮어쓰기 금지를 확인함. 독립 운영 검토는 Secret 복제, CronJob 생성 전 중지 상태·이미지·읽기 전용 PVC 검증, Book Job과 실패 후 writer·잠금 경계를 확인함. 같은 파일의 동시 수정은 없음.

## 6. 후속 조치

1. 이름으로 제한된 세 서비스 scale Role의 `update` 권한은 저장소 PR #288에서 수정·검증·병합함. N100 적용은 별도 운영 승인 후 Role만 갱신함.
2. Book 잠금 해제 조건과 실패 명령의 직접 원인을 운영 검토한 뒤, 새 승인을 받아 수동 `--go`를 실행함. Book 성공·복원 증적·외부 health가 확인된 뒤 YouTube, Crawler의 수동 검증을 순차 진행함.
3. Mac 복구본으로 실제 암호문 복호화 시험을 수행하고 추가 복구 경로를 확인함.
4. 자동 실행 활성화와 보존 삭제는 별도 운영 판단 대상으로 유지함.

## 7. 저장소 보완 후 상태

PR [#288](https://github.com/Len-Yoon/personal-server/pull/288)에서 세 서비스의 이름 제한 scale Role에 `update`만 추가하고 계약 테스트를 보완함. 병합 커밋은 `30a9dc0`이며 PR·main CI와 Trivy가 통과함. Deploy N100 workflow의 `deploy` job은 건너뛰어져 운영 Role은 여전히 `get, patch`임. 병합 후 읽기 전용 재확인에서 Book은 `failed/writer-pause`·잠금 유지·writer 1/1, YouTube·Crawler는 잠금 없음·writer 1/1이며, 세 CronJob은 중지 상태임. Portal·News·YouTube·Book 외부 health는 10초 간격 3회 HTTP 200임. 진단 Job의 직접 실패 stderr는 미확인임.

N100 Role 적용·Book 잠금 해제·새 수동 Job은 별도 운영 승인 전까지 미수행함. 자동 CronJob 활성화는 놓친 일정의 즉시 실행 가능성과 서비스별 실패 알림 경로 미검증 때문에 보류함.
