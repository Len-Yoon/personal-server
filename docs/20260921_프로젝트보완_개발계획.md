## 2. 핵심 요약

먼저 사용자 기능 장애와 데이터 손실을 수정하고 검증 체계를 보강함. 이후 운영 자동복구·데이터 처리·문서를 정리하며, 대규모 고도화는 기존 결함 수정 뒤에 설계함. 단계별로 구현, 관련 테스트, 정적 검사, 독립 검토, 하네스 결과를 기록한 뒤 다음 단계로 이동함.

1차는 이미 원인과 수정 경계가 확정된 F01을 실행함. 2차 HomeOps는 F02 단독 활성화 시 F03·F04 위험을 드러낼 수 있으므로 하나의 안전성 묶음으로 취급함. 운영·보안 영향이 있는 2차는 구체 범위를 제시한 뒤 2026-09-21 사용자에게 로컬 코드·테스트 변경 승인을 받았음. 실제 운영 적용은 승인 범위에 포함하지 않음.

## 3. 공통 작업·승인 기준

- 저장소 `AGENTS.md`와 `docs/codex-work-loop.md`를 준수함.
- 실제 운영 데이터·PVC·Secret·Caddy·Tunnel ingress·Compose writer 변경을 포함하지 않음.
- 서버 기동·스케줄러 코드는 기본 변경 금지이며, 일반적인 “차례대로 진행”을 예외 파일의 운영 변경 승인으로 확대하지 않음.
- 회귀 테스트에서 먼저 문제를 확인하고 최소 수정함. 같은 수정의 재검증은 최대 3회로 제한함.
- 변경 전 하네스에서 필수 검사와 다음 조치를 확인하고, 실제 검사 결과를 전달해 다시 판정함.
- 주 에이전트는 계획·경계·통합 검증, Luna는 구현·단위 검증, Terra는 설계·운영·보안·rollback 독립 검토를 맡음. 동일 파일의 동시 수정은 금지함.
- 인원과 역할은 현재 `AGENTS.md` 6절의 위험·의존성·독립 검토 기준을 따름. 아래 단계별 참여 기록은 당시 수행 이력으로 보존함.
- 사용자 화면의 주소·응답 계약을 보존함. 시간 신규 저장은 UTC aware ISO 8601, 표시·날짜 판단은 Asia/Seoul, 표시 형식은 `YYYY-MM-DD HH:MM`을 유지함.
- 테스트 성공, 저장소 반영, N100 적용을 별개 상태로 기록함. 커밋·push·PR·병합·운영 적용을 한 번에 완료로 처리하지 않음.
- 기존 테스트 환경 실패는 원인과 비연관 근거를 기록함. 관련 실패가 남아 있으면 해당 단계는 완료 처리하지 않음.

## 프로젝트 보완 개발 계획의 연속 진행 승인

- 사용자가 2026-09-21 `docs/20260921_프로젝트보완_개발계획.md`의 단계별 진행에 대해 수정 → 관련 테스트·정적 검사 → 독립 검토 → 커밋·push·PR → CI·Agent Review 확인 → 병합 → 다음 단계 진행을 일괄 승인함.
- 해당 계획의 승인된 일반 앱 수정과 문서·테스트 변경은 같은 범위의 승인을 매 단계 다시 요청하지 않음. 1·2차 검증 완료 변경도 이 저장소 반영 승인에 포함함.
- 새 운영 영향, 금지 영역, 승인 범위를 벗어나는 변경은 별도로 확인함. 관련 테스트·CI·검토 실패가 있으면 병합하지 않고 원인 확인·범위 내 보완 후 재검증함.
- N100 운영 배포는 이번 일괄 승인에 포함하지 않음. 병합 전에 기존 자동 배포 분류를 확인하며, 병합이 운영 배포를 자동 유발하는 단계는 PR·검증까지 준비하고 운영 승인 전 병합하지 않음. 승인 회피를 위해 workflow를 끄거나 분류 정책·변경 묶음을 조작하지 않음.
- 검증·저장소 병합·N100 적용을 별도 상태로 기록함. 각 단계의 변경 파일·테스트·검토·PR·병합 커밋·다음 단계를 개발 계획에 갱신함.

HTTP/2 전송 고정 뒤 기존 프로세스 probe가 `tunnel run`의 인접 인수만 허용해 정상 HTTP/2 프로세스를 비정상으로 오인할 수 있음을 독립 운영 검토에서 확인함. `cloudflared tunnel [옵션] run personal-server` 형식만 허용하도록 probe를 보완하고, 장애 Telegram은 기존 자동복구와 같은 2회 연속 실패 기준에서만 전송하도록 변경함. 단발 실패 뒤 정상 전환에서는 장애·복구 메시지를 보내지 않음.

| 구분 | 결과 |
|---|---|
| 저장소 병합 | PR #258 `40e3b6e`로 main 반영함. main CI·Trivy·Deploy N100 workflow 모두 성공함 |
| N100 동기화 | N100 저장소를 `40e3b6e`로 fast-forward하고 Supervisor를 재시작함. 이전 Daemon 자식 프로세스가 남은 것을 확인해 해당 Daemon만 종료하고 현재 Supervisor의 자식으로 다시 시작함 |
| 이미지 반입 | 해당 없음 |
| 수동 운영 검증 | HTTP/2 Tunnel 단일 프로세스, 사용자 서비스 `active/running`, 재시작 횟수 0, 새 Daemon의 parent가 현재 Supervisor인 것을 확인함. 최종 상태 파일의 Tunnel 실패 카운트 0·장애 알림 상태 해제를 확인함 |
| 자동 실행 활성화 | 기존 Supervisor·3분 점검·최대 3회 복구 제한을 유지함. 단발 실패는 Telegram 장애·복구 알림을 보내지 않음 |
| 외부 health | Caddy 경유 NodePort와 Portal 외부 health를 각각 10초 간격 3회 HTTP 200 확인함 |

Windows 복구 회귀 86건, 문서 계약 27건, maintenance 묶음이 통과함. 실제 Tunnel 중지 훈련은 수행하지 않으며, 적용 후 정상 health·단일 프로세스·상태 파일 비밀값 미포함만 확인함. 2026-09-23 사용자 승인으로 Windows를 1회 재부팅하여 BootTrigger 경로를 검증함. 두 예약 작업·WSL 실행, `supervisor_started` 뒤 `post_boot_check=passed`, Supervisor 아래 Daemon 1개, Tunnel 정상, K3s 앱 준비 상태, 외부 Portal health 10초 간격 3회 HTTP 200을 확인함. 재부팅은 추가 실행하지 않았고 PVC·Secret·Caddy·Tunnel ingress·운영 데이터는 변경하지 않음.

## 2026-09-27 A3 통합 검색 병렬 조회

사용자의 “1번 진행해봐” 요청에 따라 통합 검색 병렬 조회·전체 조회 시간 제한을 구현함. 기존 1~11차 승인 이력을 새 원격 반영·운영 승인으로 재사용하지 않음.

- 변경: Portal 검색 서비스·대시보드 route·대시보드 테스트 및 결과 문서. HTTP 클라이언트는 기존 httpx 의존성을 사용함.
- 경계: 조회 fan-out 예산 1.5초, 완료 결과 보존, 미완료 요청 취소·회수, 기존 URL·빈 결과·오류 표시 보존. DNS worker 종료를 기다리지 않도록 서버 event loop에서 직접 await함.
- 검증: 기준 Portal151, 최종 Portal158, maintenance477 통과. 문서 추가 후 문서 계약 검사 별도 수행. 독립 Terra 검토에서 DNS 경계 보완 후 차단 사항 없음.
- 원격 반영 승인: 사용자가 후속 “진행해”로 이 변경의 push·PR·CI 확인·병합을 승인함. 동일 범위 승인 재요청 없이 진행하며 N100 운영 배포는 제외함. 최종 PR·병합 커밋·CI 결과는 연결된 PR 기록과 완료 보고를 기준으로 확인함.
- 상세 수치·명령·미검증 사항은 [통합 검색 병렬화 검증 결과](reviews/20260927_통합검색병렬화_검증결과.md)를 따름.
