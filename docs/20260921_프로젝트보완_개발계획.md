## 뉴스 수집 원시 관측 보존 확장 — 운영 적용 완료

사용자의 중복 제외 후 진행 요청으로 북 메모 채팅의 Helm/Grafana/YES24 완료와 기존 VM 복구를 재실행하지 않고 실제 SLO 누적을 점검함(PR #477). 추가 소스 대조에서 기존 원시 archive가 Portal replica·검색만 보존하여 뉴스 freshness의 시간 기반 30일 평가는 일일 기준 30행만 기다려 해결되지 않는 범위임을 확인함. 기존 archive/health에 뉴스 gauge 3종과 원본 sample timestamp·source coverage 진단을 선택적으로 추가함. [계약·실제 운영 상태](slo-baseline.md#뉴스-원시-보존-확장--운영-적용-완료)를 따름.

기존 capsule SHA/byte·불변성·보존 기간과 일일 1800초/실패3회 기준을 유지함. 실제 서비스 bad 값과 source 미관측을 분리하며, raw coverage를 SLO 통과로 표시하지 않음. 새 수집기·일정·경보·운영 YAML은 추가하지 않음. 기존 일회용 검증 CI의 config digest 동일성 계약에 맞춰 classic image store 사전 조건만 명시하며 source·owner·격리·정리 검사와 필수 검증을 유지함. 맥·V2·N100의 Docker 엔진 설정이나 재시작은 수행하지 않음. 2026-11-03 후속 사용자 승인으로 기록 형식 예외와 관측 도구 한정 배포를 각각 수용해 아래 실제 적용을 완료함.

두 기존 잠금(Windows recovery.lock→WSL 공용 백업 flock)을 순서대로 확보하여 자동복구·백업과 수동 반영의 충돌을 방지함. 최종 검증 후 역순 해제·실제 해제 상태·원래 supervisor와 새 daemon 각 1개를 확인함. 임시 아카이브/메타 파일 10개와 배포 제어 프로세스를 정리하고 비밀 없는 검증 증적은 로컬에 보존함. 운영 override와 복구 이미지 참조는 유지함. 수집기 첫 유휴 판정은 상시 console host를 작업 자식으로 분류해 종료 전에 중단했으며, 정확한 신원·정규 실행 경로의 기존 보조 프로세스 하나만 판정에서 제외하는 보완을 전문 검토한 뒤 한 번 재시도함. Relay 첫 사전 조건은 반입 이미지의 digest 별칭 부재로 패치 전에 중단했고, 검증 digest와 같은 새 참조만 등록한 후 진행함. 응답 불완전이나 검사 실패 뒤에는 실제 상태를 조회했으며 맹목 재실행·강제 rollback을 수행하지 않음.

주 담당은 적용·통합·기록, Sol medium 조사 담당은 원본 시각 전진·운영 후 독립 관측, Sol medium 검토 담당은 Compose 설정·DNS 표현 차이 26항목 대조, `gpt-6.1-sol` high 전문 담당은 잠금·조건부 변경·전송/정리·보호 범위를 독립 검토함. 기존 운영 구조를 조사한 Sol medium 담당을 재사용하고, 잠금·배포·정리의 실패 비용 때문에 독립 전문 검토는 Sol high로 분리함. 같은 파일의 동시 수정은 금지함. C: 이외 볼륨과 WSL root 전체 직접 용량 감시는 이번 범위가 아니며 기존 노드/PVC 신호를 별도로 유지함. 원본 수집만 중단되면 탐지에 최대 약 40분과 평가·전송 지연이 필요함.

운영 기록의 macOS 검증은 문서·관련 계약 297건과 최종 문구의 index/링크 29건, diff 공백 검사, `documentation=success` 변경 하네스를 통과함. 코드/이미지의 기존 필수 CI와 이 문서 기록의 PR/main CI는 별도 증적으로 확인함. 운영 소스는 `8e4b48f`이며 이후 문서 기록의 병합을 서비스 재배포로 표현하지 않음.

## 추가 보안 검증

- 실제 관리자 로그인 응답에서 운영 모드 플래그가 없는 경우 세션 쿠키의 `Secure` 누락을 확인함. 관리자·포트폴리오·파일함의 쿠키 정책을 공통 기준으로 보완하고 사용자 승인 후 Portal만 운영 교체함. 실제 공개 HTTPS의 관리자·파일함 로그인 응답에서 `Secure`·`HttpOnly`·`SameSite=Lax`를 확인함. 당시 포트폴리오 전용 비밀번호는 미설정이었고 동일 이미지의 격리 시험에서 보호 동작을 확인함. 해당 쿠키 보완 때 비밀번호·운영 모드·세션 범위와 기존 데이터는 변경하지 않았으며, 이후 별도 승인된 전용 비밀번호 설정과 실제 편집 검증은 위 후속 절에 기록함.

- 이전 Windows 디스크 검사는 기존 수집기→system-agent의 시각 증가만 확인했고 당시 Prometheus 연결은 미검증이었음. 이후 위 호스트 보완에서 Windows C: 연속 시계열·수집 연결·두 규칙과 합성 발생/종료 전송을 실제 검증함.
- 배포된 이미지의 임시 파일·임시 인증을 사용한 격리 시험에서 로그인·버전·CRLF 정규화·409 충돌·원문/초안 보존·재전송 보호를 확인함. 당시 운영 편집용 비밀번호는 미설정이었으며 격리 시험과 실제 인증 활성화를 구분함. 이후 전용 설정·실제 편집·시험 데이터 정리까지 위 후속 절에서 완료함.

## 후속 조치

### DevOps 로컬 실습

성능·용량 분석 → 장애 진단·복구 → 배포 표준화 순서로 진행함. 클라우드와 새 VM 환경 재구축은 제외함. 1단계는 제품 검색 함수를 로컬 샘플 서버와 연결하는 [통합 검색 성능 실습](search-performance-lab.md)이며 운영 앱·데이터·N100 설정은 변경하지 않음. 로컬 36셀·측정 1,080건의 고정 계약과 정리를 통과했고 전체 9개 검사 묶음은 최종 유효 결과 기준 2,700건 통과·기존 promtool 미설치 1건 건너뜀임. [검증 결과와 원본](reviews/20261017_통합검색성능실습_검증결과.md)에 근거·한계·실패 보완을 기록함. 저장소 PR·CI·병합은 로컬 실습과 별도로 확인함. 2단계 [로컬 장애 진단·복구 실습](incident-recovery-lab.md)은 실제 검색 지연·SQLite BUSY/FULL, 실패 원자성·동일 요청 재전송·소유 자원 정리를 구현함. 검증 및 저장소 반영 상태는 [2단계 검증 기록](reviews/20261017_장애진단복구실습_검증결과.md)과 해당 PR에서 구분함. 3단계 [로컬 배포 표준화 실습](deployment-standard-lab.md)은 Git 고정 릴리스·실제 Book HTTP 재배포·readiness 오류 후 1회 롤백·변조 사전 차단을 구현함. 같은 앱 소스의 프로세스 재배포이며 새 코드 업그레이드·컨테이너·무중단·운영 배포 성공을 뜻하지 않음. 실측·검증·PR 반영은 [3단계 기록](reviews/20261017_배포표준화실습_검증결과.md)과 해당 PR을 기준으로 구분함. 세 단계 모두 운영 배포는 수행하지 않음.

후속 네 항목은 DB 잠금 분석·사례 보고서·포트폴리오/면접 자료·실제 다른 앱 버전의 컨테이너 교체임. [DB 실습지](20261018_DB잠금_실습지.md)와 [면접 답변](20261018_DevOps_면접답변.md)을 준비하고 [컨테이너 실습](container-release-lab.md)에서 실제 두 버전 교체·역방향 읽기/쓰기·readiness 실패 롤백 각3회, 총9회를 통과함. 소유 컨테이너24개·volume9개·이미지2개를 정리했고 DB 잠금1회 추가 시연도 통과함. [검증 원본과 한계](reviews/20261018_컨테이너버전교체_검증결과.md)에 근거를 기록함. 최종 검사·저장소 반영은 해당 PR에서 확인하며, 자동 실행을 사용자의 직접 수행 경험으로 표현하지 않음. N100 운영 변경은 범위 밖임.

## 정기 알림 문구 자동 검증 후속 작업

2026-10-21 PR #433 운영 relay 반영·전후 health·가상 표시 1건의 실제 수신·임시 파일 정리·구현 미참여 운영 검토를 완료함. 상세 결과와 사용된 일회성 승인 완료는 [PR #433 운영 기록](https://github.com/Len-Yoon/personal-server/pull/433#issuecomment-6305764732)에 남김. 다음 자연 실행의 실제 새 문구 수신은 이 가상 시험으로 대체하지 않음.

후속 사용자 요청에 따라 다음 Portal 백업·공식 월간 감사의 실제 전송 문구를 N100에서 자동 확인하는 [일회성 검증](notification-followup.md)을 구현함. 실제 send 성공 뒤 비민감 receipt, 자연 실행의 시간·소유·템플릿 및 기존 원장 대조, 두 절대 검증 창, 결과 전송과 자기 정리를 포함함. 구현·검증·독립 검토·PR·병합은 승인된 개발 범위이며 새 relay 배포·일회성 예약 설치는 적용 직전 별도 승인 대상임. 기존 일정·운영 데이터·권한·Secret·완료된 4df 결과는 보존함. 검사·검토·병합 커밋과 실제 운영 상태는 해당 PR 결과 기록으로 구분함.
